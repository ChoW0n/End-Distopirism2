# 아트 제작 요청 (SPEC-007 §9.3 · §9.6)

생성은 gpt astra 가 맡는다. 이 폴더에는 요청서(YAML)와 검수 기록만 둔다. 이미지는 커밋하지 않는다 (SPEC-002 §9).
한 요청 = 한 자세(한 층) = 파일 1개. 시트로 받지 않는다.

## 이번 묶음 — 1장 첫 전투 (STORY-001 §13 1장, SPEC-007 §12.4)

카일 + 보호 대상(아린·작업자) 대 걸음 잔형 · 문지기 잔형, 제3 수문 점검 통로.

|---|---|---|---|
| `kyle/` | 카일 검 구조도 1 + 전투 자세 8 + 베기 궤적 1 | 10 | A |
| `arin/` | 아린 (보호 대상) 대기·피격·이동 | 3 | 보호 |
| `worker/` | 정비소 작업자 (보호 대상, 두 번째는 색 바꾸기) | 3 | C |

이펙트 공용 키트(명중·물보라·침전 조각·잔상)는 코드로 만든다 (SPEC-006 §4). 요청하지 않는다.

## 보내는 순서

앞 단계 승인본이 뒤 요청의 참조가 된다. **승인 없이 다음으로 넘어가지 않는다.**

1. `kyle/K-00-sword-structure` — 검·검집 구조. 승인
2. `kyle/K-01-idle` — 대표 포즈. 얼굴·등신·검 쥔 모습 승인
3. `kyle/K-06-attack` — 가장 어려운 자세(무기 쥔 손). 구조 검수
4. `kyle/` 나머지 K-02~K-05, K-07, K-08 한 장씩 → `K-T1-slash-trail`
5. `map-gate3/M1-01-far` → 승인 뒤 M1-02~04. 카일과 따로 진행해도 된다
6. `remnant-walker/R1-01-idle` → R1-02·03
7. `remnant-gatekeeper/R2-01-idle` (R1 승인본을 톤 참조로) → R2-02~05
8. `arin/A-01-idle` → A-02·03, `worker/W-01-idle` → W-02·03 (카일 K-01 을 톤 참조로)
9. `ui/` — `ui/README.md` 순서

같은 오류가 두 번 교정 뒤에도 남으면 방법을 바꾼다 (국소 수정·사람 수정, 담당 문서 §11).

## 받은 뒤 이 리포가 하는 일

- 반입 도구: RGBA·배경 알파 0·가짜 테두리 투명 검사, 키 700px 정규화, WebP (SPEC-006 §3.1)
- 접지점·무기 끝은 사람이 확정해 매니페스트에 남긴다
- 밝은·어두운 배경 합성 캡처, 승인 대표 포즈와 나란히 비교, 게임 무대 배치 캡처
- 결과는 각 yaml 의 `delivery`·`verification` 에 적는다. 승인은 `user_approved` 로만 표시한다

## gpt astra 에 붙여 넣는 공통 머리말 (캐릭터·잔형·무대)

```
End-Distopirism 전투 아트 요청이다. 세계관은 STORY-001(닫힌 물길, 도시 세르나). 아래 규칙을 지킨다.
- 한 번에 자세(또는 층) 하나, 파일 하나. 시트로 묶지 않는다.
- 이미지 안에 글자를 넣지 않는다.
- 캐릭터: 검은 외곽선 + 평면 2~3단 셰이딩의 셀화풍. 무채색 바탕 + 인물당 고유색 1개(낮은 채도).
  녹·균열 같은 배경 질감을 몸·옷에 덧씌우지 않는다.
- 잔형: 무채색 본체 + 청회색 젖은 면 + 작은 침전 결정. 얼굴 없음. 유령·영혼처럼 보이지 않는 물질 덩어리.
- 배경: 무채색/브라운, 강한 명암 대비, 거친 마모 질감, 균열·녹·벗겨진 페인트·수위 자국.
- 스프라이트는 투명 배경(RGBA, 배경 알파 0). 바닥 그림자를 그리지 않는다.
- 아군은 화면 오른쪽, 적은 화면 왼쪽을 본다. 좌우 반전으로 만들지 않는다.
- 승인본이 지정돼 있으면 그 얼굴·등신·장비를 바꾸지 않는다. 바뀐 곳이 있으면 납품 때 적는다.
- 납품 때 인수인계 양식(YAML)으로 결과 파일, 실제로 한 것, 남은 문제, 검사 안 한 것을 적는다.
이번 요청: (yaml 의 task·constraints 를 붙인다)
```
