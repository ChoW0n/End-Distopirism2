## 1. 지향점 — 시연 데모

### 1.1 한 문장

**카일 1대1 한 판(제3 수문, 3~5분)에서, 앞을 내다보고 몰아칠지 아낄지 고르는 긴장과, 맞부딪칠 때마다 누가 왜 이겼는지 읽히는 림버스급 2.5D 연출을 끝까지 끊김 없이 보여 준다.**

### 1.2 관객이 겪는 흐름

| 순서 | 화면 | 관객이 느껴야 할 것 |
|---|---|---|
| 1 | 불러오기 → 도움말 한 장 | 30초 안에 규칙이 들어온다: 예약·행동력·합 |
| 2 | 입력: 적의 예약이 이름표 위에 보인다 → 카드를 순서대로 누른다 | "적이 2턴 뒤 짓누르기를 한다 — 그 턴에 맞춰 잔향을 넣자" 같은 계산이 된다 |
| 3 | 교전: 카메라가 파고들고, 카드가 머리 위에서 뒤집히고, 위력이 맞부딪힌다 | 매 합마다 이긴 쪽·이유(앞/뒷면·위력)가 1초 안에 읽힌다 |
| 4 | 무거운 타·마지막 타 | 배경이 눌리고 섬광·큰 숫자·밀려남으로 "맞았다"가 몸으로 온다 |
| 5 | 빚을 진 뒤 | 예약이 끝나고 "행동 없음"으로 맞는 턴이 실제로 온다 — 욕심의 대가 |
| 6 | 결행(미명) | 컷신 → 밤바다 → 여러 번 베기 → 복귀. 데모의 정점 |
| 7 | 승리/패배 배너 → 다시 시작 | 한 판 더 하고 싶다 |

### 1.3 데모 완료 기준 (전부 만족하면 최종)

| # | 기준 | 재는 법 |

## 3. 수치 — 네가 정한다

### 3.1 권한과 절차

- **수치는 아스트라가 측정하며 정한다.** 사용자 승인 없이 바꿔도 된다. 이 문서·스펙의 값은 출발점일 뿐이다
- 수치는 전부 JSON 에 있다. 코드에 박지 않는다 (CLAUDE.md)
- 바꾼 커밋마다 해당 스펙 표의 값을 같이 고치고, 옆에 `[튜닝 날짜 · 근거]` 를 짧게 단다 (예: `[튜닝 10-06 · 200판 평균 6.1턴]`)
- 값을 고정한 테스트가 있으면 스펙 표를 따라 고친다. 테스트를 지우거나 건너뛰지 않는다
- **규칙의 뜻이 바뀌는 변경은 수치가 아니다** (예: 회복 시점, 빚 한도의 존재, 합 조건). 이건 §5.2 처럼 사용자에게 묻는다

## 5. 지켜야 할 선

### 5.1 리포 규칙 (CLAUDE.md 요약)

- 스펙 먼저. 구현이 스펙과 다르면 코드가 틀린 것이다. 스펙을 바꿀 때는 문서 커밋을 먼저
- `src/domain/` 에 DOM·three.js·브라우저 API 금지 (`tests/architecture.test.ts` 가 막는다). 유니티 재전환 조건
- 2.5D 원근 카메라 유지. 직교 2D 로 바꾸지 않는다. 카메라 `transform` 쓰는 곳은 하나
- 주석은 한국어 `//{내용}`. `//서머리:` 식 금지. 클래스·생성자·주요 메서드에 빠짐없이
- 커밋: `[Feat]/[Fix]/[Docs]/[Style]/[Refactor]/[Test]/[Chore]` + 한국어. PNG·소리는 커밋하지 않는다(`.gitignore`). JSON·도구는 커밋
- 그림 생성: 캐릭터는 검은 외곽선 + 평면 2~3단 셀화, 무채색 바탕에 인물당 고유색 1개(낮은 채도). 배경 마모 질감을 캐릭터에 덧씌우지 않는다 (STORY-001 §18). 카드 스프라이트는 톤 기준점이 아니다

### 5.2 사용자에게 먼저 물을 것 (혼자 정하지 않는다)

| 항목 | 이유 |
|---|---|
| 규칙의 뜻이 바뀌는 변경 (회복 시점·빚 한도의 존재·예약 변경 허용·합 조건 등) | SPEC-001 v4.0 은 사용자 결정 |
| 결행 문턱 3 | 2026-09-30 사용자 확정값 |
| SPEC-007 (전열·후열 개편) B-1~B-5, SPEC-006 아트 디렉션 A-1~A-6 | 결정 대기. 데모 범위 밖으로 둔다 |
| 걸음 잔형 그림 채택 | 생성물은 사용자 승인 후 반입 |
| 공간형 VFX 본편 반입, S1 기본 질감(원본 컬러 vs 질감 띠) | 실험 결과만 있고 결정 없음 |
| 데모에 시작 화면·튜토리얼을 따로 둘지 | 스펙에 없다 |
| 스킬 이름 (물금·이면·잔향·미명) 변경 | 이름 규칙이 사용자 결정 (SPEC-001 D-22) |
