## 1. 지금 상태 (실측)

| 항목 | 조력자 | 소각원 | 비고 |
|---|---|---|---|
| 캐릭터 장 | 13장 · 19MB | 12장 · 22MB | 캔버스 2400~3400 폭, 대부분 투명 |
| 이펙트 | 12종 × 6장 · 15MB | 12종 × 3장 · 3.0MB | 캐릭터마다 전용 팩 |
| 컷신 | 메시 4장 · 8.6MB | 레이어 13장 · 1.6MB | |

- 화면에 실제로 그려지는 캐릭터 키는 **대기 약 250px, 교전 확대 최대 약 450px**(캔버스 1600 기준)이다.
  원본 키 1340px 는 3배 과하다
- 이펙트 108장 중 **캐릭터와 상관없는 것**(명중 섬광·합 불꽃·지면 충격·연기·잔불·달리기 잔상·막기)이 절반이 넘는다.
  캐릭터가 늘 때마다 같은 종류를 또 만들고 있다
- 이 추세면 캐릭터 1명 = 장 12 + 이펙트 12종 + 컷신. 로스터 8명이면 이펙트만 100종 가깝다
- **톤은 레퍼런스에 가깝지만 우리 것이라고 할 표지가 없다.** 화면만 보면 우리 규칙(속성 3종·정신력·교착)이 안 보인다

## 2. 원칙

1. **생성은 캐릭터 몸에만 쓴다.** 이펙트·UI 재질은 공용 한 벌 + 코드로 만든다
2. **색은 규칙에서 나온다.** 흑·백·갈색 바탕에 채도를 허용하는 건 **속성 3색과 피 빨강**뿐이다. 속성은 우리 규칙(SPEC-001 v2.0 §2)이라 이 색을 보면 우리 게임이다
3. **장 수는 역할이 정한다.** 주역·일반 적·잡몹의 장 수를 등급으로 묶는다 (§3)
4. **모자란 장은 몸짓으로 메운다.** 내딛기·반동·넉백·잔상·숨쉬기는 이미 코드에 있다 (SPEC-005 §2.2)
5. **레퍼런스에서 가져오는 건 기법뿐이다** (SPEC-005 §1.2 그대로). 모양·재질은 우리 소재(지하 구역·녹·균열·벗겨진 페인트)로 그린다

## 3. 캐릭터 장 예산 — 등급

| 등급 | 누구 | 장 수 | 구성 |
|---|---|---|---|
| **A 주역** | 플레이어블 | **8장** | 대기 · 이동 · 막기 · 피격 · S1 한 방 · S2 한 방 · S3 준비 · S3 한 방 |
| **B 일반 적** | 이름 있는 적 | **5장** | 대기 · 이동 · 피격 · 공격 준비 · 공격 한 방 (전용기 3종이 같은 한 방을 쓰고 이펙트만 다르다) |
| **C 잡몹** | 무리 적 | **3장** | 대기 · 공격 · 피격. **색 바꾸기로 여러 종**을 만든다 |

- 지금 12장에서 빠지는 것: 후퇴(이동 뒤집기로 대체), S1·S2 준비(막기·대기로 대체), S3 마무리(S3 한 방 + 몸짓)
- 렌더러는 **장이 없으면 대체 장으로 떨어진다.** 대체표를 매니페스트 옆 데이터로 둔다 (`frameFallback`)
- 궁극기 컷신은 A 등급만. **일러스트 1장 + 메시 흔들기**(조력자 방식)로 통일한다. 레이어 13장 방식은 새로 만들지 않는다
- 기존 조력자·소각원은 **지우지 않는다.** 이미 있는 장은 그대로 쓰고, 새 캐릭터부터 등급 예산을 적용한다

### 3.1 해상도

- 정규화 키를 **1340px → 700px** 로 낮춘다 (화면 최대 450px 의 약 1.5배 여유)
- 빈 캔버스를 잘라내고 WebP 로 저장한다. 매니페스트 좌표는 정규화 도구가 같이 옮긴다
- 실측 (2026-09-27, 조력자·소각원 25장): 원본 PNG **41.1MB** → 빈칸만 잘라낸 PNG 32.3MB → 잘라내고 절반 크기 WebP **1.4MB**
- 이펙트 108장: 원본 **18.1MB** → 잘라낸 WebP **2.4MB**
- 절반으로 줄인 키 670px 는 화면 최대 450px 보다 크다. 화질 손실은 화면에서 확인한다 (3단계 검수)

## 4. 이펙트 예산 — 공용 한 벌 + 서명 한 가지

| 층 | 무엇 | 누가 만드나 | 장 수 |
|---|---|---|---|
| **공용 키트** | 명중 · 합 불꽃 · 지면 충격 · 달리기 먼지 · 막기 · 격파 잔해 | **코드(절차 생성)** 또는 회색조 스프라이트 한 벌 | 캐릭터 수와 무관하게 한 벌 |
| **서명** | 무기 궤적 한 가지 (베기·찌르기·총구 섬광 등) | 캐릭터당 1종 생성 | 1종 × 4장 |
| **궁극기** | 컷신 + 공용 키트를 크게 | 추가 없음 | 0 |

- 공용 키트는 **회색조 + 알파**로 만들고 렌더러가 **그 기술의 속성 색으로 물들인다** (§5). 같은 그림이 S1 은 녹빛, S2 는 청록, S3 는 뼈색으로 나간다
- 절차 생성 후보: 합 불꽃(이미 코드), 균열 선, 벗겨지는 페인트 조각, 녹 가루, 잉크 튐. **우리 소재라 레퍼런스와 겹치지 않는다**
- 캐릭터 8명 기준: 지금 방식 이펙트 약 96종 → 새 방식 공용 6 + 서명 8 = **14종**

## 5. 우리 게임의 색 — 규칙을 화면에

| 우리 규칙 | 화면 표지 | 예산 |
|---|---|---|
| **속성 3종 누적 → 궁극기** (v2.0 §2·§3) | 속성 3색. 카드 테두리, 이펙트 물들임, 머리 위 속성 눈금 3칸. 눈금이 차면 균열이 번지며 궁극기 카드가 들어온다 | 코드 |
| **정신력 = 코인 확률** (v1.0 §4.1) | 코인에 성공 확률을 적는다(예: 60%). 정신력이 낮으면 그 캐릭터만 채도가 빠지고 거친 입자가 낀다. 코인이 녹슬어 보인다 | 코드 |
| **교착 3회** (v1.0 §4.5) | 무기가 맞물려 떨리고 둘 사이 바닥 균열이 1/3 → 2/3 → 3/3 로 번진다. 3회째 둘 다 튕겨 난다 | 코드 |
| **일방 공격** (D-7) | 합과 다른 카메라. 맞는 쪽 뒤에서 잡고 "빈틈" 도장이 찍힌다 | 코드 |
| **지하 구역 세계관** | UI 재질을 녹슨 철판·찢긴 테이프·스텐실 글자로. 스킬 이름 띠는 스프레이 스텐실 | 공용 텍스처 3~4장 |

- 채도 규칙: 바탕 흑·백·갈색 / 속성 3색 / 피 빨강 / **인물당 고유색 1개**(낮은 채도). 그 밖의 원색은 쓰지 않는다 (체력바 빨강은 피 빨강으로 친다)
- **[2026-09-27 SPEC-007 B-10]** 캐릭터는 STORY-001 §18 을 따른다: 검은 외곽선 + 평면 2~3단 셰이딩의 셀화풍. 거친 마모 질감은 배경·UI 재질에만 쓴다. 고유색 예: 카일 탁한 남색, 아린 바랜 황토, 오르 바랜 청록, 나미 바랜 주황
- 속성 3색 후보는 결정 A-2

## 6. 생성 흐름 (Higgsfield) — **중단 (2026-09-27)**

> 이미지 생성은 **gpt astra** 가 맡는다 (사용자 결정). 이 리포는 요청서와 반입만 한다 — SPEC-007 §9.3.
> 아래 흐름은 요청서의 자세 목록·톤 검수표로만 참고한다.
> **포즈 시트 방식은 폐기.** 생성 담당이 시트의 칸·피벗·간격을 보장하지 못한다고 밝혔다. 자세 1장씩 받는다 (SPEC-007 §9.3).

```
① 마스터 1장 (대기, 2안)         → 사람이 고른다
② 포즈 시트 1장 (등급 장 수를 한 장에 격자로) → 잘라서 장으로
③ 정규화 (키 700, 잘라내기, WebP) + 날끝 수동 확정
④ 톤 검수표 (아래)                → 통과 못 하면 ②만 다시
⑤ 매니페스트 · 대체표 · 서명 이펙트 1종
```

- 장마다 따로 생성하던 방식(캐릭터당 11번 호출) → **시트 1~2장**. 한 장 안에서 그려서 얼굴·의상이 덜 흔들린다
- 크레딧 추정: 마스터 2 + 시트 2 + 서명 1 ≈ 5장 × 2.75 ≈ **14크레딧/주역** (지금 방식 약 35)
- 톤 검수표 (B-10 반영): 캐릭터 — 검은 외곽선·2~3단 셰이딩인가 / 고유색 1개 말고 원색이 없는가 / 배경 질감이 몸에 덧씌워지지 않았는가 / 같은 인물로 보이는가. 배경·재질 — 무채색·갈색인가 / 명암 대비가 강한가 / 균열·녹·벗겨진 페인트·수위 자국이 있는가
- **막힌 것**: 결과 CDN 이 이 환경에서 막혀 있다 (SPEC-002 §9.6). ②부터는 반입 경로가 열려야 한다
