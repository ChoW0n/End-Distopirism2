# SPEC-005 · 전투 연출 (v1.0)

상태: **확정 v1.5** / 작성 2026-09-24 / v1.1 몸짓 보강 / v1.2 끊김 숨기기·컷신 / v1.3 한 방의 시간표·밀려남 2026-09-24 / v1.4 몸 간격·색 실루엣 잔상 2026-09-25 / v1.5 조사 대조 — 쓰러짐·결과·피해 출처·상태 표시·소리 2026-09-25

> 목표는 **림버스 컴퍼니 수준의 전투 연출** — 합이 한 번 오갈 때마다 누가 이겼는지 읽히고,
> 때리면 맞은 감각이 나는 것. **메커니즘은 가져오지 않는다.**
>
> 전투 규칙은 여전히 `SPEC-001` 하나뿐이다. 이 문서는 그 규칙이 낸 이벤트를
> **어떻게 보여 줄지**만 정한다. 도메인은 한 줄도 안 바뀌고 이벤트도 새로 만들지 않는다.

## 1. 가져오는 것과 안 가져오는 것

### 1.1 가져오는 것 — 연출 기법

아래는 액션·전략 게임에서 두루 쓰는 **보여 주는 기법**이다. 특정 게임의 규칙이 아니다.

| 기법 | 무엇을 전하나 |
|---|---|
| 합 교환 — 매 라운드 두 사람이 맞부딪히고 불꽃이 튄다 | 합이 여러 번 오간다는 것 |
| 머리 위 코인 뒤집기 | 이번 라운드에 몇 개가 성공했는지 |
| 위력 숫자 맞대기 | 왜 이겼는지 |
| 반동 — 진 쪽이 더 크게 밀린다 | 누가 이겼는지 |
| 히트스톱 — 맞는 순간 잠깐 멈춘다 | 타격감 |
| 카메라 펀치·기울기·흔들림 | 충돌의 무게 |
| 피해 숫자 | 얼마나 들어갔는지 |
| 스킬 이름 띠 | 무엇을 썼는지 |
| 대시 잔상 | 속도감 |
| 넉백·화면 번쩍임 | 큰 한 방 |
| 격파 슬로모 | 마무리 |

### 1.2 안 가져오는 것

- **규칙.** 속도 주사위, 공명, 흐트러짐, 죄악 자원, E.G.O 같은 림버스 고유 규칙은 하나도 넣지 않는다.
  코인·합·정신력·교착은 원래 우리 규칙이다 (원작 End-Distopirism, SPEC-001)
- **그림·UI 모양·폰트·아이콘·사운드.** 모양은 우리 톤(흑백/브라운, 거친 선)으로 새로 그린다
- **수치.** 연출 시간·크기는 전부 우리가 정해 `assets/ui/ui-data.json` 에 둔다

## 2. 합 한 번의 타임라인

도메인이 내는 이벤트 순서 그대로다 (실측 2026-09-24).

```
clashStart
  └ 스킬 이름 띠 · 준비 자세 · 앞으로 대시(잔상) · 카메라 붙기 + 기울기
라운드 × n
  coinRolled ×2        → 머리 위 코인이 뒤집힌다            [박자 coinSec]
  damageCalculated ×2  → 위력 숫자가 떠오른다                [박자 powerSec]
  clashRoundWin        → 양쪽 휘두르기 · 접점 불꽃 · 반동
   또는 deadlock          카메라 펀치 · 짧은 히트스톱         [박자 resultSec]
  coinLost             → 진 쪽 코인 하나가 깨진다
damageApplied
  └ 이긴 쪽 전용기 전체 · 무기 궤적 · 히트스톱 · 명중 섬광
    피해 숫자 · 넉백 · (큰 피해면) 화면 번쩍임
defeated → 슬로모
clashEnd → 합 배지 · 제자리로 · 카메라 원경 · 기울기 원위치
```

일방 공격은 라운드가 한 번이고 불꽃·반동이 없다. 공격자만 **맞는 쪽 옆으로** 달려간다 (SPEC-004 §7.7).

### 2.1 프레임 쓰임

소각원 프레임은 **12장뿐**이다. 장 이름 끝으로 찾아 쓴다 (다른 캐릭터도 같은 이름 규칙이면 그대로 된다).

| 순간 | 장 | 비고 |
|---|---|---|
| 대기 | `idle` | 숨쉬기(§2.2)를 얹는다 |
| 달려감 — 보는 쪽으로 | `advance` | 대시·일방 돌진 |
| 달려감 — 등 뒤로 | `retreat` | 제자리 복귀 |
| 합 시작·라운드 사이 | 전용기 첫 장 (준비 자세) | 다음 코인이 굴러갈 때 돌아온다 |
| 라운드 **승** | 전용기 마지막 장 (맞닿는 자세) | |
| 라운드 **패** | `retreat` (없으면 `guard`) | 모두가 매번 휘두르면 누가 밀렸는지 안 보인다 |
| 교착 | 둘 다 전용기 마지막 장 | |
| 피해가 들어가는 한 방 | 전용기 전체 | 무기 궤적은 이 한 방에만 |
| 맞음 | `hit` | 넉백·몸 번쩍임과 같이 |

### 2.2 몸짓 보강

장 수가 적어서 같은 장을 **움직여서** 부족분을 채운다. 새 그림을 만들지 않는다.

| 몸짓 | 방식 |
|---|---|
| 휘두름 박자 | 여러 장짜리 동작은 첫 장(예비 동작)을 길게 `windupMs`, 나머지를 짧게 `snapMs` 로 끊는다. 균등 재생이면 흐느적거린다 |
| 내딛기 | 한 방을 휘두를 때 예비 동작 동안 살짝 뒤로 당겼다가, 휘두르는 순간 `lunge` 만큼 앞으로 나갔다 돌아온다 |
| 몸 번쩍임 | 넉백을 받으면 `hurtSec` 동안 같은 그림을 더하기 합성으로 한 번 더 얹는다 |
| 숨쉬기 | 서 있을 때 발을 축으로 세로 `breathe` 만큼 늘었다 줄었다 한다. 사람마다 박자를 어긋나게 한다 |
| 궤적 추종 | 프레임에 묶인 무기 궤적은 휘두르는 사람을 따라간다. 내딛는 동안 궤적만 제자리에 남으면 칼과 어긋난다. 연기·잔불·섬광은 터진 자리에 남는다 |
| 이펙트 반전 | 왼쪽을 보는 캐릭터의 이펙트는 비트맵·피벗을 같이 뒤집는다 (SPEC-002 §6-5) |

### 2.3 장 사이 끊김 숨기기

장이 바뀌는 순간 실루엣이 통째로 튄다. 중간 장을 그리지 않고 아래로 가린다.
원작 참고작도 장 수는 적고 이 방식으로 가린다.

| 기법 | 방식 |
|---|---|
| 장 겹치기 | 장이 바뀌면 앞 장을 `blendMs` 동안 옅게 남긴다. 두 실루엣이 겹쳐 번진 모양이 움직임 흐림처럼 읽힌다 |
| 자세 튕김 | 휘두르는 한 방의 장이 바뀔 때마다 발을 축으로 `popScale` 만큼 커졌다가 `popMs` 동안 돌아온다 |
| 휘두름 잔상 | 휘두르는 한 방 동안 지난 장을 `strikeGhosts` 장까지 옅게 남긴다 (대시 잔상과 같은 방식) |
| 카메라 차기 | 휘두르는 한 방의 장이 바뀔 때마다 카메라를 `poseKick` 만큼 순간 확대한다. 렌더러 카메라 값에만 더한다 |
| 이펙트 겹치기 | 이펙트 키프레임(3장)도 다음 장과 겹쳐 넘기고, 마지막 장은 `effectFadeMs` 동안 사라진다 (SPEC-002 인수인계 "마지막 구간 불투명도 감소") |

### 2.3.1 v1.3 에서 끈 것

| 기법 | 이유 |
|---|---|
| 자세 튕김 (`popScale` = 0) | 장마다 몸이 커졌다 줄어 "크기가 자꾸 바뀐다"로 읽혔다 |
| 카메라 차기 (`poseKick` = 0) | 같은 이유. 라운드마다 거는 카메라 펀치(§4 `camera.punchZoom`)는 남긴다 |
| 숨쉬기 폭 | 0.012 → 0.006 |

### 2.3.2 한 방의 시간표 **[v1.3]**

v1.2 까지는 예비 동작 한 장만 길고 나머지 장이 70ms 씩 붙어 나갔다. 휘두르는 장이 두 개인 전용기
(소각원 S3 올려베기→내려찍기, 조력자 S1 당김→찌르기)는 두 번 휘두른 게 한 장처럼 겹쳤고,
이펙트가 사라지기 전에 다음 동작이 나갔다.

근거: 원작 참고 이펙트 GIF 실측(범고래·소각원 이펙트 팩 REFERENCE_REVIEW) — 참격 980ms,
관통 2060ms, 폭발 1100ms, 명중 1080ms. **한 번 휘두르는 데 1초 가까이 쓴다.**

```
준비       첫 장. windupMs 동안 버틴다. 살짝 뒤로 당긴다
휘두름     이펙트가 붙은 장. 한 발 따라 들어가고(follow) 이펙트가 터진다
대기       그 장을 swingHoldMs 와 붙은 이펙트 길이 중 긴 만큼 버틴다 — 이펙트가 다 사라진 뒤 다음 장
(다음 휘두름 … 반복)
마지막 휘두름 = 맞닿는 순간. 피해·히트스톱·넉백
대기       afterHitSec 동안 아무것도 안 나간다. 그다음 제자리로
```

- 이펙트가 안 붙은 중간 장(당기는 자세 등)은 `snapMs` 로 짧게 넘긴다
- 마지막이 아닌 휘두름도 **맞는 쪽이 움찔한다** — 몸 번쩍임 + 명중 섬광 + 한 발 밀려남. 피해 숫자는
  마지막 한 방에만 뜬다 (피해 이벤트는 교전당 하나다. 도메인은 그대로다)

### 2.3.3 밀려남과 따라 들어감 **[v1.3]**

v1.2 의 넉백은 튕겼다가 **제자리로 돌아왔다.** 공격자는 휘두를 때마다 내딛으니 결국 얼굴을 맞댔다.

- 맞으면 **밀려난 자리에 머문다.** 교전이 끝나 제자리로 돌아갈 때 같이 돌아간다
- 공격자는 휘두를 때마다 `follow` 만큼 **따라 들어간다.** 맞는 쪽도 같은 만큼 밀리므로 간격이 유지된다
- 일방 공격은 맞는 쪽이 대시하지 않았어도, 끝날 때 밀려난 자리에서 제자리로 돌아간다
- 합 라운드의 반동(§2)은 그대로 튕겼다 돌아온다. 아직 한 방이 들어간 게 아니다

### 2.3.4 몸 간격 **[v1.4]**

v1.3 까지 간격은 **발(접지점)** 으로만 쟀다. 찌르기·쓸기 장은 몸통이 발보다 0.2H 가까이 앞으로 나와서,
발 간격 `pairGap` 을 지켜도 공격자의 손·몸이 맞는 쪽 몸 안으로 들어갔다 (2026-09-25 사용자 지적, 캡처 확인).

- 교전 중인 두 사람의 **몸 중심**(그 장의 `headCenter` x) 간격을 `bodyGap`(H 배수) 이상으로 유지한다
- 모자라면 **맞는 쪽이 밀려난다.** 휘두르는 쪽이 없으면(합 라운드) 반씩 벌어진다. 밀려난 자리에 머문다(§2.3.3)
- 한 번에 튀지 않게 `bodyGapSec` 에 걸쳐 벌린다. 달려가는 중(대시)에는 재지 않는다
- 렌더러 안의 표현 보정이다. 도메인·UI 감독의 자리 배치(`pairGap`)는 그대로 둔다
- 조사 근거: 사용자 조사 문서(`docs/참고/림버스-전투연출-조사.md` §4.2)의 접근 거리·교환 거리·피격 변위 분리

### 2.3.5 잔상은 색 실루엣으로 **[v1.4]**

원색 잔상·장 겹치기·더하기 번쩍임이 **캐릭터가 둘로 보이거나 하얗게 타버린 것**으로 읽혔다 (2026-09-25 사용자 "스프라이트 훼손").
흰 옷(조력자)은 더하기 합성에서 통째로 하얗게 날아갔다.

| 대상 | v1.3 | v1.4 |
|---|---|---|
| 대시 잔상 | 원색 복사 | `ghostColor` 한 색으로 채운 실루엣 |
| 휘두름 잔상 | 원색 복사 | 같은 실루엣 |
| 장 겹치기 | 모든 장 전환 | **전용기 장(휘두름·합 교환의 준비↔맞닿음)과 맞는 순간은 끈다.** 자세가 크게 바뀌어 두 몸으로 보였다. 대기·이동·막기 같은 작은 전환에만 쓴다 |
| 맞은 번쩍임 | 자기 그림을 더하기로 한 번 더 | 그림 모양대로 `hurtColor` 를 `hurtAlpha` 만큼 덮는다. 선은 살아 있다 |

### 2.4 궁극기 컷신

v1.0 은 까만 화면에 레이어를 멈춘 채 한 장 띄웠다. 컷신 레이어 구조(SPEC-002 §7)는
흔들림 한도(`motionDeg`)와 눈·입 교체를 이미 갖고 있으므로 그걸 움직인다. 새 그림은 없다.

```
들어옴 (inSec)   전투 화면이 dim 까지 어두워지고, 기운 띠가 옆에서 밀려 들어온다
                 캐릭터가 띠를 따라 slideFrom 만큼 옆에서 미끄러져 들어온다
유지             천천히 pushZoom 만큼 다가간다. 레이어가 motionDeg 한도 안에서 흔들린다
                 blinkAt 구간에 눈을 감았다 뜨고, mouthAt 구간에 입을 연다
나감 (outSec)    번쩍임과 함께 띠가 반대로 빠진다. 전투로 돌아간다
```

- 길이·구간·세기는 `ui-data.json` 의 `cutscene` 절에 둔다 (SPEC-003 §8 의 "1.6초 고정"을 대체)
- 레이어 자세는 `CutsceneDirector` 가 계산한다. 렌더러는 시간만 넘긴다
- 흔들림은 레이어마다 위상을 어긋나게 해서 한 덩어리로 도는 것처럼 보이지 않게 한다

## 3. 계층

도메인 → 어댑터 → 렌더러 구조는 그대로다 (SPEC-003).

| 층 | 새로 하는 일 |
|---|---|
| `render/presenter.ts` | 합 시작엔 **준비 자세 한 장**만. 라운드마다 이긴 쪽은 맞닿는 자세, 진 쪽은 물러나는 자세 (§2.1). 전용기 전체와 무기 궤적은 **피해가 들어가는 한 방**에 |
| `ui/director.ts` | 코인·위력·합 결과·코인 깨짐·스킬 띠·피해 숫자·히트스톱·넉백·번쩍임 명령, 라운드 박자 |
| `camera/director.ts` | 펀치·기울기·슬로모. 수치는 데이터에서 받는다 |
| `renderer/canvas.ts` | 전부 그린다. 히트스톱·슬로모는 **렌더러의 시계**에만 걸린다 |

### 3.1 명령은 이벤트 순서대로 섞여 흐른다

프리젠터·UI·카메라 명령을 **이벤트 하나마다** 모아 대기열에 넣는다. 어댑터별로 한 턴 분을
통째로 넣으면 프리젠터 명령이 전부 앞에 서고 UI 명령이 전부 뒤에 서서 박자가 안 맞는다.
카메라 명령도 같은 대기열로 흘린다. 바로 적용하면 턴 전체의 마지막 교전으로 카메라가 먼저 튄다.

카메라 감독의 "뒤에 교전이 남았으면 원경을 끼우지 않는다" 규칙은 한 턴 전체를 미리 봐야
한다. 이벤트를 하나씩 줄 때는 **남은 이벤트를 두 번째 인자로 같이 준다.**

### 3.2 프레임에 묶인 이펙트

`frameId` 가 붙은 무기 궤적은 **그 장이 실제로 화면에 떠 있을 때** 터진다. 대기열에서 꺼낸
시각이 아니다. `playFrames` 는 마지막 장이 시작될 때까지(= 접촉 순간)만 뒤를 붙든다.

### 4.1 한 사람 둘레의 자리 배치

맞붙으면 두 사람이 `pairGap`(0.85 H) 만큼 붙는다. 위력 숫자와 스킬 띠를 **상대 쪽**에 두면
두 사람 것이 가운데 접점에서 겹친다(실제로 겹쳤다). 가운데는 불꽃만 남기고 나머지는 등 뒤로 뺀다.

```
        [코인]
        [체력바][정신력바]
 [위력]   몸   ──접점 불꽃──   몸   [위력]
 [띠]
```

### 4.2 싸우는 둘 말고는 숨긴다

카메라가 두 사람에게 붙어 있는 동안, 나머지는 몸·바·코인을 `motion.othersAlpha` 까지 흐린다.
기본값 0 — **숨긴다.** v1.0 은 어둡게만 눌렀는데 뒤에 서 있는 게 거슬렸다.
한 편 4명이 같은 x 에 깊이로만 서 있어서(SPEC-003 §6.5.1.1) 바도 겹쳐 쌓인다.
누가 싸우는지 한눈에 읽히게 하는 연출이지 규칙이 아니다. 카메라가 원경으로 빠지면 다시 보인다.

**[v1.4]** 흐리는 속도는 카메라 줌 진행률이 아니라 `othersFadeSec` 고정 시간이다. 줌에 묶으면 당기는 내내
반투명한 사람이 싸우는 둘과 겹쳐 "캐릭터가 둘로 보인다"로 읽혔다 (2026-09-25 캡처).

## 5. 지켜야 할 것

1. 도메인·이벤트를 바꾸지 않는다
2. 히트스톱·슬로모가 **도메인 결과에 영향을 주지 않는다** — 렌더러 시계에만 걸린다
3. 연출 수치를 코드에 박지 않는다
4. 림버스의 그림·UI·폰트를 옮기지 않는다. 모양은 우리 것으로 그린다
5. 에셋 없는 캐릭터도 코인·숫자·바·배지는 뜬다 — 이건 그림이 아니라 정보다.
   키·머리 높이 같은 **비율만** 에셋 있는 캐릭터에서 빌린다 (`Stage.reference()`).
   그림을 빌리지 않으므로 SPEC-002 §10 과 충돌하지 않는다. SPEC-004 의 "에셋 없으면 UI 도 안 붙인다"는 이걸로 대체된다

### 7.2 쓰러짐

- `defeated` 에서 쓰러진 사람은 **맞는 자세로 굳고** `downSec` 동안 어두워지며 사라진다. 격파 잔류 이펙트(연기·잔불)는 자리에 남는다
- 쓰러진 뒤에는 이동·복귀·숨쉬기·자세 명령을 받지 않고, 바·코인·위력·배지도 그리지 않는다
- 쓰러진 그림(시체 장)은 없다. 새로 그리지 않고 사라지는 것으로 대신한다 (조사 §7.3 "공용화할지 프로젝트 규칙으로 결정")

### 7.3 피해 출처와 상태 표시

같은 `damageApplied` 라도 누가 왜 깎였는지 다르게 보인다. 이벤트는 그대로 두고 어댑터가 순서로 가린다.

| 사건 | 판별 | 표시 |
|---|---|---|
| 명중 | 교전 중, 합을 이긴 쪽이 아닌 사람의 `damageApplied` | 지금처럼 — 휘두름·히트스톱·넉백·피해 숫자 |
| 자기 피해 (체력 대가) | 교전 중, **합을 이긴 쪽**(일방 공격은 공격자)의 `damageApplied`. 우리 규칙에서 이긴 쪽은 상대에게 맞지 않는다 | 휘두름·넉백·히트스톱 없이 `self` 색 작은 숫자 |
| 상태 피해 | `statusTicked` | 공격 모션 없이 `tick` 색 숫자 + 상태 이름 |
| 처형 | `executed` | 체력 바 0, `execute` 색 "처형" 글자, 화면 번쩍임 |
| 무효 | `damageNullified` | 막는 자세 + `nullify` 색 "무효" 글자 |
| 상태 걸림·풀림 | `statusApplied`·`statusExpired` | 이름이 잠깐 뜬다. 걸려 있는 동안 체력 바 아래 작은 이름표 |

### 7.4 전투 결과

- `battleEnd` 는 **대기열 맨 뒤**에서 결과 띠를 띄운다. 마지막 한 방·격파 슬로모·잔류 이펙트가 다 나간 다음이다.
  대기열 순서만으로는 모자랐다 — 쓰러짐(`down.sec`)·슬로모·잔류 이펙트가 끝날 때까지 렌더러가 띠를 미룬다 (2026-09-25 캡처)
- 글자는 아군 기준 "승리 / 패배 / 무승부". 승리 자세·패배 자세는 만들지 않는다 (조사 §8)
- 띠는 컷신 띠와 같은 기울기·톤. 새 판이 시작되면 지운다

### 7.5 소리

그림 에셋처럼 원작 소리를 쓰지 않는다. **웹 오디오로 합성**한 자리표시 소리다. 녹음 소리가 들어오면 같은 이름으로 바꾼다.

| 이름 | 언제 (렌더러가 명령을 실제로 실행하는 순간) |
|---|---|
| `dash` | 달려 나갈 때 |
| `coin` | 코인이 뒤집힐 때 |
| `clash` | 합 맞부딪힘. 교착은 `clashTie` |
| `coinBreak` | 진 쪽 코인이 깨질 때 |
| `swing` | 휘두르는 장의 무기 궤적이 터질 때 |
| `hit` · `hitHeavy` | 피해 숫자가 뜰 때 (큰 한 방은 `hitHeavy`) |
| `guard` | 무효 |
| `down` | 쓰러질 때 |
