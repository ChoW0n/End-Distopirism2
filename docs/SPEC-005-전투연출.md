## 1. 가져오는 것과 안 가져오는 것

### 1.1 가져오는 것 — 연출 기법

아래는 액션·전략 게임에서 두루 쓰는 **보여 주는 기법**이다. 특정 게임의 규칙이 아니다.

| 기법 | 무엇을 전하나 |
|---|---|
| 합 교환 — 매 라운드 두 사람이 맞부딪히고 불꽃이 튄다 | 합이 여러 번 오간다는 것 |
| 머리 위 코인 뒤집기 | 이번 라운드에 몇 개가 성공했는지 |
| 위력 숫자 맞대기 | 왜 이겼는지 |
| 반동 — 진 쪽이 더 크게 밀린다 | 누가 이겼는지 |
| 히트스톱 — 맞는 순간 잠깐 멈춘다 | 타격감 |
| 카메라 펀치·기울기·흔들림 | 충돌의 무게 |
| 피해 숫자 | 얼마나 들어갔는지 |
| 스킬 이름 띠 | 무엇을 썼는지 |
| 대시 잔상 | 속도감 |
| 넉백·화면 번쩍임 | 큰 한 방 |
| 격파 슬로모 | 마무리 |

### 1.2 안 가져오는 것

- **규칙.** 속도 주사위, 공명, 흐트러짐, 죄악 자원, E.G.O 같은 림버스 고유 규칙은 하나도 넣지 않는다.
  코인·합·정신력·교착은 원래 우리 규칙이다 (원작 End-Distopirism, SPEC-001)
- **그림·UI 모양·폰트·아이콘·사운드.** 모양은 우리 톤(흑백/브라운, 거친 선)으로 새로 그린다
- **수치.** 연출 시간·크기는 전부 우리가 정해 `assets/ui/ui-data.json` 에 둔다

## 2. 합 한 번의 타임라인

도메인이 내는 이벤트 순서 그대로다 (실측 2026-09-24).

```
clashStart
  └ 스킬 이름 띠 · 준비 자세 · 앞으로 대시(잔상) · 카메라 붙기 + 기울기
라운드 × n
  coinRolled ×2        → 머리 위 코인이 뒤집힌다            [박자 coinSec]
  damageCalculated ×2  → 위력 숫자가 떠오른다                [박자 powerSec]
  clashRoundWin        → 양쪽 휘두르기 · 접점 불꽃 · 반동
   또는 deadlock          카메라 펀치 · 짧은 히트스톱         [박자 resultSec]
  coinLost             → 진 쪽 코인 하나가 깨진다
damageApplied
  └ 이긴 쪽 전용기 전체 · 무기 궤적 · 히트스톱 · 명중 섬광
    피해 숫자 · 넉백 · (큰 피해면) 화면 번쩍임
defeated → 슬로모
clashEnd → 합 배지 · 제자리로 · 카메라 원경 · 기울기 원위치
```

일방 공격은 라운드가 한 번이고 불꽃·반동이 없다. 공격자만 **맞는 쪽 옆으로** 달려간다 (SPEC-004 §7.7).

### 2.1 프레임 쓰임

소각원 프레임은 **12장뿐**이다. 장 이름 끝으로 찾아 쓴다 (다른 캐릭터도 같은 이름 규칙이면 그대로 된다).

| 순간 | 장 | 비고 |
|---|---|---|
| 대기 | `idle` | 숨쉬기(§2.2)를 얹는다 |
| 달려감 — 보는 쪽으로 | `advance` | 대시·일방 돌진 |
| 달려감 — 등 뒤로 | `retreat` | 제자리 복귀 |
| 합 시작·라운드 사이 | 전용기 첫 장 (준비 자세) | 다음 코인이 굴러갈 때 돌아온다 |
| 라운드 **승** | 전용기 **휘두름 장을 라운드마다 돌려 쓴다** — n 번째 라운드는 (첫 장을 뺀 장들)의 n 번째 | **[v1.6]** 전엔 마지막 장만 반복했다 |
| 라운드 **패** | `guard` (없으면 `retreat`) | **[v1.6]** 막다가 밀린다. `retreat` 는 이동 전용으로 둔다 |
| 교착 | 둘 다 그 라운드의 휘두름 장 | 승과 같은 순번 |
| 피해가 들어가는 한 방 | 전용기 전체 | 무기 궤적은 이 한 방에만 |
| 일방 공격 — 맞는 쪽 | 때리는 쪽이 휘두르기 시작하면 `guard` | **[v1.6]** 제자리에서 몸을 막는다. 맞으면 `hit` |
| 맞음 | `hit` | 넉백·몸 번쩍임과 같이 |

**[v1.6] 장 전부 쓰기 (2026-09-25).** 120초 실측에서 `guard` 는 두 캐릭터 모두 **한 번도** 안 그려졌고
(`retreat` 가 있으면 그걸 먼저 썼다), 소각원 `08-skill2-peak` 는 전체의 0.3% 만 보였다. 라운드마다 같은 한 장만
나와 합이 반복처럼 보였다 (사용자 지적 "모션별·스킬별 스프라이트를 제대로 안 쓴다").
라운드 승 자세를 휘두름 장으로 돌리고, 막는 장면은 전부 `guard` 로 보낸다.

### 2.2 몸짓 보강

장 수가 적어서 같은 장을 **움직여서** 부족분을 채운다. 새 그림을 만들지 않는다.

| 몸짓 | 방식 |
|---|---|
| 휘두름 박자 | 여러 장짜리 동작은 첫 장(예비 동작)을 길게 `windupMs`, 나머지를 짧게 `snapMs` 로 끊는다. 균등 재생이면 흐느적거린다 |
| 내딛기 | 한 방을 휘두를 때 예비 동작 동안 살짝 뒤로 당겼다가, 휘두르는 순간 `lunge` 만큼 앞으로 나갔다 돌아온다 |
| 몸 번쩍임 | 넉백을 받으면 `hurtSec` 동안 같은 그림을 더하기 합성으로 한 번 더 얹는다 |
| 숨쉬기 | 서 있을 때 발을 축으로 세로 `breathe` 만큼 늘었다 줄었다 한다. 사람마다 박자를 어긋나게 한다 |
| 궤적 추종 | 프레임에 묶인 무기 궤적은 휘두르는 사람을 따라간다. 내딛는 동안 궤적만 제자리에 남으면 칼과 어긋난다. 연기·잔불·섬광은 터진 자리에 남는다 |
| 이펙트 반전 | 왼쪽을 보는 캐릭터의 이펙트는 비트맵·피벗을 같이 뒤집는다 (SPEC-002 §6-5) |

### 2.3 장 사이 끊김 숨기기

장이 바뀌는 순간 실루엣이 통째로 튄다. 중간 장을 그리지 않고 아래로 가린다.
원작 참고작도 장 수는 적고 이 방식으로 가린다.

| 기법 | 방식 |
|---|---|
| 장 겹치기 | 장이 바뀌면 앞 장을 `blendMs` 동안 옅게 남긴다. 두 실루엣이 겹쳐 번진 모양이 움직임 흐림처럼 읽힌다 |
| 자세 튕김 | 휘두르는 한 방의 장이 바뀔 때마다 발을 축으로 `popScale` 만큼 커졌다가 `popMs` 동안 돌아온다 |
| 휘두름 잔상 | 휘두르는 한 방 동안 지난 장을 `strikeGhosts` 장까지 옅게 남긴다 (대시 잔상과 같은 방식) |
| 카메라 차기 | 휘두르는 한 방의 장이 바뀔 때마다 카메라를 `poseKick` 만큼 순간 확대한다. 렌더러 카메라 값에만 더한다 |
| 이펙트 겹치기 | 이펙트 키프레임(3장)도 다음 장과 겹쳐 넘기고, 마지막 장은 `effectFadeMs` 동안 사라진다 (SPEC-002 인수인계 "마지막 구간 불투명도 감소") |

### 2.3.1 v1.3 에서 끈 것

| 기법 | 이유 |
|---|---|
| 자세 튕김 (`popScale` = 0) | 장마다 몸이 커졌다 줄어 "크기가 자꾸 바뀐다"로 읽혔다 |
| 카메라 차기 (`poseKick` = 0) | 같은 이유. 라운드마다 거는 카메라 펀치(§4 `camera.punchZoom`)는 남긴다 |
| 숨쉬기 폭 | 0.012 → 0.006 |

### 2.3.2 한 방의 시간표 **[v1.3]**

v1.2 까지는 예비 동작 한 장만 길고 나머지 장이 70ms 씩 붙어 나갔다. 휘두르는 장이 두 개인 전용기
(소각원 S3 올려베기→내려찍기, 조력자 S1 당김→찌르기)는 두 번 휘두른 게 한 장처럼 겹쳤고,
이펙트가 사라지기 전에 다음 동작이 나갔다.

근거: 원작 참고 이펙트 GIF 실측(범고래·소각원 이펙트 팩 REFERENCE_REVIEW) — 참격 980ms,
관통 2060ms, 폭발 1100ms, 명중 1080ms. **한 번 휘두르는 데 1초 가까이 쓴다.**

```
준비       첫 장. windupMs 동안 버틴다. 살짝 뒤로 당긴다
휘두름     이펙트가 붙은 장. 한 발 따라 들어가고(follow) 이펙트가 터진다
대기       그 장을 swingHoldMs 와 붙은 이펙트 길이 중 긴 만큼 버틴다 — 이펙트가 다 사라진 뒤 다음 장
(다음 휘두름 … 반복)
마지막 휘두름 = 맞닿는 순간. 피해·히트스톱·넉백
대기       afterHitSec 동안 아무것도 안 나간다. 그다음 제자리로
```

- 이펙트가 안 붙은 중간 장(당기는 자세 등)은 `snapMs` 로 짧게 넘긴다
- 마지막이 아닌 휘두름도 **맞는 쪽이 움찔한다** — 몸 번쩍임 + 명중 섬광 + 한 발 밀려남. 피해 숫자는
  마지막 한 방에만 뜬다 (피해 이벤트는 교전당 하나다. 도메인은 그대로다)

### 2.3.3 밀려남과 따라 들어감 **[v1.3]**

v1.2 의 넉백은 튕겼다가 **제자리로 돌아왔다.** 공격자는 휘두를 때마다 내딛으니 결국 얼굴을 맞댔다.

- 맞으면 **밀려난 자리에 머문다.** 교전이 끝나 제자리로 돌아갈 때 같이 돌아간다
- 공격자는 휘두를 때마다 `follow` 만큼 **따라 들어간다.** 맞는 쪽도 같은 만큼 밀리므로 간격이 유지된다
- 일방 공격은 맞는 쪽이 대시하지 않았어도, 끝날 때 밀려난 자리에서 제자리로 돌아간다
- 합 라운드의 반동(§2)은 그대로 튕겼다 돌아온다. 아직 한 방이 들어간 게 아니다

### 2.3.4 몸 간격 **[v1.4]**

v1.3 까지 간격은 **발(접지점)** 으로만 쟀다. 찌르기·쓸기 장은 몸통이 발보다 0.2H 가까이 앞으로 나와서,
발 간격 `pairGap` 을 지켜도 공격자의 손·몸이 맞는 쪽 몸 안으로 들어갔다 (2026-09-25 사용자 지적, 캡처 확인).

- 교전 중인 두 사람의 **몸 중심**(그 장의 `headCenter` x) 간격을 `bodyGap`(H 배수) 이상으로 유지한다
- 모자라면 **맞는 쪽이 밀려난다.** 휘두르는 쪽이 없으면(합 라운드) 반씩 벌어진다. 밀려난 자리에 머문다(§2.3.3)
- 한 번에 튀지 않게 `bodyGapSec` 에 걸쳐 벌린다. 달려가는 중(대시)에는 재지 않는다
- 렌더러 안의 표현 보정이다. 도메인·UI 감독의 자리 배치(`pairGap`)는 그대로 둔다
- 조사 근거: 사용자 조사 문서(`docs/참고/림버스-전투연출-조사.md` §4.2)의 접근 거리·교환 거리·피격 변위 분리

### 2.3.5 잔상은 색 실루엣으로 **[v1.4]**

원색 잔상·장 겹치기·더하기 번쩍임이 **캐릭터가 둘로 보이거나 하얗게 타버린 것**으로 읽혔다 (2026-09-25 사용자 "스프라이트 훼손").
흰 옷(조력자)은 더하기 합성에서 통째로 하얗게 날아갔다.

| 대상 | v1.3 | v1.4 |
|---|---|---|
| 대시 잔상 | 원색 복사 | `ghostColor` 한 색으로 채운 실루엣 |
| 휘두름 잔상 | 원색 복사 | 같은 실루엣 |
| 장 겹치기 | 모든 장 전환 | **전용기 장(휘두름·합 교환의 준비↔맞닿음)과 맞는 순간은 끈다.** 자세가 크게 바뀌어 두 몸으로 보였다. 대기·이동·막기 같은 작은 전환에만 쓴다 |
| 맞은 번쩍임 | 자기 그림을 더하기로 한 번 더 | 그림 모양대로 `hurtColor` 를 `hurtAlpha` 만큼 덮는다. 선은 살아 있다 |

### 2.3.6 피격 슬로우 **[v1.7]**

맞는 순간 히트스톱(멈춤)만 있으면 "탁 멈췄다 바로 풀린다"로 끝난다. 사용자 요청으로 멈춤이 풀린 뒤
`hitStop.slowScale` 배속으로 `hitStop.slowSec` 동안 느리게 흐르다 돌아온다. 이펙트가 터지는 장면이 조금 더 보인다.

- 렌더러 시계에만 건다 (§5-2). 슬로우 시간은 멈춤이 끝난 뒤부터 센다
- 자기 대가·상태 피해에는 걸지 않는다. 명중(피해 숫자가 뜨는 경우)에만 건다
- 격파 슬로모(카메라 `slowmo`)가 더 길면 그쪽을 따른다

### 2.3.7 이펙트 화면 크기 고정 **[v1.7]**

사용자 지적: "이펙트 크기가 시시각각 변한다." 실측 결과 같은 이펙트가 **재생 중에** 최대 1.7배 커졌다
(달려 나갈 때의 잔상·연기가 카메라가 당겨지는 동안 재생된다). 휘두를 때의 순간 확대(`punch`)도 불꽃을 4% 씩 부풀렸다.

- 무기를 따라가는 궤적(`bladeTip`)을 **뺀** 이펙트는 태어난 순간의 카메라 배율로 화면 크기를 고정한다
- 자리는 월드를 따라간다. 크기만 고정한다
- 궤적은 무기와 맞아야 해서 고정하지 않는다

### 2.3.8 교환 박자 — 밀려나고 다시 달려든다 **[v1.8]**

사용자 지적 (2026-09-28): "레퍼런스는 휘두름 → 피격 → 적이 밀려남 → 약 1초 동안 베기 흔적이 사라지며 적이 다시 달려옴 → 다시 전투.
이 모든 순간에 카메라 무빙·번쩍임·흔들림·줌 인이 있다. 우리는 피격 → 다시 싸움 반복이라 밋밋하다."

v1.7 까지 합 라운드는 **반동(§2)이 0.22초 만에 제자리로 튕겨 돌아왔다.** 간격이 안 벌어지니 다시 달려들 거리도 없었다.
라운드마다 아래 네 박자를 넣는다. 도메인·이벤트는 그대로다 (`clashRoundWin`·`deadlock` 하나당 한 번).

```
① 맞부딪힘   휘두름 · 접점 불꽃 · 짧은 번쩍임 · 카메라 펀치 · 멈춤          (지금과 같음 + 번쩍임)
② 밀려남     진 쪽이 크게, 이긴 쪽이 조금 뒤로 미끄러진다. 밀린 자리에 머문다
             카메라는 벌어진 둘을 담으려고 살짝 빠진다 · 화면이 짧게 흔들린다
③ 여운       베기·불꽃 이펙트가 사라질 때까지 버틴다 (lingerSec)
④ 다시 달려듦 둘이 밀려난 만큼 잔상을 끌며 다시 붙는다 · 카메라가 다시 당겨진다
→ 다음 라운드 코인
```

- 교착은 둘이 같은 거리만큼 밀려난다
- 마지막 라운드 뒤에도 ④를 한다. 이긴 쪽이 붙은 상태에서 전용기 전체(마지막 한 방)가 나간다
- 반동(`recoil*`)은 끈다. 밀려남이 대신한다
- 마지막 한 방(피해가 들어가는 순간)은 넉백 거리를 늘리고 가벼운 번쩍임을 넣는다 (`knockback.distance`, `exchange.hitFlash*`)
- 카메라 빠짐·다시 당김은 **렌더러 순간 효과**다 (펀치·차기와 같은 층). 카메라 감독의 상태(보는 대상)는 안 바뀐다 (§3)
- 몸 간격(§2.3.4)은 붙은 뒤에만 잰다. 달려드는 동안은 재지 않는다

### 2.4 궁극기 컷신

v1.0 은 까만 화면에 레이어를 멈춘 채 한 장 띄웠다. 컷신 레이어 구조(SPEC-002 §7)는
흔들림 한도(`motionDeg`)와 눈·입 교체를 이미 갖고 있으므로 그걸 움직인다. 새 그림은 없다.

```
들어옴 (inSec)   전투 화면이 dim 까지 어두워지고, 기운 띠가 옆에서 밀려 들어온다
                 캐릭터가 띠를 따라 slideFrom 만큼 옆에서 미끄러져 들어온다
유지             천천히 pushZoom 만큼 다가간다. 레이어가 motionDeg 한도 안에서 흔들린다
                 blinkAt 구간에 눈을 감았다 뜨고, mouthAt 구간에 입을 연다
나감 (outSec)    번쩍임과 함께 띠가 반대로 빠진다. 전투로 돌아간다
```

- 길이·구간·세기는 `ui-data.json` 의 `cutscene` 절에 둔다 (SPEC-003 §8 의 "1.6초 고정"을 대체)
- 레이어 자세는 `CutsceneDirector` 가 계산한다. 렌더러는 시간만 넘긴다
- 흔들림은 레이어마다 위상을 어긋나게 해서 한 덩어리로 도는 것처럼 보이지 않게 한다

## 3. 계층

도메인 → 어댑터 → 렌더러 구조는 그대로다 (SPEC-003).

| 층 | 새로 하는 일 |
|---|---|
| `render/presenter.ts` | 합 시작엔 **준비 자세 한 장**만. 라운드마다 이긴 쪽은 맞닿는 자세, 진 쪽은 물러나는 자세 (§2.1). 전용기 전체와 무기 궤적은 **피해가 들어가는 한 방**에 |
| `ui/director.ts` | 코인·위력·합 결과·코인 깨짐·스킬 띠·피해 숫자·히트스톱·넉백·번쩍임 명령, 라운드 박자 |
| `camera/director.ts` | 펀치·기울기·슬로모. 수치는 데이터에서 받는다 |
| `renderer/canvas.ts` | 전부 그린다. 히트스톱·슬로모는 **렌더러의 시계**에만 걸린다 |

### 3.1 명령은 이벤트 순서대로 섞여 흐른다

프리젠터·UI·카메라 명령을 **이벤트 하나마다** 모아 대기열에 넣는다. 어댑터별로 한 턴 분을
통째로 넣으면 프리젠터 명령이 전부 앞에 서고 UI 명령이 전부 뒤에 서서 박자가 안 맞는다.
카메라 명령도 같은 대기열로 흘린다. 바로 적용하면 턴 전체의 마지막 교전으로 카메라가 먼저 튄다.

카메라 감독의 "뒤에 교전이 남았으면 원경을 끼우지 않는다" 규칙은 한 턴 전체를 미리 봐야
한다. 이벤트를 하나씩 줄 때는 **남은 이벤트를 두 번째 인자로 같이 준다.**

### 3.2 프레임에 묶인 이펙트

`frameId` 가 붙은 무기 궤적은 **그 장이 실제로 화면에 떠 있을 때** 터진다. 대기열에서 꺼낸
시각이 아니다. `playFrames` 는 마지막 장이 시작될 때까지(= 접촉 순간)만 뒤를 붙든다.

**측정 전 시작값이다.** 눈으로 보고 어색하면 이 파일만 고친다.

### 4.1 한 사람 둘레의 자리 배치

맞붙으면 두 사람이 `pairGap`(0.85 H) 만큼 붙는다. 위력 숫자와 스킬 띠를 **상대 쪽**에 두면
두 사람 것이 가운데 접점에서 겹친다(실제로 겹쳤다). 가운데는 불꽃만 남기고 나머지는 등 뒤로 뺀다.

```
        [코인]
        [체력바][정신력바]
 [위력]   몸   ──접점 불꽃──   몸   [위력]
 [띠]
```

### 4.2 싸우는 둘 말고는 숨긴다

카메라가 두 사람에게 붙어 있는 동안, 나머지는 몸·바·코인을 `motion.othersAlpha` 까지 흐린다.
기본값 0 — **숨긴다.** v1.0 은 어둡게만 눌렀는데 뒤에 서 있는 게 거슬렸다.
한 편 4명이 같은 x 에 깊이로만 서 있어서(SPEC-003 §6.5.1.1) 바도 겹쳐 쌓인다.
누가 싸우는지 한눈에 읽히게 하는 연출이지 규칙이 아니다. 카메라가 원경으로 빠지면 다시 보인다.

**[v1.4]** 흐리는 속도는 카메라 줌 진행률이 아니라 `othersFadeSec` 고정 시간이다. 줌에 묶으면 당기는 내내

### 7.2 쓰러짐

- `defeated` 에서 쓰러진 사람은 **맞는 자세로 굳고** `downSec` 동안 어두워지며 사라진다. 격파 잔류 이펙트(연기·잔불)는 자리에 남는다
- 쓰러진 뒤에는 이동·복귀·숨쉬기·자세 명령을 받지 않고, 바·코인·위력·배지도 그리지 않는다
- 쓰러진 그림(시체 장)은 없다. 새로 그리지 않고 사라지는 것으로 대신한다 (조사 §7.3 "공용화할지 프로젝트 규칙으로 결정")

### 7.3 피해 출처와 상태 표시

같은 `damageApplied` 라도 누가 왜 깎였는지 다르게 보인다. 이벤트는 그대로 두고 어댑터가 순서로 가린다.

| 사건 | 판별 | 표시 |
|---|---|---|
| 명중 | 교전 중, 합을 이긴 쪽이 아닌 사람의 `damageApplied` | 지금처럼 — 휘두름·히트스톱·넉백·피해 숫자 |
| 자기 피해 (체력 대가) | 교전 중, **합을 이긴 쪽**(일방 공격은 공격자)의 `damageApplied`. 우리 규칙에서 이긴 쪽은 상대에게 맞지 않는다 | 휘두름·넉백·히트스톱 없이 `self` 색 작은 숫자 |
| 상태 피해 | `statusTicked` | 공격 모션 없이 `tick` 색 숫자 + 상태 이름 |
| 처형 | `executed` | 체력 바 0, `execute` 색 "처형" 글자, 화면 번쩍임 |
| 무효 | `damageNullified` | 막는 자세 + `nullify` 색 "무효" 글자 |
| 상태 걸림·풀림 | `statusApplied`·`statusExpired` | 이름이 잠깐 뜬다. 걸려 있는 동안 체력 바 아래 작은 이름표 |

### 7.4 전투 결과

- `battleEnd` 는 **대기열 맨 뒤**에서 결과 띠를 띄운다. 마지막 한 방·격파 슬로모·잔류 이펙트가 다 나간 다음이다.
  대기열 순서만으로는 모자랐다 — 쓰러짐(`down.sec`)·슬로모·잔류 이펙트가 끝날 때까지 렌더러가 띠를 미룬다 (2026-09-25 캡처)
- 글자는 아군 기준 "승리 / 패배 / 무승부". 승리 자세·패배 자세는 만들지 않는다 (조사 §8)
- 띠는 컷신 띠와 같은 기울기·톤. 새 판이 시작되면 지운다

### 7.5 소리

그림 에셋처럼 원작 소리를 쓰지 않는다. **웹 오디오로 합성**한 자리표시 소리다. 녹음 소리가 들어오면 같은 이름으로 바꾼다.

| 이름 | 언제 (렌더러가 명령을 실제로 실행하는 순간) |
|---|---|
| `dash` | 달려 나갈 때 |
| `coin` | 코인이 뒤집힐 때 |
| `clash` | 합 맞부딪힘. 교착은 `clashTie` |
| `coinBreak` | 진 쪽 코인이 깨질 때 |
| `swing` | 휘두르는 장의 무기 궤적이 터질 때 |
| `hit` · `hitHeavy` | 피해 숫자가 뜰 때 (큰 한 방은 `hitHeavy`) |
| `guard` | 무효 |
| `down` | 쓰러질 때 |
| `ultimate` | 궁극기 컷인 |
| `result` | 결과 띠 |

- 소리는 **렌더러 시계**에서 낸다. 히트스톱·그림과 박자가 맞는다
- 브라우저는 사용자 입력 전에는 소리를 못 낸다. 첫 클릭·키 입력에 켠다. 화면 아래 "소리" 체크로 끈다
- 세기는 `sound` 절에 둔다
- **[v2.15, 2026-09-30] 합성 소리는 카드 앞·뒷면(`flip` 도는 소리 · `reveal` 면 드러남)만 낸다.** 나머지 이름은 세기 0 으로 꺼 둔다
  (사용자 지시 "카드 앞 뒷면 효과음까진 좋은데 나머지 사운드 좀 별로야 그것들 빼"). 이름 자리는 남겨 두어 녹음 소리가 들어오면 그 자리에 붙인다

## 8. 종이 인형 연출 감독 — 유니티 `Limbus25DEffectDirector` **[v1.9, 2026-09-28]**

> 사용자 지시 (2026-09-28): "카일 스프라이트가 완성됐으니 카일로 1대1 전투 먼저. 리소스 효율을 위해 이미지(오브젝트) 자체를
> 3D 공간에서 튕기고·꺾고·회전시키는 종이 인형식 물리 연출과 3D 카메라만으로 타격감을 낸다. 전투 계산과 분리된, 연출만 하는 컴포넌트."
>
> 레퍼런스의 코드·에셋은 쓰지 않는다 (§1.2). 관찰되는 기법만 새로 짠다.

### 8.1 자리와 경계

- 코드: `unity/Assets/Scripts/Presentation/` — `Limbus25DEffectDirector.cs` · `Limbus25DActor.cs` · `Limbus25DDuelDemo.cs`
- **연출만 한다.** 전투 계산(피해·승패·흐트러짐 여부)은 도메인이 끝낸 값을 `PresentationCue` 로 받는다. 연출은 규칙을 모른다
- 필요한 것: Unity 2022.3 · DOTween (무료판, Demigiant). 카메라는 원근(Perspective)
- 웹 렌더러와 같은 규칙: **카메라·시간 배율을 쓰는 곳은 각각 한 곳**이다 (CLAUDE.md 카메라 함정)

### 8.2 한 교전의 타임라인 (async/await)

```
① 초점     카메라가 두 사람 가운데로 다가가며(Z) 공격자 쪽 측면으로 돌고(24°) 기운다
② 선딜레이  공격자가 뒤로 물러난다 (뒤로 당김만. 눌림·젖힘 없음 [v1.9.8])
③ 돌진     상대 앞까지 가속해 들어간다 (늘림 없음 [v1.9.8]). 달려가는 쪽이 아군이면 머리 위에 결과 알림 (§8.10)
④ 충돌     앞으로 내딛는다 (OutBack. 늘림·숙임 없음 [v1.9.8]). 이 프레임에 금속 스파크 → 역경직 → 카메라 흔들림·차기·화각 펀치
⑤ 넉백     맞은 쪽이 공격 반대로 밀려난다. **기울지 않는다** [v1.9.5]. 흐트러짐이면 순간 내려앉았다 잠깐 멈춘다
⑥ 복귀     맞은 쪽은 스프링처럼 튕기며(OutElastic) 제자리, 공격자는 원위치로 돌아가고 카메라가 원경으로 돌아간다
```

- 맞부딪힘(합)은 ③에서 **둘 다** 가운데로 달려가 부딪히고, 진 쪽이 ⑤를 받는다
- 타격 장 뒤로 **궤적이 사라지는 장**(카일 slash 01~07)을 **0.1초** 동안 넘긴다 [v1.9.12, 0.9 → 0.65 → 0.35 → 0.22 → 0.1]. 역경직 동안은 첫 장에 멈춰 있고, 풀리면 첫 장(최대 궤적)을 50%(0.05초) 동안 보여 준 뒤 나머지 장을 빠르게 넘긴다. 고르게 넘기면 스르륵 사라지는 느낌이 난다. 공격자는 궤적이 다 사라질 때까지 그 자리에서 버틴 뒤 복귀한다
- 교전은 **대기열**로 하나씩 돈다. 앞 교전이 끝나야 다음이 시작된다
- 캐릭터 몸짓 트윈은 **게임 시간**(역경직에 같이 멈춘다). 대기열 기다림·카메라는 **실제 시간**(멈추지 않는다)

### 8.3 몸짓 — 대기 그림 하나로도 된다

- 몸짓은 **자식 `Visual`** 에만 건다. 루트는 자리·바라보는 쪽만 가진다
- 장이 있으면 바꿔 끼운다 (준비·돌진·타격·회복·피격). 없으면 대기 장 그대로 몸짓만 한다
- **좌우 반전 방어**: 바라보는 쪽은 루트 `localScale.x` 부호 하나로만 정한다. 몸짓의 이동·회전은 월드 방향으로 계산해 로컬로 바꿔 넣고,
  `Visual` 의 배율은 늘 양수로 쓴다. 매 프레임 끝에 부호가 바뀌어 있으면 되돌린다
- **장마다 원화 방향이 다를 수 있다** [v1.9.1]. 원화 방향은 장마다 따로 적고, 그림 판(`SpriteRenderer.flipX`)만 뒤집어
  **모든 장이 오른쪽을 보게** 맞춘다. 그러면 루트 부호 = 바라보는 쪽이 되고, 캐릭터는 서 있는 진영에 따라 늘 상대를 본다
  (아군 → 오른쪽, 적 → 왼쪽). 타격 뒤 궤적 장도 같은 규칙을 따른다
- 카일 원화: 대기·준비·돌진·베기(slash 01~07)·회복 **모든 장이 오른쪽**을 본다
- 소각원(자리 표시) 원화도 **모든 장이 오른쪽**을 본다. 적 자리에 서면 루트가 뒤집혀 전부 왼쪽(카일 쪽)을 본다
- 판독 기준은 얼굴·몸통이 향한 쪽이다. 칼끝·베기 궤적은 휘두른 뒤 몸 뒤로 넘어가 있을 수 있어 기준으로 쓰지 않는다

### 8.4 카메라

- **측면 회전** [v1.9.6]: 초점 때 카메라가 두 사람 가운데를 축으로 공격자 쪽 측면으로 **24°** 돈다 (v1.9 6°). 정면만 비추지 않고 좌우 측면에서도 보인다. 캐릭터 판은 §8.9 로 늘 카메라를 본다
- 대기 자세(홈)를 시작할 때 기억한다. 초점 상태는 목표 위치·회전·화각만 바꾸고, 실제 값은 실제 시간으로 부드럽게 따라간다
- 초점 거리는 **캐릭터 화면 크기 상한**에서 정한다 [v1.9.4]: 초점 중 캐릭터 화면 크기는 대기 때의 `focusSizeGain`(1.08) 배를 넘지 않는다.
  거리 = (대기 카메라 ~ 두 사람 가운데 거리) × tan(대기 화각/2) ÷ tan(초점 화각/2) ÷ focusSizeGain.
  간격에 비례해 당기던 v1.9 방식은 교전마다 캐릭터가 1.6배까지 커졌다 줄어 크기가 들쭉날쭉했다. 타격 순간의 화각 펀치·차기는 순간값이라 그대로 둔다
- **흔들림은 트라우마 방식**: 맞을 때마다 트라우마(0~1)를 더하고 초당 줄인다. 흔들림 세기 = 곡선(트라우마). 위치 X·Y·Z 와 회전 X·Y·Z 를
  서로 다른 펄린 잡음으로 흔든다. 연타는 트라우마가 쌓일 뿐 잡음이 끊기지 않아 자연스럽게 겹친다
- 타격 방향 **차기**: 맞은 방향으로 카메라가 밀렸다가 감쇠 스프링으로 돌아온다. 화각도 순간 좁아졌다 돌아온다
- 세기는 피해에 비례한다 (`damageForMaxShake` 에서 최대)

### 8.5 역경직

- 충돌 프레임에 `Time.timeScale` 을 `hitStopScale`(0.02) 로 `hitStopSeconds`(0.03~0.09, 피해 비례) 동안 낮춘다
- 겹치면 끝나는 시각만 늦춘다. 시간 배율을 쓰는 곳은 감독의 `Update` 하나다. 꺼질 때·파괴될 때 원래 값으로 돌린다

### 8.6 이펙트 레이어

- 충돌 좌표에 이펙트를 낸다. **앞/뒤**를 고른다: 앞이면 맞는 쪽 정렬 순서 +1 에 카메라 쪽으로 조금, 뒤면 −1 에 안쪽으로 조금
- 파티클은 충돌 프레임에 바로 재생한다. 역경직 동안 같이 멈춘다 (기본). 옵션으로 실제 시간 재생
- **기본 충돌 이펙트 = 금속 스파크** [v1.9.8]. 원형 고리·흰 파편은 쓰지 않는다
  - 짧은 섬광 하나(0.08초) + 노란 불똥 줄기. 불똥은 공격 방향 부채꼴(80°, 맞부딪힘 1.4배)로 튀고 30% 는 되튄다
  - 불똥은 속도 방향으로 늘인 줄기다. 머리는 흰 노랑, 꼬리로 갈수록 주황으로 식으며 중력으로 떨어지고 흐려진다
  - 수 일방 26 · 맞부딪힘 42, 속도 7~17, 중력 16, 감쇠 1.8, 수명 0.3~0.62초, 길이 = 속도 × 0.1, 폭 0.05
  - 유니티는 충돌 이펙트 프리팹이 없으면 코드로 만든 파티클 스파크를 쓴다 (`SparkSettings`)

### 8.8 무대 배경 — 원근 그림을 비춰 입힌다 [v1.9.3]

- 배경 층(`assets/map` 의 far·mid·ground)은 **이미 원근으로 그려진 한 장면**을 층으로 나눈 것이다. 이걸 3D 무대에 올릴 때
  **원근 바닥 그림을 평평한 판에 반복해 깔지 않는다.** 원근이 두 번 들어가 바닥이 줄무늬처럼 겹치고 뒤틀린다
- **기준 카메라 투영**: 원화 합성(`placement.json` 의 화면 자리)과 맞춘 기준 카메라를 하나 두고, 층마다 판의 꼭짓점을
  그 카메라 화면에 찍어 그림 좌표로 쓴다
  - 세운 층(far·mid): 층 깊이의 z 평면에 세운다
  - 바닥(ground): y=0 바닥 판에 비춘다. 캐릭터 발이 그림 속 바닥에 닿는다
  - 기준 카메라에서 보면 원화 합성과 똑같고, 카메라가 초점·흔들림으로 움직이면 층 깊이만큼 시차가 난다
- 기준 카메라는 원화 합성의 **발 높이 0.76 · 캐릭터 키 0.3 · 바닥 뒤 경계 0.445** 를 맞추도록 정한다. 대기 카메라 = 기준 카메라
- 바닥 그림 밖(초점 카메라가 원화 아래보다 가까운 바닥을 볼 때)은 가장자리를 늘리지 않고 **거울로 이어 붙인다**
- 측면 회전(§8.4) 24° 에서 보이는 범위는 기준 화면의 약 ±2배다 (먼 층 2.07, 중간 층 1.99 실측). 세운 층을 **바닥 경계 가운데(0.5, 0.445)를 기준으로
  키워** 원화만으로 덮는다 [v1.9.7]: 먼 층 2.1배, 중간 층 2.0배. 구조물도 같이 커지고 밑동은 바닥 경계에 붙어 있다.
  정면 대기 화면에는 원화 가운데 절반쯤이 보이고, 좌우 끝 구조물은 측면에서 드러난다. 좌우 거울은 회전을 더 키웠을 때를 위한 예비다
- 중간 층은 키운 뒤 화면 높이의 **0.022 만큼 내린다** [v1.9.9]. 구조물 밑동(원화 아래 50% 줄)이 바닥 턱(0.446)보다 0.015 위에 떠 있었다. 밑동은 턱 뒤로 묻힌다
- 수치는 `assets/map/placement.json` 의 `projection`. 유니티는 `Limbus25DStageBackdrop` (카메라가 +Z 를 보므로 배경은 +Z 쪽)

### 8.9 캐릭터 판 — 늘 카메라를 본다 [v1.9.4]

- 캐릭터(종이 인형) 판만 매 프레임 **카메라 회전과 똑같이** 돌린다 [v1.9.8]. 판은 늘 화면과 나란해 정면으로 보이고, 화면에서 기울지 않는다
  (v1.9.4 는 롤을 빼서 화면 기울임 때 판이 비스듬히 보여 구겨져 보였다)
- **판은 기울지도 찌그러지지도 않는다** [v1.9.8]. `Visual` 의 회전·배율은 쓰지 않는다: 선딜레이 눌림·젖힘, 돌진 늘림, 충돌 늘림·숙임,
  넉백 눌림·젖힘을 모두 뺀다. 몸짓은 **위치 이동과 장 바꾸기**로만 한다. 어떤 트윈이 건드려도 매 프레임 끝에 되돌린다 (`keepFlat`)
- 배경 층·바닥은 세우지 않는다 (§8.8 투영이 깨진다). 이펙트는 §8.6 을 따른다
- **발 밑 그림자를 두지 않는다** [v1.9.6]. 종이 인형이 바닥 그림 위에 바로 선다
- 좌우(루트 배율 부호)·몸짓(`Visual`)은 이 회전과 따로 논다. 몸짓의 회전은 판 평면 안에서 돌아 화면에서 보이는 그대로다

### 8.10 결과 알림 — 아군이 달려갈 때만 [v1.9.5]

- ③ 돌진이 시작될 때, 달려가는 캐릭터가 **아군(플레이어 쪽)** 이면 그 머리 위에 결과를 글로 띄운다. **적에게는 띄우지 않는다**
  - 일방 공격: 공격자만 달려가므로 아군이 공격할 때만 뜬다
  - 맞부딪힘: 둘 다 달려가므로 아군 쪽에만 뜬다
- 문구
  - 성공: 큰 줄 `공격 성공`. 맞부딪힘에서 이겼으면 작은 줄에 위력 비교 `위력 19 > 14`
  - 패배: 큰 줄 `패배`, 작은 줄에 **원인 한 줄**
- 원인은 전투 규칙(SPEC-007 §4.2 위력 비교)에서 오고, 어댑터가 문장을 만들어 넘긴다. 연출은 받은 문장을 그대로 쓴다
  - 원인 문장 (제안): 위력이 모자라면 `위력 열세 14 < 19`. 교란·적성 벌칙 같은 깎기가 결과를 뒤집었으면 그 깎기 하나를 쓴다
    (`교란 -4 · 18 → 14`, `적성 벌칙 -3`). 원인이 여럿이면 가장 큰 하나만
- 캐릭터를 따라다니며 1.1초 뒤 사라진다. **실제 시간**이라 역경직에 멈추지 않는다. 판처럼 카메라를 본다
- 색: 성공은 밝은 상아색, 패배는 붉은색. 글자만 쓰고 박스는 어두운 반투명 한 겹

## 9. 웹 3D 무대 — 실제 게임을 종이 인형 연출로 **[v2.0, 2026-09-28]**

§8 의 종이 인형 연출(1대1 미리보기에서 다듬은 것)을 **실제 게임**에 올린다. 2D 캔버스 렌더러(§3)는
`battle2d.html` 로 남겨 비교용으로 두고, 기본 전투 화면(`battle.html`)은 3D 무대로 바꾼다.

### 9.1 계층

```
도메인 Battle ── BattleEvent[] ──▶ render/exchange.ts (순수, 렌더러 모름)
                                        │  StageStep[]  (교전 한 건 = 한 걸음)
                                        ▼
                                 renderer3d/ (three.js)  ── 무대·인형·카메라·스파크·알림
                                        │  ActorSnapshot[]
                                        ▼
                                 DOM 현황판·명령 패널·입력 (그대로 쓴다)
```

- 도메인·이벤트는 바꾸지 않는다 (§5-1)
- `render/exchange.ts` 는 three.js·DOM 을 모른다. 유니티 어댑터가 같은 규칙으로 `PresentationCue` 를 만든다 (§8.1)
- `renderer3d/` 만 three.js 를 안다. 게임 흐름(턴·입력·재시작)은 `renderer3d/app3d.ts` 가 배선만 한다

### 9.2 교환 묶기 — `StageStep`

도메인 이벤트를 **교전 한 건 단위**로 묶는다. 한 걸음이 끝나야 다음 걸음이 돈다.

| 걸음 | 묶는 범위 | 담는 것 |
|---|---|---|
| `oneSided` | `oneSidedStart` ~ `oneSidedEnd` | 공격자·대상·카드, 위력(`damageCalculated`), 넣은 피해(`damageApplied` 합), 쓰러짐 여부 |
| `clash` | `clashStart` ~ `clashEnd` | 양쪽 카드, **라운드 목록**, 마무리 한 방 |
| `state` | 그 밖의 이벤트 한 개 | 턴 시작·출혈·상태·쓰러짐 등. 현황판 값만 바꾼다 |

- `clash` 라운드: `clashRoundWin` → `win`(이긴 쪽·진 쪽·양쪽 위력), `deadlock` → `deadlock`(같은 위력).
  라운드마다 그 라운드에 난 이벤트(코인 잃음·정신력)를 같이 담는다
- 마무리: 마지막 라운드 뒤 `damageApplied`(진 쪽) 가 있으면 이긴 쪽 → 진 쪽 한 방. 교착 한도로 끝나면 마무리가 없다
- 걸음마다 **그 걸음 뒤에 적용할 이벤트**를 들고 있다. 현황판 체력·정신력은 이 이벤트를 맞는 순간에 적용한다

### 9.3 한 걸음의 연출

§8.2 타임라인을 쓴다. 맞부딪힘은 라운드가 여러 번이라 **붙은 채로** 이어 간다.

| 걸음 | 연출 |
|---|---|
| `oneSided` | 초점 → 선딜레이 → 돌진 → 충돌(스파크·역경직·흔들림) → 넉백 → 복귀. 피해 0 이면 넉백 없이 복귀 |
| `clash` 첫 라운드 | 초점 → 둘 다 선딜레이 → 둘 다 가운데로 돌진 → 충돌(스파크) → 진 쪽이 조금 밀림 |
| `clash` 다음 라운드 | 붙은 자리에서 다시 부딪힘 (짧은 재돌진) → 스파크 → 진 쪽 밀림. 교착이면 둘 다 조금 밀림 |
| `clash` 마무리 | 이긴 쪽이 진 쪽을 친다 → 넉백·피해 숫자 → 둘 다 복귀 |
| 쓰러짐 | 피격 장으로 바꾸고 가라앉으며 흐려진다. **기울이지 않는다** (§8.9) |

- **구경꾼 숨기기** [v2.2]: 교전 한 건이 도는 동안 그 교전에 끼지 않은 인형과 이름표를 숨긴다 (`bystanderFade` 0.15초 동안 흐려짐).
  교전이 이어지면 다음 교전의 참가자만 다시 보인다. 대기열이 비면(입력·대기) 모두 다시 보인다. 쓰러진 인형은 쓰러짐 흐림으로 돌아간다.
  SPEC-007 §9.9 의 "구경꾼 흐리게"를 대체한다 (v2.1 까지는 구경꾼이 그대로 보였다)
- **유니티 맞춤** [v2.5]: `PresentationCue.ClashRounds` 가 라운드 목록(`CueRound` 이김·교착)과 마무리하는 쪽을 받는다.
  `Limbus25DEffectDirector` 는 위 표대로 붙은 채 라운드를 잇고(`reengageTime`·`clashPush`·`deadlockPush`·`roundRest`),
  밀린 쪽은 막는 장(`Pose.Guard`)으로 바꾼다. 피해 없는 합 충돌은 역경직 `clashSeconds`, 흔들림 `clashPower`.
  라운드 알림은 큰 줄을 `CueCallout.headline` 으로 넘긴다(합 승리·합 패배·교착). 라운드 목록이 없는 옛 `Clash` 는 한 라운드로 돈다
- **유니티 전부 맞춤** [v2.6]: 웹 3D 무대(`renderer3d/stage.ts`)와 한 줄씩 대조해 빠진 것을 옮긴다. 유니티 연출은 이 표를 벗어나지 않는다
  - 카드 슬롯마다 준비·맞닿음·궤적 장 (`PresentationCue.WithSlots`, 액터 `skill1~3`, 궁극기는 S3 장)
  - 피해 0 이면 넉백 없이 복귀. 한 방으로 쓰러지면(`WithDefeat`) 넉백 대신 피격 장으로 가라앉으며 `downOpacity` 로 흐려진다. 쓰러진 인형은 복귀하지 않는다
  - 피해 숫자와 `흐트러짐` 딱지(피해 `heavyDamage` 25 이상). 흐트러짐 판정도 웹처럼 피해로 한다
  - 결과 알림은 어두운 반투명 상자 + 윗줄(성공 파랑·패배 빨강), 판처럼 카메라 회전을 따라 화면에서 기울지 않는다
  - 돌진·복귀 때 깊이(z)도 상대 줄·대기 자리로 옮긴다 (여러 줄 대형)
  - 카메라 흔들림 잡음은 사인 세 겹, 세기는 트라우마² 의 smoothstep (웹과 같은 식)
  - 소리 자리 6개(돌진·합·교착·타격·큰 타격·쓰러짐). 웹은 합성음, 유니티는 클립
  - 매니페스트 임포터: `sprite-manifest.json` 으로 피벗(발)·크기(대기 장 키 = 월드 2.0)·장 칸을 채운다. 손으로 맞추다 어긋나지 않게

- 결과 알림(§8.10): **아군이 달려갈 때만**. 일방은 `공격 성공` (피해 0 이면 `빗나감` + `코인 앞면 0`),
  합 라운드는 이기면 `합 승리` + `위력 A > B`, 지면 `합 패배` + `위력 열세 A < B`, 교착이면 `교착` + `위력 A = A`
- 흐트러짐 표시는 `ui-data.json` 의 `heavyDamage` 이상 피해에 붙인다

그림은 캐릭터 자기 매니페스트(SPEC-002)에서만 가져온다. 남의 그림을 대신 쓰지 않는다.

| 피격 | `hit` |
| 복귀 | `retreat` → 대기 |

- **장마다 시간** [v2.9]: 매니페스트 장에 `ms` 가 있으면 충돌 장부터 그 시간(게임 시간)만큼 보이고 다음 장으로 넘긴다.

- 프레임 PNG 는 공통 캔버스(예: 3400x1800)라 **bbox 로 잘라** 텍스처로 쓴다. 긴 변 1024px 로 줄인다.

## 10. 궁극기 연출 형식 **[v2.3, 2026-09-28 사용자 결정]**

림버스 컴퍼니의 E.G.O·인격 스킬 연출을 참고한 형식. 그림·메커니즘은 가져오지 않는다 (§1).

```
① 시전 준비 장   무대 위 인형이 궁극기 준비 장으로 바뀐다. 카메라가 시전자에게 다가간다
② 컷신          화면 전체를 덮는 컷신 (레이어 몇 장 + 움직임). 약 1.5초
③ 시전 후 장     컷신이 걷히면 인형이 시전 후 장으로 서 있다
④ 적 피격 이펙트  적 위에 궁극기 전용 피격 이펙트(연속 장)를 낸다. 피해 숫자·넉백·흔들림은 그 이펙트의 때리는 장에 맞춘다
```

- **맵에 묶이지 않는다.** 궁극기는 덱빌딩으로 어느 맵에서든 쓰인다. 컷신·이펙트에 **전투 맵의** 배경·수면·구조물을 쓰지 않는다.
  컷신 배경은 캐릭터 고유색(카일: 탁한 남색, STORY-001 §18) 바탕의 추상 배경이다
- **캐릭터 고유 전장** [v2.9, 2026-09-29 사용자 결정 — "궁극기 사용 시 … 전환될 맵도 준비됐어"]: 궁극기가 자기 전장을 가지고 있으면
  시전 동안 전투 맵을 그 전장으로 **잠시 바꿨다가 되돌린다.** 전장은 캐릭터 에셋이라 어느 맵에서 써도 같다. 컷신 배경도 그 전장으로 바꾼다
- 컷신·피격 이펙트는 캐릭터 에셋에 들어간다 (`assets/<캐릭터>/`). 맵이 바뀌어도 그대로 재생된다
- 타수가 있는 스킬(S2 2타, S3 3타)은 장이 오면 타마다 스파크·역경직·흔들림을 준다. 피해는 규칙대로 마지막 한 번에 들어간다

## 11. 카드 뒤집기 연출 **[v2.8, 2026-09-28 사용자 결정 · SPEC-001 v3.0 D-23]**

> "서로 전투 시작할 때 서로 달려가면서 화면 슬로우 → 카드가 앞장이냐 뒷장이냐를 카드가 캐릭터 머리 위에서 회전하다가 띵! 하고 나타나서
> 서로 앞 뒤를 비교하고 위력이 열세인 쪽이 공격을 맞는 거야. … 일반 공격 스프라이트를 만들 필요 없이 스킬 스프라이트만 만들면 되잖아"

코인 연출(코인 줄·깨짐)을 없애고 카드 한 장으로 바꾼다. **겨루기용 일반 공격 장이 없다.** 합에서 여러 번 부딪히며 밀리던 라운드도 없어진다.

### 11.1 합

```
① 초점 · 선딜레이   둘 다 스킬 준비 장 (지금과 같다)
② 달려감 + 슬로우   서로를 향해 달려가기 시작하면 게임 시간이 느려진다 (cardFlip.slowScale)
                   달리는 거리의 앞부분(approachShare)만 이 동안에 간다
③ 카드 회전        두 사람 머리 위에 카드가 나타나 세로축으로 돈다 (실제 시간, spinTime · spinTurns). 앞·뒤가 번갈아 보인다
④ 띵!             회전이 멈추며 나온 면이 드러난다. 카드가 한 번 튀고(revealPop) '띵' 소리
⑤ 비교            잠깐 멈춰 두 위력을 보인다 (holdTime). 진 쪽 카드는 어두워지며 작아진다. 아군이면 결과 알림이 이때 뜬다
⑥ 복귀 속도        슬로우가 풀리고 남은 거리를 달려 맞닿는다
⑦ 한 방            이긴 쪽이 스킬 맞닿는 장·궤적으로 진 쪽을 친다. 스파크·역경직·피해 숫자·넉백 (지금 마무리 한 방과 같다)
```

- **교착(위력이 같음)**: ⑤에서 둘 다 카드가 흔들리고 불꽃과 함께 둘 다 조금 밀린다(deadlockPush). 그 자리에서 ②~⑤를 다시 한다 (달리지 않고 슬로우만).
  교착 한도로 끝나면 한 방 없이 둘 다 돌아간다
- 결과 알림 문구: `합 승리 · 앞 24 > 뒤 7`, `합 패배 · 뒤 7 < 앞 24`, `교착 · 앞 18 = 앞 18 · 다시 뒤집기`

### 11.2 일방 공격

공격자 혼자 ②~⑥ (공격자 머리 위 카드만) → ⑦ 공격자가 대상을 친다. 드러난 위력 + 레벨차 보너스가 피해다.

### 11.3 카드 (임시 도형)

- 지금은 **임시 도형**이다. 세로 카드 판 한 장: 앞면은 밝은 바탕 + 마름모 문양 + 앞 위력 + 스킬 이름, **뒷면은 같은 모양을 회색으로** (회색 필터 자리)
- 나중에 카드 디자인이 오면 앞면 = 스킬 그림, 뒷면 = 같은 그림에 회색 필터. 앞/뒤에 각 위력을 적는다
- 카드는 캐릭터 머리 위(headLift)에 떠서 인형처럼 카메라 회전을 그대로 따른다 (§8.9). 좌우 반전은 없다
- 아군 카드는 파랑, 적 카드는 빨강 테두리 (진영 색, SPEC-004 §11)

## 12. 타수 — 맞고, 따라가고, 또 친다 **[v2.10, 2026-09-29 사용자 지적]**

> "카일 S3 가 3타 판정이 아님 … S1 에 준비 자세가 달려가기 전에 나오고 … 준비 없이 그냥 검을 바로 휘두름 …
> S2 에 검을 받아내는 자세 후 찌르기인데 검을 받아내지 않고 그냥 찌름 … 여러 개의 타수가 있으면 적이 피격 후 액션 → 따라가서 다음 동작 타격 → 피격 이 루프"

### 12.1 한 방의 흐름

```
달려감(돌진 장) → 도착 → 준비 장 readyHold → 타 1 → 맞은 쪽 피격 장·밀림 ─┐
                                   ┌──────────────────────────────────────┘
                                   └→ 남은 타 장(제자리) → 돌진 장으로 따라감 → (windup 장) → 타 2 → 피격·밀림 → … → 마지막 타 → 복귀
```

- **달리기 전 선딜레이에는 준비 장을 쓰지 않는다.** 돌진 장으로 몸만 뒤로 뺀다. 준비 장은 도착한 뒤 치기 직전에 `readyHold` 동안 보인다 (v2.9 까지는 거꾸로라 준비 없이 바로 휘둘렀다)
- **타 = 매니페스트에서 `impact` 가 켜진 장.** 없으면 카드 장 목록의 둘째 장 하나가 한 타다. 한 타의 장은 그 타 장부터 다음 타 장 앞까지이고 `ms` 대로 넘긴다
- 카일 타수는 SPEC-001 [D-22] 표와 같다: S1 1타(`01`), S2 2타(받아내기 = 준비 장, 찌르기 `01`), S3 3타(칼집 쳐내기 `03` · 올려베기 `08` · 내려베기 `22`)
- **피격 슬로우** [v2.11 → v2.12]: 피해가 있는 타마다 역경직 → **밀림(제 속도로 훅)** → 그 뒤 `hitSlowTime`(실제 초) 동안 게임 시간이 `hitSlowScale` 로 느려진다.
  v2.11 은 슬로우가 밀림과 겹쳐 밀림이 느리게 풀려 보였다 (사용자 지적 "밀리는 거리를 보는 시점에서 딱 보이게 훅! 밀려나게")
- 맞은 쪽: 타마다 피격 장으로 바뀌고 `hitKnock` 만큼 밀린다. 마지막 타는 지금처럼 피해에 비례해 밀린다(`knockBase`·`knockPerDamage`). 쓰러지면 밀리지 않고 가라앉는다
- **크게 날아간다** [v2.13, 사용자 지시 "맞고 뒤로 슝 날라가잖아 … 좀 확 늘려봐"]: 만화 연출처럼 한 타마다 뒤로 슝 날아간다. `hitKnock` 2.4, 마지막 타 `knockBase` 2.6 + 피해 × 0.04 (최대 5.0), `knockTime` 0.26 (`outExpo`, 처음에 확 나가고 끝에 선다)
- 때린 쪽 **[v2.18, 2026-10-01 사용자 지적 "밀려난 적을 따라갈 때 타격 스프라이트가 나오니까 캐릭터가 질질 끌려다니는 것 같고 너무 어색해"]**:
  **앞 타의 남은 장은 그 자리에서 다 넘긴다 → 처음 달려갈 때처럼 돌진 장으로 달려 붙는다 → 도착하면 다음 타.** 셋은 차례로 하고 겹치지 않는다
  - 달리는 시간 = 거리 ÷ `followSpeed`(초당 16), 최소 `followTime`(0.12). 돌진 소리를 낸다
  - **다음 타의 준비 장(`windup`)은 도착한 뒤에 넘긴다.** 매니페스트 장에 `windup` 이 켜져 있으면 앞 타 끝이 아니라 다음 타 장 바로 앞에 붙는다 (카일 S3 `21-downcut-smear`)
  - ~~v2.14 앞 타의 남은 장이 넘어가는 동안 미끄러져 붙는다~~ → 타격 장이 미끄러져 끌려가 보였다. 폐기
  - ~~v2.13 남은 장과 돌진 장을 같이 돌린다~~ → 두 장이 번갈아 바뀌어 "슥" 보였다 다시 나타났다. 폐기. v2.18 은 남은 장이 끝난 뒤에만 돌진 장으로 바꾼다
  - 날아가는 동안 카메라는 둘을 다시 잡는다

### 12.2 피해 나누기

- 규칙의 피해는 **한 번**이다 (SPEC-001 [D-22] "타수는 연출이 몇 번 부딪히는지다"). 도메인은 바꾸지 않는다
- 연출은 그 피해를 타 수로 **똑같이 나누고 나머지는 마지막 타에** 얹는다 (`render/exchange.ts` 의 `splitDamage`). 타마다 피해 숫자를 띄우고 현황판 체력도 타마다 준다

### 12.5 휘두르기 잔흔 지우기 곡선 **[v2.21, 2026-10-01 사용자 지시]**

> "궁극기 말고 휘두를 때 슬래시 이펙트도 처음엔 천천히 사라지다 촤라락 지워져야 이쁠 것 같아"

- 대상: 전용기 장 중 **타 장 다음부터 다음 타 앞까지의 잔흔 장**(카일 S1 `02~14`, S2 `02~14`, S3 `04~07`·`09~20`·`23~37`). 궁극기 베기선(§10.2)은 대상이 아니다

- 잔흔 장 시간의 **합은 납품 그대로** 두고 나누는 방식만 바꾼다. 장 i(0부터, 모두 n 장)는 `T × (i/n)^(1/k)` 에 시작한다 (`motion.decayEase` = k, 2.0).

  - 예: S1 잔흔 13장 × 60ms(780ms) → 첫 장 약 216ms, 마지막 장 약 30ms
- 몸은 잔흔 동안 고정 자세라(최신본 '본체 고정 수정본') 시간만 바꿔도 몸이 흔들리지 않는다

- 띠 경로는 3차 베지어를 **호 길이로 등간격 샘플**(64구간)해 `u = 0`(먼저 지나간 꼬리) → `u = 1`(마지막 진행 끝)을 매긴다. 화면 좌우로 꼬리를 정하지 않는다. 좌우 반전은 공간 좌표에만

- 소멸 중 head 는 1, 메시 크기·경로·최대 폭은 고정(중심으로 줄이지 않는다). 끝 분해는 **고정 공간 노이즈**(위상 고정) + 부드러운 경계 `edgeFeatherU` → 지워진 곳이 다시 켜지지 않는다

- 효과 시각은 **게임 시간**이다. 배속은 dt 에 한 번만 곱한다. 시각은 누적 dt 로만 정해지고 같은 시각이면 프레임율과 무관하게 같은 head/tail

#### 15.3.1 휘두름 궤적 **[v2.29, 2026-10-03 사용자 지적]**

> "카메라를 돌려가면서 보면 알겠지만 이펙트가 수직으로 평면으로 그려지면 공간감이 안생겨 캐릭터가 휘둘렀다고 예상되는 궤적을 공간상에 고려해서 넣어야해"

v2.28 은 원화 판과 같은 방향의 세로 띠에 깊이만 조금(±0.5H) 얹어서, 카메라를 돌리면 평면이 드러났다. 이제 **칼끝이 몸 둘레를 돌며 올려 베는 궤적**을 공간에 세운다.

- **좌표**: 발 기준, 월드 위(y)는 그대로 두고 좌우만 게임 카메라 쪽으로 돌린 틀(z = 카메라 쪽 수평). 띠·물방울·물결이 같은 틀을 쓴다
- **위에서 본 궤적** `depthH(u)`: 위에서 본 각 φ 를 u 에 따라 −40°(오른쪽 **뒤**) → 0°(오른쪽 **옆**, u ≈ 0.19 에서 몸 판을 지남) → 90°(몸 **앞**, z 최대 0.8H) → 178°(왼쪽 옆, 칼끝 머리 z ≈ 0 — 칼을 뻗은 마무리 자세와 같은 판) 고르게 돌리고 z = 0.8H·sin φ 로 뽑아 표로 둔다. x 는 원화 그대로라 위에서 보면 몸을 감는 둥근 아치가 된다(꺾임 없음)
- **높이**: 게임 카메라(내려다보는 각 p — 배경 기준 카메라에서 계산, 제3 수문 약 19°)에서 보면 원화 호와 겹치도록 `y = (원화 y + z·sin p) / cos p`. 그래서 0° 에서는 원화와 같은 자리에 보이고, 실제 궤적은 오른쪽 뒤 무릎 높이에서 앞 허리를 지나 왼쪽 어깨 높이로 올라가는 비스듬한 휘두름이 된다
- **단면**: 궤적 점들의 평면(뉴웰 법선)을 휘두름 면으로 보고, 면 안에서 진행 방향에 직각인 **안쪽(휘두름 중심 쪽)** 이 물결 몸통 쪽이다. 원화처럼 물결이 서 보이게 안쪽 방향을 월드 위로 `liftDeg(u)` 만큼 세운다. 띠는 몸을 감싸는 비스듬한 물 벽이 된다. 안쪽 끝은 띠 면의 위쪽 법선으로 `curlH` 만큼 말린다
- u 는 원화 호 길이 비율 그대로다(3D 길이와 조금 다르다). 소멸·붓결 자리가 원화와 같게 하려는 것
- 몸 판은 게임처럼 카메라를 향해 돈다. 궤도 0° 가 아니면 몸 판과 궤적이 어긋나 보이는 것은 시험 한정이다

- 조작 선택에 **`환경 이펙트 검수`** 를 둔다. 전투 없이 바인딩의 사건을 하나씩(1.3초 간격) 무대 가운데에 내고, 전투 맵(제3 수문·콘크리트)과 고유 전장(밤바다·물)에서 번갈아 돈다. 그 지형에서 안 내는 사건은 이름 옆에 적는다
- 색 [검수 결과]: 제3 수문 바닥은 중간 밝기라 바닥색을 그대로 곱하면 먼지가 바닥과 같은 명도가 되어 안 보였다(납품 README 경고 그대로). 곱할 색을 밝게 잡는다 (`surface.tint`)
- 크기 [검수 결과]: 512 캔버스에서 그림이 차지하는 폭은 35~65% 다. `scale` 은 manifest `visible_bounds` 로 **보이는 폭**이 목표(캐릭터 키 비율)가 되게 정한다. 균열은 바닥 원근에 눕히면 낮은 카메라에서 실선처럼 납작해져 23° 만 세우고 키 1.8 배 폭으로 키웠다
- 발밑 바(SPEC-004 §2.2.1)가 발 바로 아래를 덮는다. 발밑 먼지·균열은 바보다 넓게 퍼져야 보인다

## 17. 박진감 — 카메라 압박·타격 반응·무대 채우기·템포 **[v2.32, 2026-10-04 사용자 지시]**

> 사용자: "스킬 연출 자체는 좋은데 박진감이라 해야 하나 게임이 좀 비어 보인다" → 네 가지 다 (카메라 압박·타격 반응 밀도·무대 채우기·템포)
>
> 진단(2026-10-04 캡처): 교전 중에도 캐릭터가 화면 높이 약 1/4~1/3, 아래 40% 가 빈 바닥 (초점 크기 상한 1.08배). 타격 때 화면 전체가 반응하지 않는다. 무대에 움직이는 것이 둘뿐. 합·턴 사이 쉼이 길다.
> 수치는 전부 `assets/ui/stage3d.json` (`camera`·`shake`·`motion`·`cardFlip`·`impact`·`ambient`·`tempo`).

### 17.1 카메라 압박 (§8.4 개정)

- 초점 크기 상한 `focusSizeGain` **1.08 → 1.6**, 바라보는 높이 `focusHeight` 0.1 → **0.6**. 교전이 시작되면 캐릭터가 화면 높이의 약 40~45% 가 되게 파고든다. 크기는 교전마다 같다(상한 방식 유지)
  - [검수 결과] 2.0 은 머리 위 카드 뒤집기(키의 1.9 배 높이까지)가 위 띠에 가려졌다. 1.6 + 시선을 0.6 올려 카드와 발밑 게이지가 함께 들어오게 했다
- **넘침 막기**: 두 사람 사이가 멀어지면(밀려남·날아감) 둘 다(몸 폭·뻗은 칼까지 양쪽에 키 1.2 배 여유) 화면 가로 `camera.fitShare`(0.7) 안에 들도록 그때만 물러선다. 다시 붙으면 상한 크기로 돌아온다
- 타격 화각 펀치 `shake.fovPunch` 3.5 → **6**. 측면 회전 24° → **28°**, 기울기 2.5° → **4°**
- 교전이 끝나면 대기 카메라로 빠진다 (기존 그대로)

### 17.2 타격 반응 밀도 (§15 실험 기법의 본편 승격)

- **배경 누르기**: 무거운 타(피해 `motion.heavyDamage` 이상)·마지막 타·궁극기 마지막 베기에 배경을 `impact.dim.level`(0.45) 까지 0.03초에 눌렀다 0.12초 머물고 0.3초에 푼다. 캐릭터·효과·숫자는 누르지 않는다
- **흰 섬광**: 무거운 타·궁극기 마지막 베기에 화면 전체 흰 막을 `impact.flash.alpha`(0.28) 로 `impact.flash.seconds`(0.06) 동안. 궁극기 마지막 베기는 §15 C01 임팩트 프레임(실루엣)을 본편에서도 쓴다
- **피해 숫자** 크게: 기본 2.6em → 3.6em, 무거운 타 5em + 흔들림. 마지막 타는 금색 테두리
- **위력 충돌**: 합 라운드에서 양쪽 카드가 드러나면 두 사람 사이 가운데에 `24 : 17` 처럼 두 위력을 맞부딪혀 보이고, 이긴 쪽 숫자는 커지며 진 쪽 숫자는 깨지듯 흔들린다(0.5초). 교착은 둘 다 흔들린다
- 흔들림 줄이기(`prefers-reduced-motion`)면 섬광·숫자 흔들림을 끈다. 실험 모드의 줄이기 체크도 그대로 따른다

### 17.3 무대 채우기 — 상시 환경 입자

맵 원화 위에 늘 움직이는 것을 절차로 그린다. 그림 파일을 새로 만들지 않는다 (`ambient`)
- **떠다니는 먼지**: 카메라와 무대 사이 공간에 작은 밝은 점 `dust.count`(90)개. 느리게 떠오르고 옆으로 흐른다. 가까운 것은 크고 흐리다(깊이감)
- **떨어지는 물방울**: 위 철골 높이에서 무대 뒤쪽으로 가는 물줄기 `drips.count`(14)개. 바닥에 닿으면 작은 고리가 퍼지고 다시 위에서 떨어진다
- **낮은 안개**: 바닥 위 0~0.6H 높이에 반투명 안개 판 `fog.layers`(3)장이 서로 다른 속도로 좌우로 흐른다
- 밤바다(궁극기 환경)에서는 끈다. 교전 카메라에서도 보인다 (먼지는 카메라 앞에도 있어 파고든 화면을 채운다)
- 흔들림 줄이기면 먼지·안개 속도를 1/3 로

### 17.4 템포

- 교전이 끝나고 턴을 닫기까지, 턴을 닫고 다음 턴을 열기까지 쉼 `tempo.restSeconds` **0.5 → 0.15**
- 합 라운드 사이 쉼 `motion.roundRest` 0.18 → **0.1**, 맞은 뒤 머묾 `lingerAfterHit` 0.22 → **0.14**, 자리로 돌아가기 `returnTime` 0.3 → **0.22**, 흔들림 가라앉음 `settleTime` 0.55 → **0.4**
- 카드 공개 **크고 짧게**: 크기 `cardFlip.height` 0.9 → **1.25**, 돌기 `spinTime` 0.6 → **0.42**, 회전 수 3 → **2**, 드러난 뒤 머묾 `holdTime` 0.4 → **0.3**
- 예약이 남은 턴은 입력 없이 바로 교전한다 (SPEC-001 v4.0 §6)
