# SPEC-005 · 전투 연출 (v1.0)

상태: **확정 v1.1** / 작성 2026-09-24 / v1.1 몸짓 보강 2026-09-24

> 목표는 **림버스 컴퍼니 수준의 전투 연출** — 합이 한 번 오갈 때마다 누가 이겼는지 읽히고,
> 때리면 맞은 감각이 나는 것. **메커니즘은 가져오지 않는다.**
>
> 전투 규칙은 여전히 `SPEC-001` 하나뿐이다. 이 문서는 그 규칙이 낸 이벤트를
> **어떻게 보여 줄지**만 정한다. 도메인은 한 줄도 안 바뀌고 이벤트도 새로 만들지 않는다.

---

## 1. 가져오는 것과 안 가져오는 것

### 1.1 가져오는 것 — 연출 기법

아래는 액션·전략 게임에서 두루 쓰는 **보여 주는 기법**이다. 특정 게임의 규칙이 아니다.

| 기법 | 무엇을 전하나 |
|---|---|
| 합 교환 — 매 라운드 두 사람이 맞부딪히고 불꽃이 튄다 | 합이 여러 번 오간다는 것 |
| 머리 위 코인 뒤집기 | 이번 라운드에 몇 개가 성공했는지 |
| 위력 숫자 맞대기 | 왜 이겼는지 |
| 반동 — 진 쪽이 더 크게 밀린다 | 누가 이겼는지 |
| 히트스톱 — 맞는 순간 잠깐 멈춘다 | 타격감 |
| 카메라 펀치·기울기·흔들림 | 충돌의 무게 |
| 피해 숫자 | 얼마나 들어갔는지 |
| 스킬 이름 띠 | 무엇을 썼는지 |
| 대시 잔상 | 속도감 |
| 넉백·화면 번쩍임 | 큰 한 방 |
| 격파 슬로모 | 마무리 |

### 1.2 안 가져오는 것

- **규칙.** 속도 주사위, 공명, 흐트러짐, 죄악 자원, E.G.O 같은 림버스 고유 규칙은 하나도 넣지 않는다.
  코인·합·정신력·교착은 원래 우리 규칙이다 (원작 End-Distopirism, SPEC-001)
- **그림·UI 모양·폰트·아이콘·사운드.** 모양은 우리 톤(흑백/브라운, 거친 선)으로 새로 그린다
- **수치.** 연출 시간·크기는 전부 우리가 정해 `assets/ui/ui-data.json` 에 둔다

## 2. 합 한 번의 타임라인

도메인이 내는 이벤트 순서 그대로다 (실측 2026-09-24).

```
clashStart
  └ 스킬 이름 띠 · 준비 자세 · 앞으로 대시(잔상) · 카메라 붙기 + 기울기
라운드 × n
  coinRolled ×2        → 머리 위 코인이 뒤집힌다            [박자 coinSec]
  damageCalculated ×2  → 위력 숫자가 떠오른다                [박자 powerSec]
  clashRoundWin        → 양쪽 휘두르기 · 접점 불꽃 · 반동
   또는 deadlock          카메라 펀치 · 짧은 히트스톱         [박자 resultSec]
  coinLost             → 진 쪽 코인 하나가 깨진다
damageApplied
  └ 이긴 쪽 전용기 전체 · 무기 궤적 · 히트스톱 · 명중 섬광
    피해 숫자 · 넉백 · (큰 피해면) 화면 번쩍임
defeated → 슬로모
clashEnd → 합 배지 · 제자리로 · 카메라 원경 · 기울기 원위치
```

일방 공격은 라운드가 한 번이고 불꽃·반동이 없다. 공격자만 **맞는 쪽 옆으로** 달려간다 (SPEC-004 §7.7).

### 2.1 프레임 쓰임

소각원 프레임은 **12장뿐**이다. 장 이름 끝으로 찾아 쓴다 (다른 캐릭터도 같은 이름 규칙이면 그대로 된다).

| 순간 | 장 | 비고 |
|---|---|---|
| 대기 | `idle` | 숨쉬기(§2.2)를 얹는다 |
| 달려감 — 보는 쪽으로 | `advance` | 대시·일방 돌진 |
| 달려감 — 등 뒤로 | `retreat` | 제자리 복귀 |
| 합 시작·라운드 사이 | 전용기 첫 장 (준비 자세) | 다음 코인이 굴러갈 때 돌아온다 |
| 라운드 **승** | 전용기 마지막 장 (맞닿는 자세) | |
| 라운드 **패** | `retreat` (없으면 `guard`) | 모두가 매번 휘두르면 누가 밀렸는지 안 보인다 |
| 교착 | 둘 다 전용기 마지막 장 | |
| 피해가 들어가는 한 방 | 전용기 전체 | 무기 궤적은 이 한 방에만 |
| 맞음 | `hit` | 넉백·몸 번쩍임과 같이 |

### 2.2 몸짓 보강

장 수가 적어서 같은 장을 **움직여서** 부족분을 채운다. 새 그림을 만들지 않는다.

| 몸짓 | 방식 |
|---|---|
| 휘두름 박자 | 여러 장짜리 동작은 첫 장(예비 동작)을 길게 `windupMs`, 나머지를 짧게 `snapMs` 로 끊는다. 균등 재생이면 흐느적거린다 |
| 내딛기 | 한 방을 휘두를 때 예비 동작 동안 살짝 뒤로 당겼다가, 휘두르는 순간 `lunge` 만큼 앞으로 나갔다 돌아온다 |
| 몸 번쩍임 | 넉백을 받으면 `hurtSec` 동안 같은 그림을 더하기 합성으로 한 번 더 얹는다 |
| 숨쉬기 | 서 있을 때 발을 축으로 세로 `breathe` 만큼 늘었다 줄었다 한다. 사람마다 박자를 어긋나게 한다 |
| 궤적 추종 | 프레임에 묶인 무기 궤적은 휘두르는 사람을 따라간다. 내딛는 동안 궤적만 제자리에 남으면 칼과 어긋난다. 연기·잔불·섬광은 터진 자리에 남는다 |
| 이펙트 반전 | 왼쪽을 보는 캐릭터의 이펙트는 비트맵·피벗을 같이 뒤집는다 (SPEC-002 §6-5) |

## 3. 계층

도메인 → 어댑터 → 렌더러 구조는 그대로다 (SPEC-003).

| 층 | 새로 하는 일 |
|---|---|
| `render/presenter.ts` | 합 시작엔 **준비 자세 한 장**만. 라운드마다 이긴 쪽은 맞닿는 자세, 진 쪽은 물러나는 자세 (§2.1). 전용기 전체와 무기 궤적은 **피해가 들어가는 한 방**에 |
| `ui/director.ts` | 코인·위력·합 결과·코인 깨짐·스킬 띠·피해 숫자·히트스톱·넉백·번쩍임 명령, 라운드 박자 |
| `camera/director.ts` | 펀치·기울기·슬로모. 수치는 데이터에서 받는다 |
| `renderer/canvas.ts` | 전부 그린다. 히트스톱·슬로모는 **렌더러의 시계**에만 걸린다 |

### 3.1 명령은 이벤트 순서대로 섞여 흐른다

프리젠터·UI·카메라 명령을 **이벤트 하나마다** 모아 대기열에 넣는다. 어댑터별로 한 턴 분을
통째로 넣으면 프리젠터 명령이 전부 앞에 서고 UI 명령이 전부 뒤에 서서 박자가 안 맞는다.
카메라 명령도 같은 대기열로 흘린다. 바로 적용하면 턴 전체의 마지막 교전으로 카메라가 먼저 튄다.

카메라 감독의 "뒤에 교전이 남았으면 원경을 끼우지 않는다" 규칙은 한 턴 전체를 미리 봐야
한다. 이벤트를 하나씩 줄 때는 **남은 이벤트를 두 번째 인자로 같이 준다.**

### 3.2 프레임에 묶인 이펙트

`frameId` 가 붙은 무기 궤적은 **그 장이 실제로 화면에 떠 있을 때** 터진다. 대기열에서 꺼낸
시각이 아니다. `playFrames` 는 마지막 장이 시작될 때까지(= 접촉 순간)만 뒤를 붙든다.

## 4. 수치 — `assets/ui/ui-data.json`

길이는 캐릭터 키 `H` 배수, 시간은 초. 키가 빠지면 던진다 (SPEC-004 §8 과 같은 방침).

| 절 | 키 | 뜻 |
|---|---|---|
| `clash` | `coinSec` | 코인 뒤집기 박자 |
| | `powerSec` | 위력 숫자 박자 |
| | `resultSec` | 맞부딪힘 박자 |
| | `recoilWinner` / `recoilLoser` | 반동 거리 |
| | `recoilSec` | 반동 후 돌아오는 시간 |
| | `sparkSize` | 접점 불꽃 크기 |
| | `coinSize` | 머리 위 코인 지름 |
| | `powerSize` · `powerOffsetX` · `powerOffsetY` | 위력 숫자 크기·자리. **등 뒤** 가슴 높이 (x 는 상대 쪽이 +) |
| | `contactHeight` | 맞부딪히는 높이 (발에서부터) |
| `hitStop` | `clashSec` | 라운드마다 멈추는 시간 |
| | `baseSec` · `perDamageSec` · `maxSec` | 피해 한 방에 멈추는 시간 = min(max, base + 피해 × per) |
| `damageText` | `rise` · `sec` | 피해 숫자가 떠오르는 높이·시간 |
| | `heavyDamage` | 이 이상이면 큰 한 방 (번쩍임·큰 글씨) |
| | `height` · `size` | 뜨기 시작하는 높이·글자 크기 |
| `banner` | `sec` | 스킬 이름 띠가 떠 있는 시간 |
| | `height` · `offsetX` · `size` | 높이·비키는 거리·글자 크기. **등 뒤** 허벅지 높이 |
| `knockback` | `distance` · `sec` | 맞은 쪽이 밀리는 거리·복귀 시간 |
| `flash` | `alpha` · `sec` | 큰 한 방의 화면 번쩍임 |
| `afterimage` | `count` · `intervalSec` · `alpha` | 대시 잔상 |
| `motion` | `othersAlpha` | 교전 중 싸우지 않는 사람의 불투명도. 0 이면 숨긴다 |
| | `windupMs` · `snapMs` | 여러 장짜리 동작의 첫 장·나머지 장 길이 |
| | `lunge` · `lungeSec` | 한 방 내딛기 거리·시간 |
| | `breathe` · `breatheSec` | 숨쉬기 폭·주기 |
| | `hurtSec` | 맞고 몸이 번쩍이는 시간 |
| `camera` | `focusZoom` | 교전에 붙을 때 배율 (기존 1.6 을 데이터로 옮김) |
| | `punchZoom` · `punchSec` | 라운드마다 순간 확대 |
| | `tiltDeg` | 합 중 기울기 |
| | `slowmoScale` · `slowmoSec` | 격파 슬로모 |
| | `shakeReferenceDamage` | 이 피해면 최대 흔들림 (기존 30 을 데이터로 옮김) |

**측정 전 시작값이다.** 눈으로 보고 어색하면 이 파일만 고친다.

### 4.1 한 사람 둘레의 자리 배치

맞붙으면 두 사람이 `pairGap`(0.55 H) 만큼 붙는다. 위력 숫자와 스킬 띠를 **상대 쪽**에 두면
두 사람 것이 가운데 접점에서 겹친다(실제로 겹쳤다). 가운데는 불꽃만 남기고 나머지는 등 뒤로 뺀다.

```
        [코인]
        [체력바][정신력바]
 [위력]   몸   ──접점 불꽃──   몸   [위력]
 [띠]
```

### 4.2 싸우는 둘 말고는 숨긴다

카메라가 두 사람에게 붙어 있는 동안, 나머지는 몸·바·코인을 `motion.othersAlpha` 까지 흐린다.
기본값 0 — **숨긴다.** v1.0 은 어둡게만 눌렀는데 뒤에 서 있는 게 거슬렸다.
한 편 4명이 같은 x 에 깊이로만 서 있어서(SPEC-003 §6.5.1.1) 바도 겹쳐 쌓인다.
누가 싸우는지 한눈에 읽히게 하는 연출이지 규칙이 아니다. 카메라가 원경으로 빠지면 다시 보인다.

## 5. 지켜야 할 것

1. 도메인·이벤트를 바꾸지 않는다
2. 히트스톱·슬로모가 **도메인 결과에 영향을 주지 않는다** — 렌더러 시계에만 걸린다
3. 연출 수치를 코드에 박지 않는다
4. 림버스의 그림·UI·폰트를 옮기지 않는다. 모양은 우리 것으로 그린다
5. 에셋 없는 캐릭터도 코인·숫자·바·배지는 뜬다 — 이건 그림이 아니라 정보다.
   키·머리 높이 같은 **비율만** 에셋 있는 캐릭터에서 빌린다 (`Stage.reference()`).
   그림을 빌리지 않으므로 SPEC-002 §10 과 충돌하지 않는다. SPEC-004 의 "에셋 없으면 UI 도 안 붙인다"는 이걸로 대체된다
