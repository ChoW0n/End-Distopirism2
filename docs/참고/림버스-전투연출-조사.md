# 림버스 컴퍼니 전투 규칙·모션 전이·이펙트 조사

조사일: 2026-09-25
목적: 전투 연출과 스프라이트 제작에 사용할 판정·상태·표현의 대응 관계 정리.
주의: 이 문서는 Project Moon의 내부 엔진 명세서나 원본 애니메이터 덤프가 아니다.

> 보관 메모: 사용자가 조사해 전달한 문서를 그대로 옮겼다 (2026-09-25). **스펙이 아니라 참고 자료다.**
> 전투 규칙의 기준은 여전히 `SPEC-001`, 연출은 `SPEC-005` 다. 이 문서의 [구현 해석] 을 가져다 쓸 때는
> 해당 스펙에 먼저 적고 근거로 이 문서를 단다. 메커니즘은 가져오지 않는다 (SPEC-005 §1.2).

## 0. 확인 범위와 읽는 방법

- **[자료 확인]** 공식 게임 소개, 공식 공지의 검색 가능 본문, 공개 게임 데이터·스프라이트 목록·전투 설명에서 확인한 내용.
- **[구현 해석]** 확인한 규칙을 다른 게임에 옮기기 위해 제안하는 상태 분리, 이벤트 순서, 연출 설계. 원작의 실제 함수명·레이어 구조를 뜻하지 않는다.
- **[미확인]** 특정 인격의 정확한 프레임 순서, 최신 빌드의 공통 승리 포즈, 특정 상태와 원본 파일의 일대일 대응, 밀리초 단위 재생 시간.

이번 조사에서는 기존 Library의 GIF·스프라이트 ZIP 목록과 문서 내용은 찾았으나, ZIP 원본 바이트를 가져오는 요청이 권한 오류로 실패했다. 공식 영상 페이지도 확인했지만 영상의 프레임별 판독 결과를 확보하지 못했다. 따라서 원본 GIF 전량을 재생해 검수했다거나 최신 실행 화면을 프레임 단위로 측정했다는 주장은 하지 않는다.

공식 2023년 전투 소개 영상은 개발 중 버전이라는 안내가 있는 자료다. 현재 규칙 전체를 그 영상 하나로 확정해서는 안 된다. 특히 파괴 불가 코인과 후속 특수 방어 규칙을 별도로 봐야 한다. [S03–S06]

## 1. 가장 중요한 결론

림버스를 재현할 때는 다음 세 층을 분리해야 한다.

| 층 | 무엇을 뜻하는가 | 예시 |
|---|---|---|
| 전투 판정 | 실제 게임 결과 | 합의 개별 비교, 코인 파괴, 적중, 보호막 감소, 흐트러짐, 사망 |
| 캐릭터 표현 | 그 결과를 전달하는 자세 | 대기, 이동, 방어, 회피, 피격, 공격별 포즈 |
| 장면 연출 | 관객에게 결과를 읽히는 장치 | 위치 이동, 카메라, 섬광, 궤적, 효과음, 코인 UI, 피해 숫자 |

판정 하나가 이미지 한 장과 항상 일대일로 대응하지 않는다. 예를 들어 공개 자료에는 같은 종류의 자세를 Guard 또는 Clash로 다르게 분류한 사례가 있고, 공격 애니메이션은 기본 포즈 목록과 별도로 수록된다. [S07, S09, S10]

[구현 해석] 아래 식이 작업 단위로 더 적합하다.

```
전투 연출 = 판정 이벤트
          + 현재 캐릭터 상태
          + 스킬별 포즈 시퀀스
          + 공간 이동
          + 효과·음향·카메라
```

idle → dash → attack → idle 하나만 만들면 합 도중 재대결, 공격 중 흐트러짐, 파괴 불가 코인, 사망, 결과 화면을 올바르게 처리할 수 없다.

## 2. 전투 규칙 중 연출을 결정하는 부분

### 2.1 턴과 행동

[자료 확인] 플레이어가 행동을 정하면 아군과 적의 행동이 전개되며, 서로 겨누는 스킬은 합으로 연결될 수 있다. 공식 소개는 이를 턴제 지시와 동시적인 행동 표현의 결합으로 설명한다. 따라서 '아군 전체가 공격한 다음 적 전체가 공격한다'는 교대식 전투로 이해하면 맞지 않는다. [S01, S02]

집중 전투에서는 속도가 더 빠른 수감자가 다른 수감자를 향한 적 스킬의 대상을 바꿔 합을 가져올 수 있다. 자신이 원래 공격 대상인 경우와, 남의 공격을 대신 받아내는 경우를 구분해야 한다. 속도는 매 턴 범위 안에서 결정되며, 일반 전투와 집중 전투의 대상 지정 방식도 다르다. [S18]

[구현 해석] 속도 수치, 화면상의 이동 속도, 애니메이션 배속을 같은 변수로 만들지 않는다. 행동 순서가 빠르다고 도끼 애니메이션 자체까지 배속되어야 하는 것은 아니다.

### 2.2 코인과 위력

[자료 확인] 스킬에는 기본 위력과 코인 위력이 있다. 앞면이 나온 코인의 위력이 적용된다. 플러스 코인과 마이너스 코인은 의미가 반대이므로 '앞면=무조건 좋은 결과'가 아니다. 일반적인 정신력 범위는 -45~45이며, 앞면 확률은 정신력 0에서 50%, +45에서 95%, -45에서 5%다. [S18, S19]

[계산 예시] 다른 보정이 없는 기본 위력 4, 코인 위력 +3, 코인 3개의 가상 스킬:

```
합 비교: 세 코인이 모두 앞면이면 4 + 3 + 3 + 3 = 13
공격: 코인을 순차 적용하며 모두 앞면이면 7 → 10 → 13
```

이 숫자는 설명용 가정이며 특정 인격의 스킬 데이터가 아니다. 공격 단계의 순차 누적과 합 단계의 위력 비교를 같은 화면 처리로 뭉치면, 다단 공격의 후반 타격이 왜 달라지는지 표현하기 어렵다.

[구현 해석] ClashRoll과 AttackCoinRoll을 별도 이벤트로 둔다. 코인 앞·뒷면의 판정이 바뀌어도 무기 그립이나 캐릭터 외형을 임의로 바꾸지 않는다. 앞면 전용 효과가 있는 스킬만 해당 연출 분기를 연결한다.

### 2.3 합은 한 번의 비교로 끝나지 않는다

[자료 확인] 일반적인 합은 위력을 비교해 낮은 쪽의 코인을 하나 제거하고, 양쪽에 합을 계속할 코인이 남아 있으면 다시 비교한다. 무승부는 최종 승패가 아니다. 상대 코인을 모두 무력화해야 합 전체의 승자가 정해진다. 승자는 공격권을 얻는다. [S01, S06]

[구현 해석] 적어도 다음 이벤트는 나눈다.

```
ClashExchangeWon      합의 개별 비교에서 우세
ClashExchangeLost     개별 비교에서 열세
ClashExchangeTied     개별 비교에서 무승부
ClashWon              합 전체의 최종 승리
ClashLost             합 전체의 최종 패배
```

개별 비교에서 한 번 이겼다고 승리 대사나 전투 결과 화면을 재생하면 안 된다. 원작의 무승부 반복 상한을 이번 조사에서 확정하지 못했으므로 임의로 '3회 제한' 같은 숫자를 원작 규칙으로 넣지 않는다.

### 2.4 합과 실제 적중은 다른 사건이다

[자료 확인] 합은 기본적으로 공격권을 가리는 과정이다. 그러나 출혈처럼 합의 코인 판정 자체에 반응하는 효과는 합 도중에도 체력을 감소시킬 수 있다. 출혈은 공격 스킬의 개별 합 교환에서, 승패·무승부를 포함해 발동할 수 있다. [S11]

[구현 해석] '합 장면에서는 HP가 절대 변하지 않는다'도 틀리고, '합에서 밀릴 때마다 무기 피해를 준다'도 틀리다. 화면에 나타난 HP 감소가 OnHit 때문인지 OnCoinRoll 계열 효과 때문인지 구분한다.

### 2.5 정신력 변화도 임의로 넣지 않는다

[자료 확인] LCB 로쟈의 공개 정신력 요인에는 합 승리·조건을 만족하는 적 처치 등에 따른 회복과, 아군 사망 등에 따른 감소가 명시돼 있다. '모든 인격이 합에서 질 때마다 기본적으로 정신력이 떨어진다'는 규칙으로 일반화할 근거는 아니다. [S07, S20]

[구현 해석] 화면에서 실패했다는 인상만으로 SP 감소 팝업을 추가하지 않는다. 해당 인격·스킬의 실제 정신력 요인과 일치할 때만 표시한다.

### 2.6 스킬 구성·속성·공명

[자료 확인] 기본적인 인격 스킬 묶음은 스킬 1 세 장, 스킬 2 두 장, 스킬 3 한 장의 구조와 방어 스킬로 설명된다. 특수 스킬 교체·변형까지 모두 이 기본형과 같다는 뜻은 아니다. 같은 죄악 속성을 묶는 공명과 연속 배치의 완전 공명은 전투 보정과 패시브에 관여한다. [S18]

공격 위력은 피해 숫자와 같은 개념이 아니다. 물리 공격 종류, 죄악 속성, 내성, 공격·방어 레벨과 각종 효과가 실제 피해에 관여한다. 따라서 '합에서 20을 띄웠으므로 맞으면 무조건 HP 20 감소'로 연결하지 않는다. [S06, S18]

[구현 해석] UI에서 다음 표시를 구분한다: 스킬의 위력 범위, 합 예상, 실제 코인 결과, 실제 피해, 추가 고정 피해. 이 다섯 가지를 하나의 큰 숫자로 처리하지 않는다.

### 2.7 뒷면은 빗나감이 아니다

[자료 확인] 코인 뒷면은 해당 코인의 앞면 보정이 붙지 않는 결과다. 기본 위력이 있으므로 뒷면이 나왔다고 곧바로 공격이 빗나가거나 타격이 사라지는 것은 아니다. 마이너스 코인은 오히려 뒷면이 높은 위력을 유지하는 데 유리할 수 있다. [S18, S19]

[구현 해석] Tails와 Evaded를 같은 이벤트로 묶지 않는다. 전자는 위력 계산의 결과이고, 후자는 상대 회피가 성공한 결과다. 뒷면 공격에도 유효한 적중이 발생했다면 해당 타격과 HP 반응을 보여준다.

### 2.8 전투 형식

[자료 확인] 일반 전투와 집중 전투는 대상 선택 방식이 다르고, 연속 전투는 전장 인원이 사망했을 때 대기 인원이 투입되는 구조를 포함한다. 모든 전투를 고정 6명, 매 턴 한 슬롯, 고정된 1:1 짝으로 이해하면 안 된다. [S37]

[구현 해석] 전투 참가자, 현재 전장에 존재하는 캐릭터, 실행할 행동 슬롯을 별개로 관리한다. 같은 캐릭터가 여러 행동을 가질 수 있는 경우에는 이미지 인스턴스를 복제하는 대신 행동 예약을 분리한다.

## 3. 원본 리소스에서 확인되는 포즈 분류

[자료 확인] LCB 로쟈의 현재 공개 갤러리에는 Idle, Moving, Guard, Evade, Hurt, Dead와 별도의 Skill 1·2·3 애니메이션이 있다. 예전 Fandom 쪽은 Guard에 해당하는 분류를 Clash라고 표시하기도 한다. 따라서 분류명 자체를 엔진 상태명으로 확정할 수 없다. [S07, S09]

| 공개 분류 | 제작 관점의 역할 | 단정하면 안 되는 부분 |
|---|---|---|
| Idle | 행동을 수행하지 않는 기본 자세 | 모든 Idle이 한 장짜리이거나 호흡 효과가 같다는 주장 |
| Moving | 공간을 이동할 때의 자세 | 전진·후퇴·복귀가 전부 같은 파일을 쓴다는 주장 |
| Guard / Clash | 방어적 자세 또는 합 표현에 관련된 자료 | 이 자세가 보일 때마다 실제 방어 스킬이 발동했다는 주장 |
| Evade | 회피 자세 | 자세가 보였다는 이유만으로 HP 피해가 무효였다는 주장 |
| Hurt | 충격을 받은 자세 | 피격·흐트러짐·합 열세의 엔진 상태가 전부 같다는 주장 |
| Dead | 사망 상태 표현 | 모든 인격마다 독립적인 시체 이미지가 있다는 주장 |
| Skill animations | 스킬별 공격 표현 | 코인 1개가 이미지 1장이라는 주장 |

위키의 편집자 설명에는 합 애니메이션 개선 이후 이동·회피·방어·피격 자세가 필요해졌다는 언급도 있다. 다만 이 설명은 공식 상태 전이 명세가 아니므로, 특정 합 승패에 어떤 원본 파일을 무조건 호출하는지까지 확정하는 근거로 사용하지 않는다. [S10]

### 리소스 개수에 관한 수정

기존 작업 문서의 '기본 포즈 6종만으로 전체를 판단하지 말라'는 주의는 유효하다. 하지만 '모든 인격은 총 27~28장'이라는 수치도 원작 전체에 적용할 수 없다. 변형 자세와 별도 스킬 애니메이션이 존재하며, 와일드헌트 히스클리프처럼 탑승·비탑승 기본 포즈가 구분된 사례도 있다. [S21]

## 4. idle → 이동 → 합 → 공격 → 복귀를 어떻게 읽어야 하는가

다음은 [구현 해석] 전이표다. 원작의 공통적인 판정 구조를 시각화하기 위한 설계이며, 실제 엔진 클래스명이나 모든 인격의 정확한 재생 순서를 주장하지 않는다.

```
명령 대기 / Idle
  └─ 행동 시작
      └─ 교전 위치 확보 / Approach 또는 Moving
          ├─ 합 없음 → 공격 준비
          ├─ 방어 상호작용 → 방어별 처리
          └─ 합 있음
              └─ 개별 합 비교
                  ├─ 우세 + 상대 코인 남음 → 다음 합 교환
                  ├─ 열세 + 내 코인 남음   → 다음 합 교환
                  ├─ 무승부               → 다음 합 교환
                  ├─ 최종 승리            → 공격 준비
                  └─ 최종 패배            → 상대 공격 수용

공격 준비
  └─ 사용 가능한 코인별 공격
      └─ 각 코인의 판정·적중 효과·상태 변화 처리
          ├─ 다음 코인 사용 가능 → 다음 타격
          ├─ 행동 중단          → 중단 상태
          └─ 공격 종료          → 회수 / 재배치

회수 / 재배치
  ├─ 다음 행동 대기 → Idle
  ├─ 흐트러짐      → Staggered
  ├─ 사망          → Dead
  └─ 전투 종료     → 결과 연출
```

### 4.1 Idle에서 출발하는 부분

Idle은 '매 프레임 아무 일도 하지 않는 이미지'가 아니라 명령·판정을 기다리는 상태로 취급한다. 공격이 예약돼 있어도 아직 자기 행동이 시작되지 않았다면 대기 상태일 수 있다.

출발 시에는 전진 포즈 변경과 실제 위치 이동을 분리한다. 이동 거리, 접지, 상대와의 간격은 맵·캐릭터 크기에 따라 정하고, 스프라이트 자체의 빈 여백으로 거리를 계산하지 않는다.

### 4.2 접근과 합 교환

접근 이동은 교전 위치를 잡는 과정이고, 합 교환은 그 위치 근처에서 공방을 보여주는 과정이다. 둘을 합치면 합이 반복될 때마다 캐릭터가 시작 지점까지 돌아갔다 다시 달려오는 문제가 생긴다.

다음 네 가지를 별도 파라미터로 두면 좋다.

- 접근 거리: 최초 교전 위치를 잡는 이동.
- 교환 거리: 합 한 번에서 오가는 짧은 이동.
- 피격 변위: 실제 타격을 읽히게 만드는 국소 이동.
- 복귀·재배치 거리: 행동이 끝난 뒤 다음 배치를 만드는 이동.

이 구분은 제작 제안이며, 원작의 실제 거리값은 측정하지 않았다.

### 4.3 합 전체에서 승리한 직후

핵심은 '환호'가 아니라 공격권 획득이다. 공방 표현에서 해당 스킬의 공격 시퀀스로 넘어가야 한다. 최종 합 승리를 스킬 3이나 강공격 모션으로 고정하면 안 된다. 선택한 스킬과 남은 코인이 결정하는 공격을 해야 한다.

### 4.4 합 전체에서 패배한 직후

일반 코인만 있는 스킬은 공격권을 잃고, 상대의 실제 공격을 받는 쪽으로 전환된다. 이 시점의 논리 상태는 '사망'이 아니다. 상대 공격을 맞고도 살아 있으면 정상 복귀하거나 흐트러짐으로 남을 수 있다. 파괴 불가 코인이 있는 경우는 아래 6절의 예외 분기로 처리한다.

### 4.5 공격 후 복귀

AttackFinished → Idle을 조건 없이 실행하지 않는다. 마지막 코인에서 시전자나 대상이 죽었는지, 흐트러졌는지, 변신·추가 행동·전투 종료가 발생했는지 먼저 확인한다.

원작이 모든 공격 뒤에 반드시 같은 장소로 돌아오는지, 별도 후퇴 파일을 쓰는지, 어느 인격이 이동 포즈를 재사용하는지는 이번 조사에서 프레임 단위로 확정하지 않았다.

## 5. 방어·회피·반격은 서로 다른 시퀀스다

[자료 확인] 일반 Guard는 보호막, Evade는 공격 위력과의 비교를 통한 회피, Counter는 피격 후의 반격으로 구분된다. 회피 위력이 현재 공격 위력 이상이면 회피에 성공한다. 성공한 회피는 재사용될 수 있고 실패하면 회피가 소진된다. 합 가능 방어·반격 같은 변형은 일반형과 같은 것으로 취급하면 안 된다. [S06, S22]

아래의 자세·이벤트 배치는 **[구현 해석]**이다.

| 상호작용 | 방어자 흐름 | 공격자 흐름 | 필수 분리 |
|---|---|---|---|
| 일반 방어 | 방어 준비 → 보호막 확보 → 충격 수용 | 공격 시퀀스 진행 | 보호막 손실과 HP 손실 |
| 회피 성공 | 회피 준비 → 회피 성공 → 다음 코인 대응 | 타격 동작은 진행하되 적중 결과는 없음 | 무기 궤적과 적중 이펙트 |
| 회피 실패 | 회피 준비 → 실제 피격 → 회피 소진 | 실제 적중 처리 | 실패했다고 공격자의 남은 코인을 삭제하지 않기 |
| 일반 반격 | 피격 → 생존·행동 가능 여부 확인 → 반격 | 공격 후 반격을 받을 수 있음 | 피격 없는 공짜 반격으로 바꾸지 않기 |
| 합 가능 방어 | 합 교환 → 승패별 방어 효과 | 해당 합 결과에 맞춘 행동 | 일반 Guard와 다른 분기 |
| 합 가능 반격 | 공격과 합 → 승패별 처리 | 해당 합 결과에 맞춘 행동 | 일반 Counter와 다른 발동 시점 |

### 회피 연출에서 특히 중요한 것

[구현 해석] 방어 스킬을 선택한 상태와 실제 방어가 활성화된 상태를 나눈다. 선택한 순간부터 무조건 모든 공격을 막는 것으로 처리하지 말고, 선택 대상과 실제 발동 트리거를 검수한다.

[구현 해석] 회피 성공 시 무기 자체가 존재하지 않았던 것처럼 지우는 대신, 공격 준비·궤적은 진행되고 대상의 적중점 이펙트·HP 피해가 발생하지 않도록 나누는 편이 판정을 읽기 좋다. 회피 실패 순간부터는 피격 반응으로 전환한다.

실제 회피는 방어 스킬의 위력 비교에 따른 판정이지, 모든 공격 전에 공통으로 굴리는 '방어 레벨 × 일정 확률' 형태의 기본 규칙으로 설명할 수 없다. 다른 게임에서 그런 회피율을 쓰는 것은 별도의 설계다.

## 6. 파괴 불가 코인: 합 승리가 무피해를 뜻하지 않는 이유

[자료 확인] 빨간 파괴 불가 코인은 합에서 패배해도 완전히 없어지지 않고 균열 상태로 남아 후속 공격이 가능하다. 균열 시 코인 위력의 크기가 1로 고정되는 기본 처리가 있지만, 이후 코인 위력 보정이 적용될 수 있다. 이것은 '기본 위력도 1', '최종 피해가 항상 1'이라는 뜻이 아니다. [S06, S19, S23]

개발사는 2025-05-22 공지에서 적 애니메이션을 보여주고 전투 밀도를 더하려는 도입 의도를 설명했다. 모든 합을 이기면 적이 공격 모습을 전혀 보여주지 못하는 문제와 관련된 장치로 이해할 수 있다. [S03]

[구현 해석]

```
A 합 최종 승리
  → A의 공격
  → B 생존 / 행동 가능 여부 재확인
  → B의 후속 공격 가능한 균열 코인 처리
  → 양측 행동 종료 확인
  → 정상 복귀 또는 상태 유지
```

파괴 불가 코인이라고 사망·흐트러짐을 전부 무시한다고 가정하지 않는다. 별도 패시브나 스킬 문구가 있다면 그것을 우선 적용한다.

또한 스킬에 붙은 '합 패배 시 피해 감소', '흐트러뜨리지 못함', '균열 없이 적중 시 추가 효과'는 서로 다른 조건이다. 특정 적이 그런 문구를 가진다고 모든 빨간 코인에 일괄 적용해서는 안 된다. 실제 공개 적 스킬에도 이 조건들이 따로 적혀 있다. [S24]

현재 공개 데이터에는 녹색 Excision Coin도 있으며, 파괴 불가 코인을 합에서 파괴할 수 있다는 별도 규칙이 있다. 영문 표기를 그대로 사용하며, 한국어 공식 명칭은 이 문서에서 확정하지 않는다. [S12]

## 7. 피격·흐트러짐·사망·비치명적 패배

### 7.1 피격

[구현 해석] 피격은 순간적인 반응이다. 피해량 적용, 충격 자세, 적중 효과, 국소 넉백을 묶되, 그 직후의 상태는 따로 결정한다. 피해가 있었다고 항상 흐트러지는 것도, 피격 자세를 썼다고 항상 죽는 것도 아니다.

### 7.2 흐트러짐

[자료 확인] 흐트러짐은 HP의 임계선과 관련된 지속 상태다. 기본적으로 발생한 턴과 그 다음 턴의 행동을 제한하고, 물리 내성을 크게 악화시킨다. Stagger / Stagger+ / Stagger++의 물리 내성 값은 2 / 2.5 / 3으로 구분된다. 모든 효과와 예외를 단순히 '최종 피해 2배'로 표현하는 것은 부정확하다. [S06]

[구현 해석] 별도의 흐트러짐 이미지 유무와 관계없이 Staggered 논리 상태는 필요하다. 피격 애니메이션이 끝났다는 이유로 Idle로 복귀해 다시 공격하면 안 된다. 회복 조건이 만족될 때까지 행동 불가와 화면 상태를 유지한다.

### 7.3 일반 사망

[자료 확인] LCB 로쟈의 공개 자료는 기본 Dead Sprite를 모든 인격에서 사용하는 사망 스프라이트로 명시한다. 인격이 사망 시 벗겨지는 표현 역시 인격 설명 자료에서 다룬다. 따라서 '인격마다 그 복장의 시체 이미지를 반드시 따로 만든다'는 구조로 이해하면 틀릴 수 있다. [S07, S25]

[구현 해석] 시체 표시, 스킬 취소, 대상 후보 제거, 아군 사망 이벤트, 연속 전투의 교대 처리를 별개 이벤트로 둔다. 사망한 캐릭터를 대기 호흡이나 복귀 이동의 대상으로 계속 남겨두지 않는다.

### 7.4 특수 사망

[자료 확인] 다음은 실제로 별도 사망 표현이 기록된 사례다.

| 사례 | 자료에서 확인되는 특수 표현 |
|---|---|
| 장미 표지판 / Sign of Roses | 특정 기믹으로 죽은 수감자의 시체를 덩굴이 감싸고 장미가 피는 표현 |
| 종말 달력 / Doomsday Calendar | 특정 공격으로 죽으면 불타고 보라색 잔여물로 덮이는 표현 |
| 경멸의 나선 / Spiral of Contempt | 무릎을 꿇고 손을 모은 시체 위로 황금 가지가 자라는 표현 |

이 사례들은 각각의 공격·기믹 조건에 묶여 있다. 모든 처치를 같은 붉은 파티클과 시체 한 장으로 처리하면 원작의 특수 연출 층을 잃는다. [S26–S28]

### 7.5 쓰러졌지만 죽지 않은 적

[자료 확인] 적의 공개 갤러리에는 Defeated Sprite와 Dead Sprite가 따로 있는 사례가 있다. Dead Rabbits Boss, Night Drifter 같은 적의 자료에서 이러한 구분을 확인할 수 있다. Night Drifter에는 특정 생존·HP 조건에 따라 승리 전 특수 애니메이션이 발생하는 설명도 있다. [S29, S30]

[구현 해석] 스토리 전투에서는 Defeated와 Dead를 구분한다. 전투에서는 졌지만 대화나 컷신에 계속 등장해야 하는 적을 사망 상태로 지워버리지 않는다.

## 8. 승리·패배 시 정확히 무엇을 구분해야 하는가

| 사건 | 확인되는 의미 | 연출 설계에서의 처리 | 원작 포즈 검증 상태 |
|---|---|---|---|
| 합의 한 교환 승리 | 상대 코인 하나를 무력화하는 과정 | 공방을 이어가거나 합 종료로 전환 | 인격별 정확한 파일 미확인 |
| 합의 한 교환 패배 | 자기 코인을 잃는 과정 | 남은 코인이 있으면 재대결 | 동일 |
| 합 최종 승리 | 공격권 획득 | 선택한 스킬의 공격으로 연결 | 공통 환호 포즈로 확정 불가 |
| 합 최종 패배 | 일반 공격권 상실 | 상대 공격 수용, 특수 코인 예외 처리 | 사망 포즈와 동일시 불가 |
| 전투 승리 | 전멸 또는 별도 승리 조건 만족 | 현재 행동 종료와 결과 연출 연결 | 최신 빌드의 보편적 고정 포즈 미확인 |
| 전투 패배 | 전멸 또는 별도 실패 조건 만족 | 살아 있는 자와 사망자를 구분한 채 실패 연출 | 생존자 전용 패배 포즈 일괄 적용 근거 없음 |

### 승리 대사와 승리 모션은 별개다

[자료 확인] LCB 로쟈의 음성 자료에는 공격 개시, 적 흐트러짐, 자신 흐트러짐, 적 처치, 아군 사망, 승리, 추가 조건 달성, 패배가 서로 다른 항목으로 존재한다. [S08]

이 사실은 승리·패배 음성이 있다는 근거이지, 별도의 전투용 victory.png 또는 defeat.png가 반드시 있다는 근거는 아니다.

[미확인] 이번에 확보한 자료로는 '마지막 적을 처치하면 모든 인격이 항상 특정 자세를 취한다', '항상 마지막 공격 자세로 멈춘다', '항상 Idle로 정렬한 뒤 결과 화면으로 간다' 중 어느 것도 원작 전체의 공통 규칙으로 확정할 수 없다. 결과창 진입 직전 포즈를 최신 실제 영상에서 따로 대조해야 한다.

[구현 해석] 별도 원작 포즈를 확인하기 전에는 새로운 승리 춤이나 무릎 꿇는 패배 포즈를 임의로 만들어 '림버스식'이라고 부르지 않는다. 우선 현재 유효 상태를 보존하고, 연출 감독이 마지막 타격·사망·특수 컷신 종료 후 결과 화면으로 넘기도록 만든다.

## 9. 스킬 애니메이션과 코인 수의 관계

[자료 확인] 일반 포즈와 스킬 애니메이션은 따로 수록된다. 또한 현재 공개 적 데이터에는 스킬명이 아니라 코인마다 선택한 무기에 따라 애니메이션이 달라지는 사례도 있다. 즉, '스킬 하나=고정 GIF 하나'만으로 원작의 모든 사례를 설명할 수 없다. [S07, S31]

[구현 해석] 한 코인의 연출은 다음처럼 나눌 수 있다.

```
준비 자세
  → 가속·공격 자세
  → 판정 시점
  → 타격 잔상·후속 자세
  → 다음 코인을 위한 연결
```

코인 하나가 한 장의 이미지라는 뜻이 아니다. 반대로 화면에서 여러 섬광이나 칼자국이 나와도 그것만으로 코인 수나 실제 적중 횟수를 세면 안 된다. 판정은 코인·재사용·추가 피해 이벤트를 기준으로 추적한다.

### 스킬 데이터에 넣을 항목

[구현 해석]

| 항목 | 이유 |
|---|---|
| 원래 코인 인덱스 | 합에서 일부 코인이 무력화되어도 효과와 표현의 연결 보존 |
| 코인 상태 | 정상·균열·제거·재사용 대기 구분 |
| 준비 / 타격 / 회수 포즈 | 위력 판정과 그림 전환을 분리 |
| 접촉 시점 | 숫자·피격·이펙트가 따로 놀지 않게 함 |
| 대상 선택 정책 | 단일·광역·코인별 분산 타격 구분 |
| 행동 중단 규칙 | 사망·흐트러짐·페이즈 전환에 대응 |
| 추가 행동 연결 | 반격·재사용·추가 공격을 별도 스킬처럼 잃어버리지 않기 |

원작에서 파괴 코인의 실제 배열상 선택 순서와 일부 인격의 모션 생략·연결 방식은 이번에 확정하지 않았다. 구현 시 화면상 왼쪽·오른쪽 코인 위치만 보고 추정하지 않는다.

## 10. 광역 공격과 공간 연출

[자료 확인] 현재 공개 스킬에는 일반적인 여러 대상 공격뿐 아니라, 코인마다 대상 중 하나를 골라 공격하는 Unfocused Volley도 존재한다. 해당 설명은 첫 코인이 주 대상을 공격하며, 각 코인의 피해와 적중 효과가 선택된 대상에게 적용된다고 명시한다. [S32]

[구현 해석] 다음 세 개를 따로 둔다.

```
주 대상: 합과 주 카메라의 중심
판정 대상 집합: 이번 코인의 효과를 받을 대상들
연출 범위: 무기 궤적·충격파·배경 효과가 차지하는 화면 영역
```

화면의 폭발이 크다고 주변 캐릭터가 모두 피해를 받는 것은 아니다. 넓은 이펙트와 실제 판정 대상을 일치시킬지, 과장된 원근 효과로 사용할지는 스킬마다 정하되, 대상이 아닌 캐릭터에게 피해 숫자나 피격 동작을 잘못 붙이지 않는다.

지정 대상이 공격 전에 사망하거나 흐트러진 경우의 표적 재배정은 전투 모드·특수 효과에 따라 따로 확인해야 한다. 모든 스킬에 '가장 가까운 생존 적에게 자동 재지정'을 보편 규칙으로 넣지 않는다.

## 11. E.G.O는 컷인 한 장만의 문제가 아니다

[자료 확인] 맹목 이스마엘, 구속 히스클리프, 차원찢개 홍루 등의 공개 리소스에는 각성·침식 애니메이션이 나뉘며, 침식용 Idle·Moving·Clashing·Hurt 같은 기본 전투 자세도 별도로 존재한다. 단순히 일러스트를 한 장 띄운 뒤 원래 인격으로 공격하는 표현만으로 설명할 수 없다. [S33–S35]

[구현 해석] 제작할 때는 다음을 각각 자산 또는 이벤트 묶음으로 취급한다.

1. 발동 전환: 배경 억제, 시선 집중, 대사·사운드 시작.
2. 일러스트 구간: 얼굴·상체·전경·배경 등의 레이어 이동과 표시.
3. 전투 연결: E.G.O 전용 외형 또는 전용 전투 자세.
4. 판정 구간: 각 코인·대상별 공격과 충격.
5. 종료 전환: 잔효과 정리, 다음 유효 외형과 상태로 전환.

이 5단계는 원작의 공통 엔진 구조를 해독한 결과가 아니라, 누락 없이 제작하기 위한 분해 방식이다. 일러스트가 실제 Live2D로 제작됐는지, Spine·Unity Transform 등 다른 방식인지 이번 자료만으로 확정하지 않는다.

침식 상태는 연출이 끝났다는 이유만으로 정상 Idle로 돌리면 안 된다. 외형의 수명은 전투 상태가 결정해야 한다. E.G.O 비용, 정신력, 사용 후 내성·패시브 변화도 단순 이펙트 재생과 별개로 다룬다. [S18, S33]

## 12. 이펙트·카메라·음향을 위한 실무 분해

이 절은 전부 **[구현 해석]**이다. 원작의 셰이더·프리팹·믹서 구조를 확인했다는 뜻이 아니다.

### 12.1 효과는 최소한 역할로 나눈다

| 효과 종류 | 기준 위치 | 켜지는 사건 | 잘못 구현했을 때 |
|---|---|---|---|
| 이동 먼지·잔상 | 발·이동 경로 | 접근·후퇴 | 대기 중에도 발밑이 터짐 |
| 무기 궤적 | 칼날·창끝·도끼날 | 휘두름·찌르기 진행 | 손잡이 중심에서 베기 궤적이 나옴 |
| 합 접촉 | 공방 접촉점 | 합 교환 | 실제 적중처럼 피가 튐 |
| 적중 효과 | 대상의 피격 지점 | 유효 적중 | 회피한 대상에게 피가 튐 |
| 방어 효과 | 방어 도구·접촉면 | 방어 접촉 | 보호막 손실과 HP 피해가 구별 안 됨 |
| 상태 효과 | 대상 또는 UI | 출혈·화상 등 해당 이벤트 | 턴 종료 피해에 공격 모션이 붙음 |
| 잔효과 | 마지막 공격 경로·공간 | 타격 이후 | 다음 동작에도 무기와 함께 따라다님 |
| 화면 효과 | 카메라 | 강한 순간·특수 연출 | 전투 내내 밝아서 충격의 차이가 없어짐 |

### 12.2 실제 접촉 순간을 하나의 기준으로 묶는다

```
ContactEvent
  ├─ 판정 결과 표시
  ├─ 보호막 또는 HP 변화
  ├─ 대상의 반응 자세
  ├─ 적중 위치 이펙트
  ├─ 타격 효과음
  └─ 필요할 때만 짧은 화면 강조
```

입자나 궤적은 이 순간 전후로 길게 이어져도 되지만, 피해 숫자만 먼저 나타나거나 무기가 지나간 뒤 한참 후에 HP가 줄면 타격감과 판정 가독성이 모두 약해진다.

### 12.3 항상 같은 세기로 흔들지 않는다

일반 준비, 합 교환, 실제 적중, 마지막 코인, 흐트러짐, 처치, 전투 결과는 강조의 목적이 다르다. 모든 사건에 같은 흔들림·같은 큰 섬광을 주면 중요한 사건을 읽기 어렵다.

'합에서 코인 하나 파괴'는 공격권 경쟁의 강조이고, '실제 강타'는 육체적 충격의 강조다. 이 둘의 음향과 화면 반응을 다르게 설계한다.

### 12.4 효과음도 공용 하나로 끝내지 않는다

[자료 확인] 남부 세븐협회 4과 파우스트와 히스클리프는 고유 합 효과음을 사용하는 사례로 기록돼 있다. 따라서 원작의 모든 합이 동일한 금속 충돌음이라는 전제로 소리를 묶어서는 안 된다. [S36]

[구현 해석] 소리의 묶음은 출발 / 공방 / 코인 무력화 / 무기 통과 / 실제 적중 / 방어 / 회피 / 흐트러짐 / 사망 / 결과로 나누고, 무기·인격별로 대체 가능하게 한다. 모바일에서도 타격과 판정 안내음이 대사에 묻히지 않도록 우선순위를 둔다.

## 13. 적은 본체 이미지로 옮길 때 필요한 상태 설계

아래는 원작을 분석해 얻은 제작 제안이지 새 스프라이트 생성 지시가 아니다. 기존 확정 아트를 변경하지 않는다.

| 기능 | 별도로 필요한 것 | 이미지 재사용 가능 여부 |
|---|---|---|
| 대기 | Idle 상태와 접지 기준 | 가능 |
| 접근 | Moving 상태와 이동 경로 | 가능 |
| 합의 공방 | 공격 쪽·수세 쪽 표현과 반복 연결 | 확인한 포즈 범위에서 가능 |
| 방어·회피 | 판정이 구분되는 대응 상태 | 같은 그림을 쓸 경우에도 논리는 분리 |
| 순간 피격 | Hurt 반응과 짧은 변위 | 가능 |
| 흐트러짐 유지 | 지속 상태와 회복 시점 | Hurt 그림 재사용 여부는 시각 검수 |
| 코인별 공격 | 준비·접촉·후속 동작의 구분 | 스킬별 필요량만 제작 |
| 사망 | 행동 취소와 시체 상태 | 원작처럼 공용화할지 프로젝트 규칙으로 결정 |
| 승패 결과 | 결과 장면 전환 | 별도 환호 그림을 우선 만들 필요 없음 |

프레임 수를 먼저 고정해놓고 모든 사건을 끼워 넣는 대신, 논리 상태를 먼저 나누고 필요한 경우에만 이미지를 추가하는 방향이 안전하다. 같은 그림을 재사용해도 상태 이벤트, 위치 변화, 이펙트, 표시 시간은 독립적으로 지정할 수 있다.

## 14. 구현·합성 검수 시나리오

| 검수 장면 | 확인할 것 |
|---|---|
| 3코인 대 1코인, 중간 합 승패 반복 | 개별 합 승리를 전투 승리로 처리하지 않는가 |
| 합 무승부 반복 | 피해를 잘못 넣거나 시작점까지 매번 복귀하지 않는가 |
| 합 도중 출혈로 사망 | 공격 타격 없이 발생한 사망도 즉시 행동을 취소하는가 |
| 합 승리 후 1·2·3타 | 코인 판정, 자세, 접촉, 숫자가 타격별로 연결되는가 |
| 회피 연속 성공 후 실패 | 성공한 타격에는 적중 효과가 없고, 실패 시점부터 실제 피해가 있는가 |
| 방어막으로 전부 흡수 / 일부 관통 | 보호막과 HP 반응이 다르게 읽히는가 |
| 반격 준비자가 먼저 흐트러짐·사망 | 잘못된 반격이 이어지지 않는가 |
| 파괴 불가 코인에 합 승리 | 후속 코인 공격과 그 중단 조건을 처리하는가 |
| 마지막 타격으로 흐트러짐 | 순간 Hurt가 끝난 뒤 정상 Idle로 잘못 돌아가지 않는가 |
| 적 처치와 다음 웨이브 | 시체·재배치·다음 행동 예약이 섞이지 않는가 |
| 비치명적 보스 패배 | Dead 대신 적절한 Defeated·스토리 전이를 유지하는가 |
| 특수 사망 기믹 | 일반 시체 표현과 특수 표현을 중복 실행하지 않는가 |
| E.G.O 각성·침식 | 전용 외형의 종료 시점과 논리 상태가 일치하는가 |
| 마지막 적 처치 후 전투 승리 | 마지막 충격과 사망을 결과창이 무조건 잘라먹지 않는가 |
| 전멸이 아닌 조건 실패 | 살아 있는 캐릭터를 일괄 사망시켜 버리지 않는가 |

이 표의 통과는 원작 영상과 픽셀·프레임 단위로 동일하다는 뜻이 아니다. 프로젝트 자체의 판정과 표현이 모순되지 않는지 검사하는 기준이다.

## 15. 아직 확정할 수 없는 항목

1. 특정 인격의 idle → move → gud/miss/dmg → skill 정확한 파일 호출 순서.
2. 개별 합 우세·열세·무승부에 사용되는 포즈의 최신 빌드별 대응표.
3. 행동 종료 후 복귀 위치와 복귀 포즈의 인격·스킬별 차이.
4. 전투 승리·패배 결과창 직전의 공통 포즈가 실제로 존재하는지.
5. 원작의 히트스톱, 카메라 진동, 대시, 잔효과의 정확한 재생 시간.
6. 원본 GIF 팩의 전체 프레임 대조와 특정 컷신의 내부 파츠·제작 도구.

공개 규칙과 리소스 목록만으로 위 항목을 만들어내면, 실제 림버스를 따라 만든 것이 아니라 설명하기 편한 별도 연출을 원작이라고 부르게 된다. 따라서 이 문서는 이 항목들을 명시적으로 미확인으로 남긴다.
