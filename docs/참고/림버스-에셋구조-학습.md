## 1. 캐릭터 전투 스프라이트

### 1.1 장 구성 [직접 확인]

표본: 로쟈 `LCB Sinner`(32장), `Zwei Assoc. South Section 5`(51장).

| 묶음 | 파일 | 장 수 |
|---|---|---|
| 기본 포즈 | `idle` · `move` · `gud`(막기/합) · `miss`(회피) · `dmg`(피격) | **5장 고정** |
| 사망 | 인물 폴더의 `dead` 공용 1장 | 인격별이 아니다 |
| 스킬 | `skill1_1` … `skill3_N` | 스킬당 3~14장. 신규 인격일수록 많다 (LCB S1 3장 → Zwei S1 12장) |
| 이펙트 분리 장 | `skill1_5_e1`, `skill1_5_e2`, `skill3_4_e1_e2` | 몸 프레임 번호에 붙는 별도 장 |

- 기존 조사(`림버스-전투연출-조사.md` §3)의 Idle·Moving·Guard·Evade·Hurt·Dead 분류는 **파일 이름 기준으로 idle·move·gud·miss·dmg + 공용 dead** 로 확정된다
- 합 전용 포즈는 따로 없다. 합은 `gud` 와 스킬 프레임으로 표현한다 [추정]

### 1.2 그림 기법 [직접 확인]

- **몸 프레임에 모션 블러를 그려 넣는다.** 스윙 중간 장(`skill1_5`)은 몸·머리카락 전체가 방향성 블러로 번져 있다. 셰이더 블러가 아니다
- **이펙트는 몸과 다른 장이다.** `_e1` 은 흰 가시형 충격 섬광, `_e2` 는 검은 스윙 궤적에 무기 고유색(금색)을 끝에만 둔다
- 궤적이 빛나는 색이 아니라 **검은 먹선 + 고유색 1점**이다. 우리 톤 규칙(STORY-001 §18: 무채색 + 인물당 고유색 1개)과 같은 방향이다
- 프레임은 **여백 없이 꽉 잘려 있고 장마다 크기가 다르다** (예: idle 303×454, skill1_5 618×463). 기준점은 이미지가 아니라 아틀라스 메타데이터에 있다 [추정]

### 1.3 아틀라스 분할 [직접 확인]

인격 하나의 아틀라스가 `Base_Common`(1024²) · `S1`(1024²) · `S2`(2048²) · `S3`(2048²) 로 **스킬별로 나뉜다**.
기본 포즈만 늘 올리고 스킬 장은 그 스킬을 쓸 때 올리는 구조로 읽힌다 [추정].

### 1.4 우리와 대조

| 항목 | 림버스 | 우리 지금 | 메모 |
|---|---|---|---|
| 기본 포즈 | 5장 + 공용 사망 | 카일 76장 매니페스트, 잔형 최소 11장 | 잔형 M3 최소 세트(대기·돌진·물러남·막기·피격)가 이 5장과 거의 같다 |
| 이펙트 | 몸과 분리된 `_e` 장 | 카일 S1 "효과분리 v3" 15장 | 같은 방향. 이름 규칙만 다르다 |
| 기준점 | 꽉 자른 이미지 + 별도 피벗 [추정] | 고정 캔버스 1700×1000 + 매니페스트 `anchor`·`bbox` | 우리 방식이 검수가 쉽다. 용량은 림버스 쪽이 작다 |
| 로딩 | 스킬별 아틀라스 [추정] | 개별 PNG | D7 첫 로딩 10초를 넘기면 검토할 후보 |

## 2. 전투 이펙트

### 2.1 재질별 타격 반응 [직접 확인]

| 폴더 | 구성 |
|---|---|
| Craters | `crater_{재질}_{S/M/L}` — 재질 6종 × 크기 3종 = 18장. 발밑 바닥 데칼 |
| Particles | `particle_{재질}` 6장. **16~35px짜리 회색조 조각** |
| Fragments | 기계·돌 파편 |
| Floor | `floor_broken` 등 바닥 균열 띠 (2048×162) |

재질 6종: `CORPES`(시체·살) · `DIRT` · `FABRIC` · `METAL` · `ROCK` · `WOOD`.

- **맞는 대상의 재질이 파편 종류를 정하고, 타격 세기가 크레이터 크기(S/M/L)를 정한다** [추정]
- 파편이 아주 작은 회색조 조각 하나라서, 색과 개수·흩어짐은 입자계가 정한다 [추정]. 우리 `외부에셋-라이선스.md` 의 "회색조로 받아 코드가 물들인다"와 같은 원리다

### 2.2 순간 이펙트와 잔흔을 나눈다 [직접 확인]

`StaggeredEffect` + `StaggeredEffect_remain_1`, `MindBlastEffect` + `MindBlastEffect_remain`.
터지는 장과 **그 자리에 남는 장을 따로 만든다.**

### 2.3 그 밖

- `Boundary`: 빨간 "!" 경고 표식 (128²)
- `Burn`: 옷·벽용 **마스크 텍스처**. 불타는 효과를 대상 그림 위에 마스크로 입힌다 [추정]
- 흐트러짐(Stagger)은 노란 폭발 + 금 간 구멍 그림

## 5. Spine 사용 범위 [직접 확인]

- `Text/Prefab` 의 `.prefab` 파일은 대부분 **Spine 4.0.64 뼈대 JSON**이다 (`skeleton.spine: "4.0.64"`, bones·slots)
- 짝인 `.atlas.prefab` 은 Spine 아틀라스(`pma:true`, `scale:0.414`): **크게 그려 0.41배로 줄여 내보낸다**
- 대상: 심장 같은 특수 연출, `ego_battle_*` E.G.O 전투 연출, 보스
- 일반 인격의 전투 동작은 Spine이 아니라 §1의 **프레임 그림 교체**다

우리 결행(미명) 컷신을 뼈대 애니메이션으로 만들 필요는 없다는 근거로 쓸 수 있다. 원작도 일반 전투는 장 교체다.

## 6. 데이터 구조 [직접 확인]

### 6.1 스킬 효과 문구 (`KR_Skills_personality-*.json`)

```
{ id, levelList: [ { level, name, desc, coinlist: [ { coindescs: [ { desc } ] } ] } ] }
```

- 스킬 하나 = 동기화 단계별(`level`) 묶음. 단계마다 **코인별** 효과 문구 목록이 있다
- 문구는 **발동 시점 태그로 시작한다**. 표본 55개 스킬에서 센 횟수: `[OnSucceedAttack]` 296 · `[WhenUse]` 168 · `[StartBattle]` 15 · `[WinDuel]` 12 · `[EndSkill]` 8 · `[ReUseOnSucceedAttack]` 12
- 효과가 "언제 발동하는가"를 먼저 정하고 내용을 붙이는 구조다. 도메인이 이벤트를 내보내는 우리 구조(합 승리 → 효과)와 그대로 대응한다

### 6.2 일러스트 기준점 (`illust-pivots-unitinfo`)

```
{ "id": "10101_normal", "offsetX": 132.0, "offsetY": -3.0, "scaleFactor": 1.25, "rotateZ": 0.0 }
```

인격·동기화 단계(`normal` / `gacksung`)마다 화면 배치값을 JSON으로 따로 둔다. 그림을 고치지 않고 데이터로 맞춘다. 우리 "수치는 JSON" 규칙과 같다.

### 6.3 전투 도움말 문구 (`KR_BattleHint.json`)

한 줄에 규칙 하나다. 예: "모든 스킬은 1개 이상의 코인을 가지고 있습니다." / "코인은 앞면과 뒷면에 따라 위력이 감소하거나 증가합니다."
M4에서 도움말을 8항목에서 5항목으로 줄인 방향(QA-007)과 같다.
