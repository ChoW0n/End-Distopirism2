## 1. 계층 배치

```
도메인 (BattleEvent[])
   ↓
UiDirector (src/ui/director.ts)   ← 신규. 상태를 필드 하나로만 든다
   ↓ UiCommand[]
렌더러 (미구현)
```

`BattlePresenter`(캐릭터·이펙트)와 `CameraDirector`(카메라)와 **같은 자리**에 하나 더 놓는다.
셋 다 같은 `BattleEvent[]` 를 각자 본다. UI 가 프리젠터를 통해 전투를 읽지 않는다.

**원작은 `BattleManager` 1,232줄이 상태·연출·UI·입력을 전부 들고 있었다.** 그게 재설계가
실패한 이유라 이번엔 UI 를 독립 구독자로 둔다.

## 2. 프로필 패널 · 체력바 · 정신력바

### 2.1 원작 동작 (승계)

- 캐릭터마다 체력바 1개 + 정신력바 1개를 **월드 좌표**에 띄운다. 화면 고정 HUD 가 아니다
- 채움 비율: 체력 `hp / maxHp`, 정신력 `정신력 / 100`
- 값이 바뀌면 0.5초 `OutQuad` 로 보간한다. 즉시 스냅하지 않는다
- 체력바 색은 빨강↔초록 사이를 체력 비율로 섞는다
- 아군과 적은 같은 바 프리팹을 쓰고 텍스트 슬롯만 다르다
- 겹침 순서: 체력바가 정신력바보다 위 (원작 `sortingOrder` 3 vs 1)

### 2.2 버리는 것

- **월드 캔버스·프리팹 인스턴스화 구조 전체.** 유니티 `Canvas.renderMode = WorldSpace` 에
  묶여 있어 웹으로 그대로 안 옮겨진다. 위치는 SPEC-002 앵커로 다시 잡는다
- **캐릭터 스케일이 1 넘을 때까지 기다렸다가 바를 만드는 코루틴**
  (`WaitForScaleAndCreateBars`). 스프라이트 배율이 정규화된 지금은 필요 없다

### 2.3 정신력 수치는 원작을 따르지 않는다 — 중요

| 시점 | 원작 코드 | **확정 스펙** |
|---|---|---|
| 합 승리 | 정신력 +5 | **+2** (`mentalityOnClashWin`) |
| 합 패배 | 정신력 -10 | **변화 없음** |
| 교착 3회 | — | **-10** (`mentalityOnDeadlock`) |

원작 `BattleManager.cs:775~786` 이 합 승리 +5 / 합 패배 -10 으로 되어 있다.
**확정본은 SPEC-001 §4.4·§4.5 와 `battle-data.json` 이고, 원작 숫자를 되살리지 않는다.**
UI 는 도메인이 낸 값을 표시만 한다. 증감 계산을 UI 가 하지 않는다.

## 3. 곡선 타겟 화살표

### 3.1 원작 동작 (승계)

2차 베지어 곡선 하나. `P(t) = (1-t)²·시작 + 2(1-t)t·제어 + t²·끝`

| 항목 | 원작 값 | 승계 여부 |
|---|---|---|
| 제어점 | (시작+끝)/2 + 위쪽 `curveHeight` | 방식 승계, 값은 §7 |
| `curveHeight` | 300 | 유니티 단위. 다시 잡는다 |
| 분할 수 | 50 | 승계 |
| 그려지는 시간 | 0.5초. `t` 에 비례해 점 개수를 늘린다 | 승계 |
| 화살촉 | 길이 40, 벌어지는 각 20° | 방식 승계, 값은 §7 |
| 색 | `(1, 0.8, 0.2)` → `(1, 0.4, 0)` 그라데이션 | 승계 |
| 겹침 순서 | 스킬 카드보다 **아래** | 승계 |

시작점은 **선택된 스킬 카드의 중심**이고, 카드가 없으면 캐릭터 기준 오프셋으로 떨어진다.
끝점은 대상 기준 오프셋이다.

### 3.2 고칠 것

- 원작은 화살표를 `LineRenderer` 게임오브젝트로 만들고 코루틴·리스트 3개
  (`lineRenderers` / `connections` / `activeCoroutines`)를 **인덱스로 맞춰** 들고 있다.
  `RemoveConnection` 이 세 리스트를 각각 지워서 인덱스가 어긋날 수 있다.
  → 연결 하나를 **객체 하나**로 들고, 진행도는 `t` 값 하나로만 둔다
- 오프셋 `up 250` / `right 70` / `left 70` 은 유니티 월드 단위와 UI 좌표가 섞인 값이다.
  2400×1500 정규화 캔버스 기준으로 다시 잡는다 (§7)

## 4. 합 승리/패배 배지

### 4.1 원작 동작 (승계)

- 합이 끝나면 **양쪽에 동시에** 뜬다. 이긴 쪽에 승리, 진 쪽에 패배
- 캐릭터의 `ResultPosition` 지점에 생성
- **항상 카메라를 바라본다** (빌보드). 매 프레임 회전을 카메라와 맞춘다
- 1초 동안 위로 떠오르면서 알파 1 → 0, 끝나면 제거

2.5D 라서 빌보드가 필요하다. 배지가 바닥·벽과 같이 기울면 안 읽힌다.

### 4.2 동점 주의

원작은 합 판정이 `>` / `else` 2분기라 **동점이 적 승리로 표시됐다** (CLAUDE.md 함정표).
확정 스펙은 승/패/교착 3분기다. 배지도 3종이 필요하고, 교착은 승리도 패배도 아니다.
→ **교착 배지 디자인이 없다** (§7)

## 5. 중앙 대시 이동

### 5.1 원작 동작

매칭된 한 쌍이 전투 구역(`battleZone`) 안의 한 지점으로 같이 달려가 거기서 합을 벌인다.

| 항목 | 원작 |
|---|---|
| 아군 목표 | 구역 안 무작위 (X, Z) |
| 적 목표 | 아군 목표 + X `150~250` 무작위, Z `-100~+100` 무작위 |
| 겹침 방지 | 이미 쓴 자리와 `safeDistance` 미만이면 다시 뽑는다 |
| 재시도 | 최대 30회. 넘으면 마지막 값을 그냥 쓴다 |
| 이동 | `MoveTowards` 등속. 도착하면 `Attack` 애니메이션 종료 |

### 5.2 고칠 것

- **무작위에 시드가 없다.** 확정본의 도메인은 주입된 `Rng` 로 같은 시드면 같은 전투가 나온다.
  배치도 같은 `Rng` 를 받아야 재현이 된다. `Math.random()` 을 쓰지 않는다
- 30회 실패 시 **겹친 자리를 그냥 쓴다.** 경고만 찍고 넘어가서 캐릭터가 겹쳐 보인다.
  → 실패하면 구역을 격자로 나눠 빈 칸에 배치하는 확정적 대체 경로를 둔다
- D-7 로 교전이 한 턴에 여러 건 생긴다. 합·일방 공격이 섞이므로 **일방 공격은 한쪽만 달려간다**

### 5.3 대기 부유 동작 — 그대로 옮기면 안 된다

원작 `CharacterMovement.Update()`:

```csharp
position.y += Mathf.Sin(Time.time * moveSpeed) * moveAmount;
```

현재 위치에 사인 값을 **누적 대입**한다. 기준 높이에서 오르내리는 게 아니라 매 프레임
더해지므로 프레임 간격이 고르지 않으면 캐릭터가 위아래로 떠내려간다.
원작 카메라 버그(매 프레임 `transform` 덮어쓰기)와 같은 종류다.

→ **기준 높이를 따로 들고 `기준 + sin(경과시간)·진폭` 으로 대입한다.** `+=` 를 쓰지 않는다.

## 6. UI 명령 **[2026-09-21 구현본]**

```ts
type UiCommand =
  | { type: 'bar'; combatantId; kind: 'hp' | 'mentality'; ratio;
      origin: Point; size: { width, height }; tweenSec; easing }
  | { type: 'targetArrow'; sourceId; targetId; curve: Point[];
      head: [Point, Point, Point]; drawSec; colorStart; colorEnd }
  | { type: 'clearArrows' }
  | { type: 'clashBadge'; combatantId; result: 'win' | 'lose' | 'deadlock';
      from: Point; to: Point; durationSec; text: string | null }
  | { type: 'dashTo'; combatantId; position: Point; speed }
  | { type: 'dashBack'; combatantId }
  | { type: 'float'; combatantId; base: Point; amplitude; periodSec }
```

초안에서 늘어난 것과 이유:

- **좌표·크기를 명령이 들고 있다.** U-1 대로 전부 무대 좌표다. 렌더러가 앵커를 다시 풀면
  계산이 두 군데가 되고, 그게 원본 카메라 버그와 같은 구조다
- **`float` 이 새로 생겼다.** 기준 높이 `base` 를 같이 줘서 렌더러가 `base + sin(t)·amplitude`
  로만 그리게 한다. 원본처럼 `+=` 로 누적할 자리를 아예 없앤 것이다 (§5.3)
- **`head` 는 화살촉 세 점**이다. `curve` 와 같은 이유로 여기서 계산해서 넘긴다
- **`text` 는 교착 카운터**다. 스프라이트가 나오기 전까지 이걸로 그린다 (U-4)

### 6.1 입력은 이벤트가 아니다

적의 타겟은 `enemyTargeted` 이벤트로 오지만 **아군의 선택은 도메인 이벤트가 아니다.**
플레이어 입력이라 `UiDirector.selectTarget(sourceId, targetId)` 로 따로 받는다.
이걸 도메인 이벤트로 만들지 않는다 — 선택은 아직 전투에 반영되지 않은 상태고,
도메인이 입력 단계를 알 필요가 없다.

### 6.2 체력·정신력을 UI 가 따라 센다

`damageApplied` 는 남은 체력을 주지만 `statusTicked` 는 깎인 양만 준다. `mentalityChanged`
역시 바뀔 때만 온다. 그래서 `UiDirector` 가 두 값을 따라 센다.

- 시작값은 캐릭터 데이터(`maxHp`, `mentality`)에서 가져온다. 임의값을 쓰지 않는다
- `damageApplied` 는 확정값이라 받을 때마다 어긋난 값이 맞춰진다
- 턴 시작마다 두 바를 한 번씩 다시 낸다. 놓친 변화가 있어도 여기서 맞는다

**이걸 없애려면 도메인 이벤트를 늘려야 한다.** SPEC-001 v2.0 §4 가 이벤트 추가를 셋으로
못 박았으므로 지금은 UI 쪽에서 감당한다. 나중에 필요하면 그때 스펙을 먼저 고친다.

`curve` 는 이미 계산된 점 목록이다. 베지어 계산은 UI 계층 안에서 끝내고 렌더러에 곡선 공식을
넘기지 않는다. 렌더러 교체 시 곡선 모양이 달라지면 안 되기 때문이다.

수치(분할 수, 그려지는 시간, 곡선 높이, 화살촉 크기, 부유 진폭·주기)는 **코드에 박지 않고**
`assets/ui/ui-data.json` 에서 읽는다 (§7 U-6).

## 7. 확정 항목 **[2026-09-21]**

| # | 결정 |
|---|---|
| U-1 | UI 명령은 **무대(월드) 좌표**로만 낸다. 화면 픽셀 변환은 렌더러가 마지막에 한 번 |
| U-2 | 새 앵커를 만들지 않는다. `bbox` 상단 + `anchor` + 캐릭터 키 `H` 로 푼다 (SPEC-002 §5.1) |
| U-3 | 카드 UI 가 생길 때까지 시작점은 **시전자의 `headCenter`**. 데이터 한 줄로 교체 가능하게 둔다 |
| U-4 | 배지는 **3종**. 교착 배지에 누적 횟수 `n/3` 을 같이 띄운다 |
| U-5 | 원작 UI 에셋을 **재사용**한다. 신규 제작은 교착 배지 하나뿐 |
| U-6 | `assets/ui/ui-data.json` 을 **새로 만든다.** `battle-data.json` 에 섞지 않는다 |
| U-7 | 구역을 픽셀이 아니라 **캐릭터 키 `H` 배수**로 준다. 뷰포트 크기와 무관해진다 |

### 7.1 U-1 · UI 좌표계

`UiCommand` 의 모든 좌표는 `stage.ts` 가 쓰는 무대 좌표다. 화살표 곡선의 점 목록도 무대 좌표다.

**화면 픽셀이 `UiDirector` 안으로 들어오면 안 된다.** 들어오는 순간 UI 가 해상도·카메라 줌에
묶이고, 유니티 재전환 때 이 계층을 통째로 버려야 한다 (CLAUDE.md 아키텍처 규칙).
2.5D 카메라 배치(SPEC-003 §8)가 나중에 정해져도 UI 코드는 한 줄도 안 바뀐다 — 그게 이 결정의 이유다.

### 7.2 U-2 · 바·배지가 붙는 자리

매니페스트에 이미 `headCenter` · `anchor` · `bbox` 가 있다. 새 필드도 새 앵커도 추가하지 않는다.

```
바 바닥 y = bbox 상단 y − H × bar.topMargin
바 폭     = H × bar.width
배지 위치 = 바보다 한 단 위
```

`H` 는 **정지 프레임(`00-idle`) 기준 캐릭터 키**다. 프레임마다 다시 재지 않는다 — 공격
프레임은 키가 0.75~1.00 배로 흔들려서(SPEC-002 §3.1) 매 프레임 재면 바가 캐릭터 따라 출렁인다.

### 7.3 U-3 · 화살표 시작점

`arrow.start` 값으로 고른다. 지금은 `"headCenter"`, 카드 UI 가 들어오면 `"selectedCard"` 로 바꾼다.
**카드 UI 를 기다리느라 화살표를 미루지 않는다.** 시작점 하나 빼면 나머지(곡선·화살촉·색·시간)는
카드와 무관하다.

### 7.4 U-4 · 교착 배지

승리/패배 2종으로는 **교착이 몇 번 쌓였는지 플레이어가 못 본다.** 3회면 합이 끝나고 정신력이
깎이는데(SPEC-001 §4.5) 그 카운터가 화면에 없으면 갑자기 합이 끝난 걸로 보인다.

→ 배지 3종. 교착 배지에는 `교착 n/3` 을 같이 띄운다. 스프라이트가 나오기 전까지는 **텍스트로**
그린다. 승/패 배지를 색만 바꿔 돌려쓰지 않는다 — 교착은 승리도 패배도 아니다.

### 7.5 U-5 · 배지·바 스프라이트

원작 리포에 쓸 만한 게 이미 있고 톤도 소각원과 충돌하지 않는다. **새로 발주하지 않는다.**

| 쓰는 것 | 원작 경로 |
|---|---|
| 합 승리/패배 팔각 배지 | `Resources/Art/UI/Icon/합 승리.png` (570×446), `합 패배.png` |
| 체력·정신력 바 | `Resources/Art/UI/UI_전투 정보_01.png` (644×156), `_02` |
| 코인 | `Coin_01.png`, `Coin_02.png` |
| 턴 표시 | `Turn.png` |

**신규는 교착 배지 하나.** 발주 시 팔각 배지와 같은 실루엣·같은 크기, 색만 회색 계열.
카드 스프라이트는 톤 기준점에서 제외라(CLAUDE.md) 여기 섞지 않는다.

이미지는 **git 에 커밋하지 않는다** (SPEC-002 §9). 좌표·수치만 리포에 들어온다.

### 7.6 U-6 · 수치 데이터 파일

`assets/ui/ui-data.json` 을 새로 만든다.

`battle-data.json` 은 **도메인이 읽는 파일**이다. 거기에 곡선 높이·부유 진폭을 넣으면 도메인이
연출 수치를 들고 있게 되고 아키텍처 규칙이 깨진다. 파일을 나누는 게 규칙을 지키는 가장 싼 방법이다.

### 7.7 U-7 · 대시 구역

**유니티 콜라이더 단위를 옮기지 않는다.** 씬에 놓인 값이라 웹에 대응물이 없고, 옮겨도 뷰포트가
바뀌면 다시 틀린다. 전부 **캐릭터 키 `H` 배수**로 준다.

| 항목 | 값 (H 배수) | 근거 |
|---|---|---|
| 구역 폭 | 3.2 | 한 쌍이 붙어도 양옆에 여백이 남는 최소 폭 |
| 구역 깊이 | 0.2 | **v1.x 0.9 → 0.2 (2026-09-25).** 0.9 였을 때 교전마다 캐릭터 크기가 뒷줄 대비 1.08~2.1 배로 제각각이었다 (원근 계산 실측) |
| 최종 간격 | 0.85 | 겹치지 않고 닿아 보이는 거리. 0.55(도끼 기준)는 창을 든 조력자가 앞발을 벌리면 몸이 겹쳤다 (2026-09-24) |
| 좌우 흔들림 | 0.06 ~ 0.16 | 매 합 같은 자리에 서지 않게 |
| 깊이 흔들림 | ±0.02 | ±0.12 였을 때 한 쌍 안에서 크기가 최대 7% 달랐다. 둘이 같은 크기로 보여야 한다 |
| 겹침 방지 거리 | 0.45 | 실루엣이 안 겹치는 최소 |
| 재시도 | 30회 | 원작 그대로 |
| 이동 속도 | 초당 2.4 | 합 시작까지 0.6초 안쪽 |

중심의 **가로(x)는 교전 쌍의 중점**이다. 무대 중앙에 고정하지 않는다 — D-7 로 한 턴에 교전이 여러 건
생기므로 고정하면 전부 한 자리에 겹친다.

중심의 **깊이(y)는 대형 전체의 중심 줄 + `forward`** 로 고정한다 (2026-09-25). 쌍의 중점을 쓰면 뒷줄끼리 붙은
교전은 뒤에서, 앞줄끼리 붙은 교전은 앞에서 벌어져 **교전마다 캐릭터가 커졌다 작아졌다** 했다.
원근(2.5D)은 그대로다 — 제자리 ↔ 전투 줄을 오갈 때 커지고 작아지는 건 남는다. 교전끼리의 들쭉날쭉만 없앤다.

**일방 공격은 예외다.** 맞는 쪽은 제자리이므로 공격자가 **맞는 쪽 옆, 같은 깊이**에
최종 간격만큼 떨어져 선다. 둘의 중점으로 달리면 허공을 베고, 명중 이펙트는 멀리 선 맞는 쪽에 뜬다
(실제로 그랬다, 2026-09-24).

재시도 30회를 넘겨도 **원작처럼 겹친 자리를 쓰지 않는다.** 구역을 격자로 나눠 빈 칸에 넣는다.
무작위는 주입된 `Rng` 만 쓴다 (§5.2). `Math.random()` 금지.

> 위 값은 **측정 전 시작값**이다. 붙여 보고 어색하면 `ui-data.json` 만 고친다. 코드는 안 고친다.

## 8. `assets/ui/ui-data.json`

단위는 전부 **캐릭터 키 `H` 배수**, 시간은 초다. 픽셀 값은 이 파일에 없다.

| 절 | 담는 것 | 대응 |
|---|---|---|
| `dash` | 구역 크기 · 간격 · 흔들림 · 속도 | §7.7 |
| `float` | 대기 부유 진폭 · 주기 | §5.3 |
| `arrow` | 시작점 · 곡선 높이 · 분할 · 색 · 화살촉 | §3 |
| `bar` | 폭 · 높이 · 머리 위 여백 · 보간 시간 | §2 |
| `badge` | 떠오르는 높이 · 시간 · 교착 최대치 | §4 |

읽기 실패·키 누락은 **기본값으로 때우지 않고 던진다.** 수치가 빠진 채 그려지면 어디가 틀렸는지
화면만 보고는 못 찾는다. 매니페스트 로더(SPEC-003 §3)와 같은 방침이다.

## 9. 이벤트 순서 — `used` 가 `cutscene` 보다 먼저 나오는 것 **[2026-09-21 확정]**

**고치지 않는다.** 도메인이 이벤트 순서의 유일한 출처고, 프리젠터도 UI 도 재배열하지 않는다.
연출상 "카드가 먼저 사라져 보이는" 문제는 **렌더러가 `cutscene` 을 타임라인 장벽으로 다뤄서**
흡수한다 (SPEC-003 §5.3). 순서를 보장하는 건 프리젠터, 시간을 가지는 건 렌더러다.
