## 1. 한 턴

```
① 선언   적이 각자 대상·카드·위력을 선언한다. 화면에 전부 보인다
② 대형   아군이 전열·후열을 옮긴다 (대가: 정신력)
③ 지시   아군마다 카드 1장 + 대상 1개
④ 태우기 아군마다 정신력을 태워 위력을 올린다 (대가)
⑤ 해결   교란 → 막기·맞부딪힘 → 남은 공격 (아군 먼저, 적 나중)
⑥ 마감   정신력 회복, 궁극기 판정, 상태 만료
```

- **주사위·확률이 없다.** 같은 선택이면 같은 결과다. 무작위는 적 AI 가 무엇을 선언할지 고를 때만 쓴다(시드 고정)
- 적의 선언은 ①에서 확정되고 바뀌지 않는다. 아군 교란으로만 바뀐다

## 2. 대형 — 전열과 후열

한 편은 **전열 2칸 · 후열 2칸**, 최대 3명이다.

| | 전열 | 후열 |
|---|---|---|
| 근접 카드 사용 | 가능 | **불가** |
| 원거리 카드 사용 | 가능 | 가능 |
| 근접 공격에 맞는가 | 맞는다 | **전열에 누가 서 있으면 안 맞는다** |
| 막아서기 | **자기와 동료 전원**을 막을 수 있다 | 자기에게 오는 공격만 |

### 2.1 이동과 대가

- ②단계에서 아군 누구든 한 번 열을 옮길 수 있다. **정신력 10**을 낸다 (제안값)
- 전열이 가득 차 있으면 전열의 한 명과 **맞바꾼다.** 밀려난 쪽은 대가를 내지 않는다
- **앞으로 나온 캐릭터는 다음 턴 ②단계에 뒤로 못 빠진다** (한 턴 묶임). 이게 "당겨 나와 손해를 보는" 대가다

### 2.2 근접 공격이 대상을 잃으면

적의 근접 공격 대상이 ②단계에서 후열로 빠졌고 전열에 누가 서 있으면, 그 공격은 **전열 첫 칸**에게 간다.
그래서 두 가지 수가 생긴다.

- **에이스 빼기** — 노려진 에이스를 뒤로 빼고 전열의 튼튼한 동료가 대신 맞는다
- **대신 서기** — 후열의 동료를 앞으로 당겨 에이스를 막아선다. 정신력 10과 한 턴 묶임이 대가다 (사용자 요청 전략)

원거리 공격은 열과 상관없이 대상에게 간다. 막아서기로만 막는다.

### 2.3 포메이션과 역할 칸 **[2026-09-27 사용자 요청]**

> "대형은 추후 여러 개 해서 축구 포메이션처럼, 그 포메이션에서 정해진 역할이 들어가게.
> 해당 역할이 아닌 캐릭터가 서 있으면 능력치 패널티를 받게."

대형은 코드가 아니라 **데이터**다. 포메이션 하나 = 칸 목록이고, 칸마다 **열**과 **역할**이 붙는다.

```
formation "2-2 기본"
  전열  [방패] [돌격]
  후열  [사수] [지원]
```

| 역할 (제안) | 맡는 일 | 적성 예 |
|---|---|---|
| 방패 | 막아서기 | 조력자 |
| 돌격 | 근접 공격 | 소각원 · 지하 경찰 |
| 사수 | 원거리 공격 | 메인 |
| 지원 | 교란 | 메인 · 조력자 |

- 캐릭터마다 **적성 역할**(1~2개)이 데이터에 있다
- **적성이 아닌 칸에 서면 벌칙.** 제안: 그 칸 역할의 카드 위력 -3, 받는 피해 +20%. 수치는 포메이션 데이터가 들고 있어 포메이션마다 다르게 줄 수 있다
- 적성 칸에 서면 보너스는 첫 판에 두지 않는다 (벌칙만. 읽기 쉽게)
- §2.1 의 "당겨 나와 손해를 보는" 수가 여기서 커진다: 후열 사수를 전열 방패 칸으로 당기면 정신력 10 + 한 턴 묶임 + **적성 벌칙**을 함께 떠안는다
- **첫 판은 포메이션 1개**("2-2 기본")만 넣는다. 구조는 여러 포메이션(3-1, 1-3, 중열이 있는 1-2-1 등)과 전투 전 포메이션 선택을 받을 수 있게 짠다. 열 수도 데이터로 둔다 (지금은 2열)
- 적도 포메이션을 가진다

## 3. 카드 — 역할 3종

캐릭터마다 3장. 수치와 효과는 캐릭터마다 다르다.

| 역할 | 대상 | 하는 일 | 속성 |
|---|---|---|---|
| **공격** | 적 1명 | 위력만큼 피해 | 공격 |
| **막아서기** | 적의 **선언 하나** | 그 공격을 가로막는다. 위력 비교 (§4) | 방어 |
| **교란** | 적의 **선언 하나** | 선언을 바꾼다: 위력 깎기 · 대상 돌리기 · 밀기/당기기 (카드마다 하나) | 보조 |

- 카드에는 **사거리**(근접/원거리)가 붙는다. 후열에서는 원거리 카드만 쓴다
- 위력은 고정값이다. ④단계에서 올릴 수 있다
- 속성 3종 누적 → 궁극기는 v2.0 에서 이어받는다 (§6)

## 4. 해결

### 4.1 순서

1. **교란** — 아군 교란을 지시 순서대로 적용한다. 적 선언이 바뀐다
2. **막기** — 막아서기가 붙은 적 공격마다 위력을 비교한다
3. **맞부딪힘** — 아군 공격의 대상 적이 **그 아군을** 노리는 공격을 선언했으면 둘이 맞부딪힌다
4. **나머지 공격** — 아군 공격 → 적 공격 순서로 그대로 들어간다

앞에서 쓰러진 캐릭터의 행동은 건너뛴다.

### 4.2 위력 비교

| 상황 | 결과 |
|---|---|
| 막는 쪽 위력 > 공격 위력 | 막는다. 공격자에게 **차이만큼 반격 피해** |
| 막는 쪽 위력 < 공격 위력 | 뚫린다. **막는 쪽이 차이만큼** 맞는다 (원래 대상은 무사) |
| 같다 | **교착.** 둘 다 튕겨 나고 피해 없음. 둘 다 정신력 -5 |
| 맞부딪힘에서 한쪽이 크다 | 이긴 쪽 공격만 들어간다 (자기 위력 그대로). 진 쪽 공격은 사라진다 |
| 맞부딪힘에서 같다 | 교착 |

### 4.3 정신력 — 태우기와 폭주

- 모두 정신력 100 으로 시작, 상한 100
- **태우기:** 10 을 태울 때마다 그 카드 위력 +2 (제안값). 몇 번이든 되지만 0 아래로는 못 간다
- 회복: 턴 마감 +10, 막기·맞부딪힘에서 이기면 +5
- 잃는 곳: 태우기, 열 이동, 교착(-5), 막기가 뚫림(-5)
- **폭주:** 턴 마감에 정신력이 0 이면 다음 턴 그 캐릭터는 지시를 받지 않는다. 자기 공격 카드를 가장 가까운 적에게 쓰고, 막아서기·이동을 못 한다. 폭주가 끝나면 정신력 30 으로 돌아온다
- 적도 정신력을 가진다. **적은 태우지 않는다** (선언된 위력이 곧 최종 위력이라 읽을 수 있어야 한다). 교착·패배로 깎이고, 0 이면 폭주해 선언이 바뀐다 → 적의 정신력을 깎는 것도 수가 된다

## 5. 적

- 적도 같은 카드 3장 구조를 쓴다. AI 는 ①단계에 대상과 카드를 고른다 (가중 무작위, 시드 고정)
- **적은 막아서기·교란을 선언하지 않는다** (첫 판). 공격만 선언해 읽기 쉽게 한다. 막는 적은 뒤 단계에서
- 적 AI 가중치: 빈사인 아군, 전열 아군, 이미 노려진 아군 감점 (v1.0 §13.6 의 뼈대를 이어받는다)

## 6. 속성과 궁극기 (v2.0 이어받음)

- 카드 역할 = 속성. 공격 카드가 피해를 넣으면 공격 +1, 막기에 성공하면 방어 +1, 교란이 적용되면 보조 +1
- 합이 `ultimateThreshold`(제안 **5**) 이상이면 다음 턴 궁극기 카드가 손에 들어온다. 쓰면 속성이 0 이 된다
- 궁극기: 원거리 · 위력 높음 · 막아서기에 막혀도 **절반은 뚫는다** (제안)
- 목표: 한 판에 한 번은 나온다 (§8)

## 7. 캐릭터 카드 — 제안값

수치는 시뮬레이터로 확정한다 (§8). 이름은 기획이 정한다(당분간 "역할 · 캐릭터").

| 캐릭터 | 체력 | 적성 (§2.3) | 공격 | 막아서기 | 교란 |
|---|---|---|---|---|---|
| 조력자 (창) | 140 | 방패 · 지원 | 근접 8 | 근접 11 · 이기면 반격 | 근접 · 걸어 넘기기: 대상 적 위력 -4, 전열이면 **후열로 밀어낸다** |
| 소각원 (도끼) | 126 | 돌격 | 근접 12 | 근접 7 | 근접 · 불붙이기: 대상 적 위력 -3, 다음 턴도 -3 |
| 메인 (권총) | 112 | 사수 · 지원 | 원거리 8 | 원거리 6 | 원거리 · 견제 사격: 대상 선언을 **나에게 돌린다** |
| 지하 경찰 (검) | 80 | 돌격 (에이스) | 근접 14 | 근접 6 | 원거리 · 연행: 후열의 적을 **전열로 당긴다** |

- 에이스(경찰)는 세지만 약하다. 전열에서 노려지면 누군가 대신 서야 한다 → §2.2 의 수
- 밀기·당기기로 **적 대형**을 흔든다. 후열의 원거리 적을 당겨 근접으로 친다

## 9. 연출·에셋

### 9.1 공용 자세 8장 — 기술별 전용 장면을 버린다

모든 캐릭터가 같은 자세 칸을 쓴다 (SPEC-006 A 등급과 같다).

`대기 · 이동 · 막기 · 피격 · 공격 준비 · 공격 · 특수 준비 · 특수`

- 카드는 **동작 대본**(데이터)으로 자세를 고른다. 공격 카드 = 공격 준비 → 공격, 막아서기 = 막기, 교란 = 특수 준비 → 특수, 궁극기 = 특수 + 컷신
- 기존 조력자·소각원 12장은 **대응표**로 8칸에 물린다 (예: 공격 = S1 장, 특수 = S2 장). 그림은 다시 만들지 않는다
- 이펙트는 SPEC-006 §4: 공용 키트를 속성 색으로 물들이고, 캐릭터마다 무기 궤적 1종

### 9.2 박자 틀 — 교전 하나는 정해진 틀로

| 교전 | 틀 |
|---|---|
| 공격 | 다가감 → 준비 → 한 방 → 결과 숫자 → 복귀 |
| 막기 | 공격자 다가감 · 막는 쪽이 대상 앞으로 끼어듦 → 부딪힘 → 결과 → 복귀 |
| 맞부딪힘 | 둘 다 다가감 → 부딪힘 → 이긴 쪽 한 방 → 복귀 |
| 교란 | 시전 → 대상 적 선언 표지가 바뀌는 연출 |
| 이동 | 열 사이를 걸어 옮김 |

- 도메인은 결과 이벤트만 낸다. 어댑터가 이벤트를 **틀 목록**으로 바꾸고, 렌더러는 틀을 재생한다
- 박자 길이는 `ui-data.json`. 교전 하나 약 2~3초가 목표

### 9.3 이미지 생성 — gpt astra **[2026-09-27]**

생성 담당이 스스로 밝힌 능력·한계(`docs/참고/gpt-astra-이미지제작-능력.md`)에서 나온 규칙이다.

| 담당이 밝힌 한계 | 이 리포가 정하는 것 |
|---|---|
| 여러 장 사이 얼굴·무기·비율이 누적해서 바뀐다 | **승인한 대표 포즈 1장**을 모든 요청의 참조로 고정한다. 한 번에 한 자세씩 요청한다 |
| 시트는 칸·개수·피벗·간격을 보장하지 못한다 | **시트로 받지 않는다.** 자세 1장 = 파일 1개 (SPEC-006 §6 의 시트 방식은 폐기) |
| 연속 프레임의 흐름·접지·궤적은 재생으로만 검증된다 | 자세는 **정지 키 포즈 8장**뿐이다. 사이 움직임은 코드 몸짓(내딛기·반동·잔상)이 맡는다 |
| 이펙트 연속 프레임은 미검증 | 이펙트는 **공용 키트를 코드로** 만든다 (SPEC-006 §4). 무기 궤적도 정지 1장 + 코드 재생(쓸기·늘이기·사라짐) |
| 투명 요청이 알파 품질을 보장하지 않는다 | 반입 도구가 알파를 검사한다: 알파 채널 존재 · 배경 알파 0 · 밝은/어두운 배경 합성 캡처 |
| 피벗을 자동으로 잡으면 칼끝·옷자락을 발로 오인한다 | 접지점·무기 끝은 **사람이 확정**하고 매니페스트에 "수동 확정"으로 남긴다 (지금 방식 유지) |
| 좌우 반전은 주손·장착 위치까지 뒤집는다 | 지금은 적 쪽을 반전해서 쓴다. **비대칭이 두드러지는 캐릭터만** 반대 방향 대표 포즈를 따로 요청한다 |
| 수정 요청이 범위 밖 픽셀도 바꾼다 | 수정본은 원본과 **픽셀 비교**해 범위 밖 변화를 기록한다 |

**요청 방식 [2026-09-27 사용자 지시]**: 요청서에는 **용도와 목적만** 적는다. 특정 자세·동작 각도·구도·방향을 강요하지 않고 담당에게 맡긴다. 요청서가 정하는 건 설정(STORY-001 의 인물 외형·장비)과 게임 쪽 기술 조건(크기·알파·바라보는 쪽·반전 금지)뿐이다. 담당은 고른 이유를 납품 때 적는다.

**요청 순서** (담당 문서 §11 을 그대로 따른다)
1. 대표 포즈(대기) 1장 → 사용자 승인
2. 가장 어려운 자세(공격 — 무기 쥔 손) 1장 → 구조 검수
3. 나머지 자세를 한 장씩
4. 반입 → 실제 게임에서 교전 틀로 재생 → 사용자 승인
5. 같은 오류가 두 번 교정 후에도 남으면 방법을 바꾼다 (국소 수정·사람 수정)

**인수인계**: 요청마다 담당 문서 §15 양식(YAML)을 `assets/requests/<캐릭터>/<자세>.yaml` 로 남긴다. 승인·검수 상태는 이 파일에만 적는다.
이미지는 커밋하지 않는다 (SPEC-002 §9). 요청서와 검수 기록만 커밋한다.

### 9.4 화면 틀 — UI 는 게임 화면 안에만 **[2026-09-27 사용자 지시]**

> "최대한 1920×1080 해상도, 아이폰15의 게임 실행 해상도 내 UI 인터페이스 벗어나서 구현하지 마.
> 필요한 버튼 UI 가 있으면 제작 요청을 해."

**규칙**
1. 게임 UI 는 전부 게임 화면(캔버스) **안에** 그린다. 화면 밖 DOM 패널·버튼을 만들지 않는다.
   지금 `web/battle.html` 의 명령 패널·조작 줄은 화면 밖에 있다 → §11 4단계에서 화면 안으로 옮기며 지운다
2. 개발 도구(시드·대진·배속)는 게임 UI 가 아니다. 기본으로 숨기고, 켜면 화면 **안** 오버레이로 뜬다
3. 버튼·틀·아이콘 그림은 **제작 요청**한다 (§9.5). 그림이 오기 전까지 코드로 그린 단색 임시 도형을 쓰고, 임시라는 걸 데이터에 표시한다

**기준 좌표계**: 1920×1080 (16:9). 모든 UI 좌표·크기는 이 단위로 쓴다.

| 화면 | 실제 해상도 | 기준 단위로 | 처리 |
|---|---|---|---|
| PC | 1920×1080 | 1920×1080 | 그대로 |
| iPhone 15 가로 | 2556×1179 (19.5:9) | 높이 1080 에 맞춰 **2341×1080** | 배경만 좌우로 211 씩 더 보인다. UI 는 가운데 1920 안 |
| 16:9 보다 좁은 화면 | — | — | 범위 밖. 위아래 띠를 둔다 |

**iPhone 15 세이프 영역** (가로, 3배율): 좌우 59pt · 아래 21pt = 좌우 177px · 아래 63px
→ 기준 단위로 좌우 **162** · 아래 **58**. 가운데 1920 칸은 좌우 세이프 선(162)보다 안쪽이라 가려지지 않는다.
**아래 60 은 비운다** (홈 인디케이터). UI 가 쓰는 영역은 **x 0~1920, y 0~1020** 이다.

**터치 크기**: 최소 44pt = 기준 단위 **120**. 누르는 것은 짧은 변이 120 이상.

**배치 (기준 단위)**

| 구역 | 범위 | 내용 |
|---|---|---|
| 위 띠 | y 0~120 | 턴 · 포메이션 이름 · 단계 안내 · 메뉴 |
| 무대 | y 120~800 | 캐릭터·칸·적 선언 표지. 칸의 발 위치는 y 620~780 안 (아래 지시판에 안 가리게) |
| 지시판 | y 800~1020 | 아군 3칸(x 24~528) · 카드 3장(548~1262) · 태우기 −/+(1282~1532) · 해결(1552~1896) |
| 비움 | y 1020~1080 | 홈 인디케이터 |

- 대상 고르기와 칸 옮기기는 **무대 위를 누른다** (적·적 선언 표지·바닥 칸). 따로 목록 패널을 두지 않는다
- 결과 예측은 무대 위에 붙인다: 적 선언 표지 끝에 결과(막힘·뚫림·교착·끊김), 아군 체력바에 예상 체력

### 12.4 아군 구성 — 카일 고정 + 장면 동행 + 보호 대상

- **카일은 모든 전투에 고정.** 쓰러지면 패배. 가는 체형·"장시간 완력 싸움이 약함"(원문 §10)이라 체력이 낮다 → **카일이 곧 지켜야 할 에이스**다
- **장면 동행**: 장(章)마다 데이터로 0~2명이 합류한다. 상시 수집·편성은 없다 (원문 §2 "수집형 동료 아님"을 지킨다). 후보는 무기를 드는 사람들 — 잔류 수색대원, 협력한 경비원, 6장 조건 충족 시 레트
- **보호 대상**: 아린·작업자·주민·장치가 칸을 차지한다. 카드가 없고 적이 노린다. 1장 첫 전투는 **카일 + 보호 대상**(아린과 정비소 작업자)만으로 시작한다
- 포메이션·역할 칸·적성 벌칙은 **양쪽 모두** 유지. 적 쪽은 경비대 대열(레트가 "대열이 무너지는 것을 두려워한다")·잔형 무리
- "손해를 보고 지키는 수"는 두 방향이 된다: 동행을 앞으로 당겨 카일을 지키거나, 카일이 유리한 칸을 버리고 보호 대상 앞을 막는다
- 조력자(범고래)·소각원·메인·경찰 카드(§7)는 **자리 표시용**으로만 남긴다. 시안·테스트에서 동행 칸을 채우는 용도. 줄거리에 넣지 않는다

§2·§7·§8 은 이 구성으로 다시 쓴다. 수치는 여전히 §10 B-1~B-7 확정 뒤 시뮬레이터로 정한다.
