## 8. 새 채팅 시작 절차

```bash
git fetch origin && git pull --no-rebase origin claude/trusting-keller-2qeupr
npm ci && npm run typecheck && npm test   # 41파일 553개 기준
npm run web                               # 화면 확인 전
```

1. Slack #ed-01-production OPS-002 스레드를 읽는다. Codex의 `[M3-Q01 · 전달 요청 실행]` 답글에 가지 이름·SHA가 올라왔는지 본다
2. 올라왔으면 해당 가지를 받아 Q01을 시작한다: 매니페스트와 11장 대조 → RGBA·여백 → 피벗 [760,840]·접점 → `battle.html?art=remnantWalker` 실제 크기. 결과는 스레드에 `[M3-Q01 · 수신]` 양식으로 남긴다. 그림 수정은 Codex 담당이고 문제는 BUG-ID로 올린다
3. 안 올라왔으면 사용자에게 알리고 §6 결정 항목을 먼저 묻는다
4. 푸시가 거부되면 `git pull --no-rebase`. 아스트라(Codex)도 같은 가지에 올린다
5. 서브에이전트는 사용자가 시킬 때만. PR·릴리스는 요청할 때만. 이 환경에서 Release 생성은 403이다

- 이미지·소리 커밋 금지 (`assets/**/*.png` 등은 gitignore)
- 수치는 Codex 소유다. 바꾸면 스펙 표에 `[튜닝 날짜·근거]`를 같이 남긴다

- 이번 턴에 실행한 결과 없이 "통과"라고 쓰지 않는다. 못 돌린 것은 "미검증"
