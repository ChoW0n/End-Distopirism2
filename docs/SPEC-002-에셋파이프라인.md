# SPEC-002 · 에셋 파이프라인 (v1.0)

상태: **확정 v1.2** / 작성 2026-09-21 / 근거: 소각원 1차 조립 검수 실측 / v1.1 캐릭터별 설정·조력자(범고래) 반입 / v1.2 이펙트 활용 확장 2026-09-24

> 스프라이트·이펙트·컷신이 렌더러에 들어가기 전에 거치는 단계와 좌표 데이터 규격을 정한다.
> 전투 규칙은 `SPEC-001-전투시스템.md`, 생성 지시 규칙은 프로젝트 문서 `아트_생성_지침.md`가 기준이다.

---

## 1. 왜 필요한가

GPT가 생성한 프레임은 **캐릭터 크기가 프레임마다 다르다.** 소각원 12프레임 실측:

| 기준 | 값 |
|---|---|
| idle 대비 최소 | 10-skill3-cast **0.75배** |
| idle 대비 다음 | 06-skill1-cast **0.80배** |
| 정지 프레임 | 0.90 ~ 1.00배 |

그대로 이어 붙이면 공격할 때마다 캐릭터가 작아진다. **생성 쪽에 픽셀 크기를 강제하는 방식은
이미 실패했으므로**(`스프라이트_규격_규칙.md`), 받은 그림을 우리가 보정한다.

---

## 2. 범위

반입되는 에셋 3종의 좌표 데이터를 하나의 매니페스트로 만든다.

| 에셋 | 처리 |
|---|---|
| 전투 프레임 | 배율 보정 + 접지 정렬 + 기준점 추출 |
| 이펙트 | 원본 팩의 정렬본·피벗을 그대로 인용 (재가공 안 함) |
| 궁극기 컷신 | v3 확정 좌표를 그대로 인용 (추정 금지) |

구현: `tools/assets/normalize_sprites.py`. 오프라인 도구이고 게임 빌드에 포함하지 않는다.

## 3. 전투 프레임 정규화

### 3.1 좌표계

| 항목 | 값 |
|---|---|
| 정규화 캔버스 | 2400 × 1500 |
| 접지선 y | 1340 |
| 기준 x | 1200 |
| 원점 | 좌상단, +X 오른쪽, +Y 아래 |

모든 프레임이 이 좌표계를 공유한다. 렌더러는 프레임 이미지 크기로 배치하지 않고 이 좌표로 배치한다.

### 3.2 배율 추정 — bbox 높이 방식을 쓰지 않는다

`스프라이트_규격_규칙.md`의 "idle bbox 높이 기준" 방식은 **웅크린 자세에서 뒤집힌다.**
머리-발 거리로 재면 편차가 74.6%로 나오는데, 이 중 상당 부분이 실제 배율 차이가 아니라 자세다.

확정 방식: **idle 프레임의 머리(후드+은백발) 주변을 템플릿으로 잘라, 다른 프레임에서
배율 0.65~1.45 / 회전 ±20°로 매칭해 최고 점수의 배율을 쓴다.** 머리는 자세와 무관하게
크기가 유지되므로 배율만 분리해서 잡힌다. 실측 일치율 0.90~1.00.

보정값 = `1 / 추정배율`. 소각원 기준 ×1.00 ~ ×1.33.

### 3.3 앵커

- **세로**: 알파 최하단(발바닥)을 접지선 y에 맞춘다.
- **가로**: 발바닥 띠(하단 40px) 중앙값과 머리 중심의 **중간점**을 몸통 축으로 본다.
  발만 쓰면 돌진·베기 자세에서 캐릭터가 캔버스 밖으로 밀려난다.

## 4. 매니페스트 스키마

`assets/<캐릭터>/sprite-manifest.json`

```jsonc
{
  "version": 1,
  "character": "incinerator",
  "canvas": [2400, 1500],
  "ground": [1200, 1340],
  "frames": [{
    "id": "06-skill1-cast",
    "file": "frames/06-skill1-cast.png",
    "scale": 1.25,          // 적용한 보정 배율
    "scaleMatch": 0.901,    // 머리 템플릿 일치율. 0.85 미만이면 불합격
    "anchor": [1200, 1340], // 접지 기준점
    "headCenter": [x, y],
    "axeHead": [x, y],
    "bladeTip": [x, y],
    "tipSource": "자동 검출" | "수동 확정" | "미검출",
    "bbox": [x0, y0, x1, y1]
  }],
  "effectsPack": "incinerator-effects-remake-v4",   // 어느 이펙트 팩인지
  "effects": [{ "id", "name", "anchor", "size", "pivot", "scale", "blend", "loop", "frames": [{ "file", "ms" }] }],
  "cutscene": { "size": [1774, 887], "layers": [{ "id", "file", "pos", "pivot", "z", "parent", "visibleDefault", "motionDeg" }] }
}
```

## 5. 기준점 규칙

### 5.1 이펙트가 붙는 자리

| 앵커 | 붙는 좌표 | 해당 이펙트 |
|---|---|---|
| `bladeTip` | 프레임의 날끝 | 베기 궤적 4종 (대각·수평·올려·내려) |
| `hitPoint` | **맞은 대상의 좌표** | 명중 섬광 |
| `groundPoint` | 날끝 x + 접지선 y | 지면 충격, 수직 화염 |
| `emissionPoint` | 발생 지점(월드 고정) | 연기·잔불·분출 |

모든 이펙트를 무기 중심에 붙이지 않는다. 잔류 이펙트(연기·잔불)는 생성 시점의 월드 좌표를
복사한 뒤 무기 추적을 끊는다.

**UI 가 붙는 자리는 앵커를 새로 만들지 않는다 [2026-09-21 확정 · SPEC-004 U-2].**
체력바·정신력바·합 배지는 이미 있는 값 세 개로 푼다.

| UI 요소 | 계산 | 쓰는 값 |
|---|---|---|
| 체력바 · 정신력바 | 머리 위 `H × topMargin` | `bbox` 상단 y, `anchor` |
| 합 승리/패배/교착 배지 | 바보다 한 단 위 | 위와 동일 |
| 바 기본 폭 | `H × bar.width` | 캐릭터 키 `H` |

`H`(캐릭터 키) = **정지 프레임(`00-idle`)의** `anchor.y − bbox` 상단 y. 소각원 기준 약 900px.
**프레임마다 다시 재지 않는다.** 공격 프레임은 키가 0.75~1.00 배로 흔들려서(§3.1) 매 프레임
재면 바가 위아래로 떠다닌다. 매니페스트에 새 필드를 추가하지 않는다.

### 5.2 날끝 검출과 수동 확정

붉은 도끼 머리를 먼저 찾고, 거기 붙은 밝은 회색 날에서 가장 먼 점을 날끝으로 잡는다.
**도끼가 화면 밖으로 나가거나 어두운 배경에 묻히면 코트의 붉은 무늬를 도끼로 오인한다.**

현재 수동 확정 목록 (도구의 `BLADE_OVERRIDE`):

| 프레임 | 확정 좌표 | 자동 검출이 틀린 이유 |
|---|---|---|
| 05-skill1-ready | [810, 16] | 도끼가 캔버스 위로 빠짐 |
| 10-skill3-cast | [1616, 242] | 머리 위로 든 날을 코트 무늬로 오인 |

**새 프레임이 들어오면 날끝 격자 검사를 반드시 한 번 돌린다.** 공격 프레임에 날끝이 없으면
파이프라인이 실패로 끝난다(§8 자가검사).

### 5.3 명중점은 전투 도메인이 준다

명중 좌표는 에셋 데이터에 없다. **1:1 매칭된 대상의 화면 좌표**를 전투 이벤트에서 받아 쓴다.
검수용 임시값으로 `날끝 + (40, -34)`를 쓰고 있으나 이건 연출 확인용이고 최종값이 아니다.

어느 전용기가 어느 베기 궤적을 쓰는지는 **프레임의 실제 포즈가 정한다.** 임의 배정이 아니다.

#### 5.4.1 v1.2 개정 — 12종을 다 쓴다 **[2026-09-24]**

v1.0 은 "자리를 채우려고 아무 데나 붙이지 않는다"며 3종을 비워 두고 5종은 궁극기·격파에만 썼다.
그림은 좋은데 화면에서 거의 안 보였다(사용자 지적). 원칙은 그대로 — **포즈와 사건이 맞는 곳에만** 붙인다.
대신 붙일 사건을 늘린다.

소각원 추가분:

| 자리 | 이펙트 | 근거 |
|---|---|---|
| S1 06-skill1-cast | + `embers` | 대각으로 긋고 불티가 흩날린다 |
| S2 08-skill2-peak | + `fire-horizontal` | 옆으로 쓸어낸 날끝에서 앞으로 분출. 팩: "왼쪽 근원에서 오른쪽으로 분출" |
| S3 10-skill3-cast | + `fire-rising` | 올려베는 날끝에서 위로 분출. 팩: "왼쪽 아래 근원에서 오른쪽 위" |
| S3 11-skill3-finish | + `ash-mixed` | 내려찍은 자리에 재가 내려앉는다 |
| 준비 (`ready`) | `embers` | 전용기를 잡을 때 발치에서 불티가 오른다 |
| 대시 (`dash`) | `smoke` | 박차고 나간 자리에 탄화 연기 |

조력자(범고래)는 `assets/helper/effect-bindings.json` 에 둔다 (§9.5.1).

`ultimateFrame` (선택): 궁극기 이펙트를 붙일 전용기 3의 장. 없으면 마지막 장이다.
마무리 자세에서 무기가 등 뒤로 가는 캐릭터는 앞을 치는 장을 고른다. 고른 장이 **때리는 장**이 되어
그 장의 지면·분출은 피해가 들어갈 때 그 장의 날끝에서 터지고, 마지막 장은 이펙트 없이 자세만 보인다.
조력자는 `10-skill3-cast`(올려 베기, 창끝이 앞 위). 마무리 장(창이 등 뒤)에 붙이면 지면 충격·화염이 등 뒤에서 터진다 (2026-09-24 실측)

#### 5.4.2 사건 이펙트 **[v1.2]**

전용기 장 말고도 이펙트를 붙이는 사건. 바인딩 파일에 키로 둔다. 전부 **명중이 아니다.**

| 키 | 언제 | 어디 |
|---|---|---|
| `ready` | 합·일방 공격 시작, 준비 자세를 잡을 때 | 제자리 |
| `dash` | 달려 나갈 때 | 출발점. 보는 쪽으로 뒤집는다 |
| `clash` | 합 라운드에서 이겼을 때. 교착이면 공격자 것 | 맞부딪히는 접점. **있으면 렌더러의 도형 불꽃 대신 쓴다** |
| `recoil` | 합 라운드에서 졌을 때 | 몸 가운데 |

- 준비·대시 높이: 지면 이펙트(`groundPoint`, 충전 고리 등)는 **발**, 나머지(잔상·연기·불티)는 **몸 가운데**.
  잔상을 발에 놓으면 바닥의 붉은 웅덩이처럼 보였다 (2026-09-24 실측)
- 사건 이펙트에는 **명중 섬광(`hitPoint`)을 쓰지 않는다.** §6-1 "맞았을 때만"을 지키기 위해서다
- 합 접점 좌표는 UI 감독이 정한다(SPEC-005 §4.1). 그래서 `clash` 는 렌더러가 합 결과 명령을 받을 때 바인딩을 읽어 띄운다
- 중간 장(마지막이 아닌 휘두름)에 붙은 지면·분출 이펙트는 **그 장의 날끝**에서 그 장이 뜰 때 터진다.
  마지막 장의 지면·분출은 지금처럼 피해가 들어갈 때 터진다

### 5.5 이펙트 배율은 종류마다 다르다 **[2026-09-22 확정 · v4]**

이펙트 팩이 `incinerator-effects-remake-v4` 로 교체되면서 **12종 전부 크기와 피벗이 바뀌었다.**
v2 좌표를 재사용하면 전부 어긋난다.

배율은 `sprite-manifest.json` 의 이펙트별 `scale` 이고, **캐릭터 키 `H` 대비 긴 변의 비율**이다.
`실제 픽셀 = H × scale / max(size)`.

| 이펙트 | scale | 근거 |
|---|---|---|
| slash-horizontal | 1.2 | 낮게 쓸어내는 궤적이 발밑까지 닿아야 한다 |
| slash-diagonal | 1.1 | 더 키우면 머리·팔을 덮는다 |
| slash-rising | 1.1 | 더 키우면 몸통을 가로지른다 |
| slash-downward | 1.2 | 내려찍기 궤적은 길게 |
| ground-impact | 0.6 | 지면에 퍼지는 폭 |
| impact | 0.45 | 접점의 짧은 섬광. 크면 베기를 먹는다 |
| fire-upright | 0.95 | 궁극기 소각. 캐릭터 키에 가깝게 |
| fire-horizontal / fire-rising | 0.9 | 미사용(§5.4). 값만 둔다 |
| smoke / ash-mixed | 0.7 | 격파 후 잔류 |
| embers | 0.8 | 위와 동일 |

**일괄 배율을 쓰지 않는다.** 하나로 맞추면 베기가 명중 섬광만큼 작아지거나 섬광이 화면을 덮는다.
로더가 `scale` 누락을 던지고, `tests/render-stage.test.ts` 가 값이 전부 같지 않은지 확인한다.

위 값은 소각원 12프레임에 실제로 합성해 눈으로 맞춘 것이다(밝은 배경·어두운 배경 양쪽).
**검수 안 된 것**: 좌우 반전, 히트스톱, 접촉 타이밍, 플레이 해상도.

프레임 3장은 **발생 → 최대 → 소멸** 키프레임이다. 촘촘한 애니메이션이 아니다.
마지막 키프레임에도 그림이 남으므로 **재생이 끝나면 노드를 반드시 제거한다.**

---

**현재 쓰이지 않는 이펙트**: `fire-horizontal`, `fire-rising`, `ash-mixed`.
화염을 뿜는 기술이 생기기 전까지는 호출하지 않는다. **자리를 채우려고 아무 데나 붙이지 않는다.**

준비 프레임(05/07/09)에는 이펙트를 걸지 않는다. 아직 때린 게 아니다.

## 6. 이펙트 재생 규칙

1. **피해가 실제로 들어간 교전에만 재생한다.** 판정 기준은 `damageApplied > 0`이다.
   교착·합 패배·피해 0인 교전에는 섬광·화염·지면 충격을 띄우지 않는다.
   > 2026-09-21 정정 — 이 조항은 원래 "회피(SPEC-001 §4.2)면 띄우지 않는다"였다. 그 §4.2는
   > **폐기된 2026-09-16판 v2.0의 회피 판정**이고 확정본에는 `evaded` 이벤트가 없다.
   > 의도("맞았을 때만")는 그대로고 판정 근거만 피해량으로 바꿨다. 교착까지 같이 막히므로 더 맞다.
2. 합성은 일반 알파(source-over). 검은 외곽이 있으므로 전체를 더하기 합성으로 바꾸지 않는다.
3. 3프레임은 발생·최대·소멸 키프레임이다. 기본은 1회 재생 후 종료.
4. 프레임 시간은 제안값이다. 히트스톱과 접촉 시각에 맞춰 조정한다.
5. 좌우 반전 시 비트맵과 피벗을 함께 변환한다. **캐릭터 반전과 이펙트 반전은 따로 판단한다**
   (캐릭터를 단순 반전하면 손잡이와 손의 좌우가 바뀐다).
6. **짧은 이펙트는 늘려서 튼다 [v1.2].** v4 베기는 3장 합이 215ms 라 최대 장면이 70ms 만 뜬다.
   원작 참고 GIF 실측은 참격 980ms. 전체 길이가 `ui-data.json` `effects.minMs` 보다 짧으면
   장마다 같은 비율로 늘린다(발생·최대·소멸 비율 유지). 4번 "제안값, 조정한다"에 따른 것이다
7. **발광 겹 [v1.2].** 바인딩의 `glow` 목록에 있는 이펙트는 원본(일반 합성) 위에 흐린 복사본을
   더하기 합성으로 한 번 더 얹는다. 원본을 더하기로 바꾸는 게 아니다(2번 유지). 먹색 연기·재는 목록에 넣지 않는다.
   브라우저가 캔버스 흐림을 못 하면 겹을 생략한다
8. 휘두르는 사람을 따라가는 것은 **날끝(`bladeTip`) 궤적뿐**이다. 분출·연기·불티는 생성 순간 자리에 남는다

## 7. 궁극기 컷신 (v3)

- 배치는 **v3 확정 좌표 그대로**. 특징점·밝기 매칭을 쓰지 않는다. 검증: 13개 레이어를
  좌표대로 놓으면 제공된 조립본과 **픽셀 차이 0**.
- 부모 계층: `body-core`가 루트, 나머지 본체·보강은 그 자식, 눈 4장·입 2장은 `head-hood` 자식.
  얼굴 파츠를 각자 중심으로 회전시키면 얼굴에서 미끄러진다.
- 눈·입은 **상태별로 하나만 켠다** (open/closed 동시 표시 금지).
- 회전 한도는 매니페스트의 `motionDeg`(머리·팔 0.25°, 옷자락 0.55~0.8°)를 넘기지 않는다.
  접합부는 뒤에 깔린 `body-underpaint` 20px 겹침으로만 막혀 있다.
- **컷신 시작·종료가 피해 판정을 새로 만들지 않는다.** 합/명중 확정 → 연출 이벤트 → 기존 피해
  적용 순서를 지킨다.

### 7.1 메시 컷신 (범고래 컷신 1 v1) **[2026-09-24]**

범고래 컷신은 파츠 분리가 아니라 **한 장짜리 캐릭터를 격자 메시로 휘는 방식**이다
(팩 README: "Canvas 메시 프로토타입. Cubism 파일 아님"). 매니페스트 `cutscene` 에 `kind` 로 가른다.

| `kind` | 내용 |
|---|---|
| `layers` (기본) | §7 의 13레이어 회전. 소각원 |
| `mesh` | 전경 한 장 + 배경 + 눈·입 원화 조각. 조력자 |

`mesh` 의 데이터:

| 키 | 뜻 | 출처 |
|---|---|---|
| `size` | 캔버스 1672×941 | rig.json `canvas` |
| `foreground` · `background` | 투명 캐릭터 · 캐릭터 지운 배경 | 팩 assets |
| `eye` · `mouth` | 눈 감은 원화·입 다문 원화와 그 다각형(`eyePatch`·`mouthPatch`) | rig.json |
| `grid` · `extraRows` | 격자 칸 수(32×19)와 추가 경계선(y=710) | 팩 renderer.js |
| `rigid` | 이 y 구간부터 변형이 0 으로 줄어든다 [650, 710]. 손·창은 같이 움직이기만 한다 | rig.json `rigidRegion`·renderer.js |
| `deformers` | 머리·머리카락 뒤·앞·숨 변형. 가중치 모양·중심·반경·세기·위상 | 팩 renderer.js 의 수치를 **그대로** 옮김 |
| `sway` · `zoom` | 몸 전체가 같이 흔들리는 양, 가장자리 가림용 확대 1.025 | 팩 renderer.js |

- 변형 수치를 코드에 박지 않는다. 팩 renderer.js 의 값을 매니페스트로 옮겨 읽는다
- 계산(점 → 휜 점)은 `render/` 의 순수 함수, 그리기(삼각형 잘라 붙이기)는 렌더러다
- 눈·입 원화 조각은 **같은 텍스처에 먼저 덮은 뒤** 메시로 휜다. 얼굴 위치를 따로 따라가지 않는다
- 팩의 4초 반복 타이밍 대신 SPEC-005 §2.4 의 컷인 시간표(`blinkAt`·`mouthAt`)를 쓴다.
  범고래 원화는 입이 열려 있으므로 `mouthAt` 밖에서 입 다문 조각을 덮는다

## 9.5 캐릭터별 설정 **[2026-09-24]**

소각원 기준으로 짠 정규화가 다른 캐릭터에서 그대로 안 맞는다. 캐릭터마다 다른 것은
`tools/assets/characters/<캐릭터>.json` 에 두고 `--config` 로 넘긴다. 설정이 없으면 소각원 기본값이다.

| 키 | 뜻 | 조력자 값 | 왜 |
|---|---|---|---|
| `weapon` | `axe` / `spear`. 날끝 검출 방식 | `spear` | 도끼 검출은 붉은 도끼 머리+회색 날을 찾는다. 창은 붉은 자루 축을 따라 양 끝을 찾는다 |
| `tipEnd` | 창의 두 끝 중 창날 쪽 (0 = x 가 작은 끝) | 13장 수동 확정 | 창날·물미 판정이 그림만으로 안정적으로 갈리지 않는다(실측). 소각원 `BLADE_OVERRIDE` 와 같은 수동 확정이다 |
| `scaleBy` | `headTemplate` / `hood`. 배율 추정 방식 | `hood` | 흰 재킷이 은발보다 커서 머리카락 템플릿이 재킷을 잡는다. 검은 후드 면적 비로 잡는다. 일치도 기준은 0.6 (후드 가로세로 비가 자세마다 바뀐다) |
| `baseScale` | 전체 배율 | 0.81 | 원본이 크다(서 있는 키 1604px). 소각원(1340)과 비슷하게 맞춘다 |
| `canvas` · `ground` | 캔버스 크기·접지점 | 3400×1800, (1700, 1640) | 찌르기는 창이 앞으로, 07 은 머리 위로 뻗어 2400×1500 에서 잘린다. 매니페스트 `canvas`·`ground` 는 캐릭터마다 다르고 렌더러는 그 값을 읽는다 |
| `aliases` | 파일 이름 끝 바꾸기 | `forward` → `advance` | 렌더러가 이름 끝으로 프레임을 찾는다 (SPEC-005 §2.1) |
| `effects` | 프레임 애니메이션 이펙트 팩의 기준점·배율·피벗 | 12종 | 범고래 이펙트 v6 에는 기준점·배율이 없다. 피벗은 팩 제안값을 쓰고, `pivot` 이 있으면 그 값이 이긴다. 가로 쓸기(06)는 몸을 감는 타원이라 뒤끝 [40, 337] 을 창끝에 붙인다 — 쓸기 마무리는 창끝이 등 뒤라 가운데 피벗이면 등 뒤에서 터졌다 |

### 9.5.1 프레임 애니메이션 이펙트 팩

범고래 v6 는 12종 × 6장, 576×576 캔버스, `effects.json` 에 장별 시간·피벗이 있다.
`--frame-effects <팩>` 으로 읽는다. v4(3장·정렬본) 형식과 매니페스트 결과는 같다.

- **명중점(`hitPoint`) 이펙트는 맞을 때마다 전부 터진다.** 그래서 조력자는 `02_impact_flash` 하나만 명중점이다
- 지면·분출 이펙트는 피해 순간에 나간다. 준비 자세에 붙이면 준비 때가 아니라 맞을 때 터진다
- 붙일 사건이 없는 것(합 불꽃·충전 고리·방어 껍질·이동 잔상)은 `effect-bindings.json` 의 `_unused` 에 둔다
