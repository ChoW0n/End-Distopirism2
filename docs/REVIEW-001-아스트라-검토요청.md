## 2. 켜는 법

```
unzip end-distopirism2-review-<커밋>.zip
cd end-distopirism2-review-<커밋>
python3 -m http.server 8000      # 또는 npx serve -l 8000
# 브라우저로 http://localhost:8000/ 을 연다
```

- 화면이 데이터와 그림을 `fetch` 로 읽어서 **`file://` 로 열면 안 된다.** 반드시 정적 서버로 연다
- WebGL 이 되는 데스크톱 Chrome·Edge 기준으로 맞췄다. 1600×900 이상 가로 화면 권장
- 헤드리스 Chromium 은 `--use-gl=swiftshader --enable-unsafe-swiftshader` 로 켠다 (작업 쪽 검수도 이 설정)
- 첫 화면(`index.html`)에 화면 목록과 이 문서가 있다

## 5. 봐 줬으면 하는 것

번호를 붙여 두었다. 결과에 번호를 그대로 쓴다.

### R1. 전투 한 판 — 직접 조작

1. `web/battle.html` → 도움말 읽고 시작 → 아군(카일) 선택 → 무대의 적 클릭 → 카드 선택 → 교전 시작
2. 판이 끝날 때까지 반복. 위 띠의 **배속**·**자동**도 눌러 본다

- R1.1 처음 하는 사람이 도움말만 보고 한 턴을 넘길 수 있는가
- R1.2 합에서 누가 이겼는지, 왜 이겼는지(앞/뒷면·위력) 읽히는가 (SPEC-005 §11)
- R1.3 발밑 반원(붉은 체력·푸른 정신력)·흔적 세 칸·결행 카드 등장이 읽히는가 (SPEC-004 §14)
- R1.4 카메라가 인물을 가리거나 화면 밖으로 놓치는 순간이 있는가 (SPEC-005 §9 · SPEC-007 §9.9, 원본 카메라 버그 재발 여부)
- R1.5 막히거나 멈추는 상태(입력이 안 먹음, 판이 안 끝남)가 있는가

### R2. 연출 — 시연 모드

메뉴 → 조작 → 시연 (제작용). 한 바퀴(S1→S2→S3→결행) 이상 본다.

- R2.1 스킬마다 맞은 감각(밀림·슬로우·스파크·흔들림)이 나는가 (SPEC-005 §12)
- R2.2 결행 컷신 → 밤바다 → 여러 번 베기 → 복귀가 끊김 없이 이어지는가 (SPEC-005 §10.2)
- R2.3 스프라이트 장이 튀거나(크기·발 위치가 장마다 다름), 잘리거나, 겹쳐 깨지는 곳
- R2.4 연출 실험 모드에서 흔들림·섬광 줄이기가 실제로 줄이는가

### R3. 공간형 VFX — 이번 작업의 핵심

`web/vfx-space.html`. 위 **스킬** 선택에서 S1·S2·S3·결행을 하나씩 고른다 (게임 카드 이름은 S1 물금 · S2 이면 · S3 잔향). 기본은 왼쪽 평면 재생, 오른쪽 공간형, 같은 카메라.

- R3.1 **게임 카메라(궤도 0°)에서 두 칸이 거의 같아 보이는가.** 공간형은 원화 자리에 정확히 겹치게 계산한다 (SPEC-005 §15.4). 다르게 보이면 그 스킬·시각(ms)을 적어 달라
- R3.2 **궤도 슬라이더를 ±60°, 높이 슬라이더를 올려 돌렸을 때** 효과가 세로 판처럼 납작하지 않고 휘두른 궤적대로 공간에 놓였다고 느껴지는가
- R3.3 몸 가림: 효과가 몸 뒤로 돌아가는 부분이 몸에 가려지는가, 앞 부분은 몸 위로 오는가 (가림 판 보기 체크로 확인 가능)
- R3.4 바닥: 낮은 물보라·밤물 웅덩이가 바닥 밑으로 꺼지지 않고 바닥에 눕는가
- R3.5 S2 찌르기는 돌렸을 때 아래 물보라가 카메라 쪽으로 꽤 나온다. 과한지 의견
- R3.6 결행은 실험 장면(카일이 적 뒤에 선 마지막 자세)만 보여 준다. 컷신·피해·흔들림은 없다. 획 4개(0·100·200·300ms)와 물보라(350ms) 박자가 읽히는가
- R3.7 이 방식(효과 분리 장 + 투영 곡면)을 게임 본편에 넣을 만한가, 넣는다면 무엇을 먼저 고쳐야 하는가

### R4. 물금 실시간 VFX

`web/vfx-lab.html`. 원본 비교 나란히/겹쳐 보기.

- R4.1 셰이더 띠가 원본 15장의 색·붓결·소멸 순서(꼬리부터)를 따라가는가
- R4.2 원본 질감 / 절차 두 방식 중 어느 쪽이 나은가

### R5. 아트 톤

- R5.1 캐릭터는 검은 외곽선 + 평면 2~3단 셀화풍, 배경은 무채색·브라운의 거친 마모 질감 (STORY-001 §18). 지금 화면에서 둘이 섞이거나 어긋나는 곳
- R5.2 UI v4 금빛 윤곽이 배경·캐릭터와 싸우는 곳

### R6. 구조 (코드 리뷰를 할 경우)

- R6.1 `src/domain/` 에 DOM·three.js·브라우저 API 의존이 없는가 (유니티 재전환 조건)
- R6.2 게임 수치가 코드에 박힌 곳 (JSON 이어야 한다)
- R6.3 공간형 계산(`src/render/space-fx.ts`)이 렌더러 비의존 순수 함수로 남아 있어 유니티로 옮길 수 있는가

## 6. 결과를 보내는 형식

항목마다 아래 칸을 채워 달라. 확인하지 못한 것은 추정으로 쓰지 말고 **미검증**으로 남긴다 (`docs/참고/gpt-astra-이미지제작-능력.md` §2 의 구분을 그대로 쓴다).

| 칸 | 내용 |
|---|---|
| 번호 | R1.1 같은 번호. 번호 밖이면 `R+` |
| 판정 | 통과 / 문제 / 의견 / 미검증 |
| 근거 | 직접 확인(실행해서 봄) / 코드 확인 / 추정 |
| 재현 | 화면·모드·스킬·시각(ms)·카메라 궤도. 공간형은 화면 아래 읽기 줄을 그대로 붙이면 된다 |
| 기대·실제 | 무엇을 기대했고 무엇이 나왔나 |
| 심각도 | 막힘 / 중요 / 사소 / 제안 |
| 스크린샷 | 있으면 파일 이름 |

묶음의 `screenshots/` 는 작업 쪽이 같은 화면을 찍어 둔 것이다. 실행이 안 되는 환경이면 이것만으로 볼 수 있는 항목(R3.1·R3.2·R5)을 보고 나머지는 미검증으로 둔다.

### 자동으로 돌려 볼 때

두 실험 화면은 창에 손잡이를 단다. 헤드리스로 같은 장면을 찍을 때 쓴다.

```js
//공간형: 스킬 고르기 → 시각 고정 → 카메라 돌리기 → 상태 읽기
await window.__vfxSpace.skill('s3');      // 's1' | 's2' | 's3' | 'ult'
window.__vfxSpace.seek(700);              // 스킬 시작부터 ms
window.__vfxSpace.orbit(60, 20);          // 좌우 궤도°, 높이°
window.__vfxSpace.shot('close');          // 'combat' | 'close' | 'home'
window.__vfxSpace.view('side');           // 'side' | 'flat' | 'space'
window.__vfxSpace.state();                // { skill, age, pre, loopMs, calls, programs }

//물금 실시간: 시각 고정·방식·비교
window.__vfxLab.seek(300); window.__vfxLab.mode('texture'); window.__vfxLab.compare('side');
window.__vfxLab.state();
```

전투 화면은 손잡이가 없다. 메뉴의 **조작** 선택(`#mode`)과 개발 → **시드**(`#seed`) 뒤 **다시 시작**으로 같은 판을 다시 낸다.

## 7. 묶음 만들기 (리포 쪽)

```
npm ci
node scripts/review_bundle.mjs            # 그림이 들어 있는 작업 환경에서
```

1. `node web/build.mjs` 로 화면을 빌드하고 `npm run typecheck`·`npm test` 결과를 `BUILD.json` 에 적는다
2. 정적 서버를 띄우고 Playwright 로 세 화면을 열어 **실제로 요청한 파일만** 모은다. 404 가 하나라도 나면 멈춘다
3. 같은 길에 `screenshots/` 를 찍는다
4. `review-bundle/end-distopirism2-review-<커밋>/` 와 같은 이름의 zip 을 만든다. 둘 다 커밋하지 않는다

Release 에 올리는 것은 사용자 승인 뒤에 한다. 묶음에는 그림 원본이 들어가므로 공개 리포의 Release 에 올리면 누구나 받을 수 있다.
